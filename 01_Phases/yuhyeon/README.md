## 🛤 트랙 (팀장 결정)

**Dumb Client 전반 작업.**

> "Dumb Client" = 헌법 #1 (Server Authority)의 직접 결과물.
> 클라는 단순 렌더러 + 입력 전달자. 데미지·HP·인벤토리 등 authoritative
> 상태는 절대 직접 변경하지 않고, 서버가 알려준 것만 표시.

구체적 작업 방식:

1. **팀장이 박은 일지를 먼저 읽음** (`00_Document/learning-journal/youngho/`,
   `01_Phases/youngho/M*/`의 `-DONE.md`). 서버가 이미 무엇을 하고 있는지 파악.
2. **본인이 만들 수 있는 클라 요소를 판단**. 예: 서버가 `S_EnterMap`을
   보내면 클라가 어떻게 표시해야 하는가? 서버가 `S_Snapshot`을 보내면
   캐릭터를 어떻게 그릴까?
3. **그걸 Phase로 분해**해서 한 단계씩 만들기.

## 💡 권장 시작 흐름 (팀장 권장)

> 강제 아님. 본인이 판단 시 변경 가능. 단 변경 시 팀장에게 알려주세요.

1. **UI 세팅** — 메인 메뉴, HUD 골격, 입력 매핑.
2. **캐릭터 스프라이트 세팅** — 2D 사이드스크롤 캐릭터 idle/walk/jump
   스프라이트 + 애니메이션 컨트롤러 골격.
3. **컨텐츠 작업** — 위 2개 끝난 후 (서버가 보내는 데이터를 표시하는
   실제 컨텐츠. 예: 다른 플레이어 표시, 입장/퇴장 알림 UI 등).

이 순서는 *유연한 토대 먼저 → 그 위에 얹기* 패턴. UI/스프라이트가
들쭉날쭉이면 컨텐츠 만들 때마다 재공사 발생.

## 🤖 정유현의 Claude에게 (팀장 메시지)

> 이 메시지는 정유현의 Claude Code 세션에 직접 향합니다.

정유현님은 지금 개발 전반 지식이 *많이 초보*입니다. 당신(Claude)의
**어느 정도 리딩이 필요**합니다. 단:

1. **프로젝트에 있는 정보를 최대한 활용**하세요. `CLAUDE.md`(헌법),
   `CONTEXT.md`(현재 상태), `00_Document/ADR/`, `00_Document/policies/`,
   팀장이 박아둔 일지(`learning-journal/youngho/`) 등 — 추측 X.
2. **무엇을 먼저 진행할지 정유현님과 의논하고 진행**하세요. 위 권장 흐름은
   *팀장 의견*이지 강제 아닙니다. 정유현님이 다른 우선순위를 원하면 그쪽으로.
3. **학부생 멘토링 톤** (헌법 "사용자 컨텍스트" 섹션). 전문 용어 첫 사용
   시 풀어쓰기. trade-off 항상 설명. "정답" 단정 X.
4. **Server Authority(헌법 #1) 절대 어기지 않기**. 클라에서 HP/데미지/
   인벤토리 직접 변경 코드 절대 짜지 말 것. 정유현님이 "이거 클라에서
   계산하면 안 되나?"라고 물으면 **헌법 #1 풀어 설명하고 서버로 위임**.

### 첫 호출 권장 흐름

