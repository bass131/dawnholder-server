판단 — B 추천

이유:

  • Phase 05 의도엔 A·B·C 모두 통과. 차이는 "이후"에서 갈림.
  • B가 미래 비용을 가장 적게 만듦: Phase 08 데모/M3 다인 진입 시 채팅·인벤토리 송신에도 latency 적용이 자연스러움. A로 가면 그때 옮겨야 함.
  • C는 한 단계 과함: 04_ClientNet은 socket 인프라 레이어라 "게임 시뮬레이션 옵션"이 의미적으로 어색. 그리고 Unity 비의존 어셈블리라 #if UNITY_EDITOR가 안 먹음 → 별도 플래그 도입.
  • A의 "단순함" 매력은 잠깐: 코드 양은 B와 비슷한데(~15줄) 격리가 좁아 재사용성을 일찍 잃음. Rule of three 한 번도 안 거쳐서 분리 정당성이 약함.

구현 메모 (B):

  • UnityClientSession에 SimulatedLatencyMs 정적 필드 (기본 0).
  • Send() 호출 시 #if UNITY_EDITOR로 분기 — 0이면 직통, >0이면 큐에 timestamp 박고 코루틴이 후처리.
  • 코루틴 호스트는 MainThreadDispatcher GameObject가 적합 (이미 있는 main-thread queue 인프라).
  • Inspector에서 토글 가능하면 더 좋음 (옵션, 사용자가 원하면 추가).
