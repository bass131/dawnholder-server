> ★ **M1 Foundation 정비 마지막 단계**. 자체 PDL 인프라가 양쪽 wire-up 정합 + 임시 BitConverter 코드 0.

## TL;DR
Phase 05의 임시 BitConverter `PingPacket`/`PongPacket`을 자체 PDL이 자동 생성한 `C_Ping`/`S_Pong`으로 교체했다. 코드 생성기 출력은 *책임 단위*로 분리했다 — 패킷 데이터 정의는 `98_Shared/Protocol/Generated/`로 통합, manager/handler는 양쪽 분리. 사용자 통찰("Network 코어는 같은 걸 쓰고 핸들러만 분리")로 ADR-012가 "전부 분리"에서 *책임마다 따로* 결정으로 진화했고, M1 Foundation의 네트워크 기반은 임시 코드 없이 정리됐다. 다음 단계는 Phase 08(자동 dispatch) 또는 M2 First Connection 진입.

## 5단계 보고

### 🎯 무엇을 만들었나
Phase 05의 임시 BitConverter `PingPacket`/`PongPacket`을 자체 PDL이 자동 생성한 `C_Ping`/`S_Pong`로 교체. PacketGenerator가 *책임 단위*로 출력 분리 (`98_Shared/Protocol/Generated/`로 패킷 정의, `--no-manager` 옵션으로 manager 출력 skip). 양쪽 dispatch 정합 후 Unity Play → Phase 05와 동일 RTT 로그 재현 입증. **책임 단위 분리/통합** 결정을 ADR-012 + Shared CLAUDE.md + SendBuffer 양쪽 주석에 박제.

### 🤔 왜 필요한가
Phase 05의 임시 BitConverter 코드는 *교체 가정*으로 박힌 것. ADR-002 v2가 약속한 *자체 PDL 단일 소스*가 Phase 06에서 깨어났고, 본 Phase가 *그 인프라를 양쪽에 wire-up*. 본 Phase 후 새 패킷 추가는 *PDL.xml 한 줄 + 명령*으로 양쪽 자동 동기.

부수 가치: **사용자 통찰("Network 코어는 같은 걸 쓰고 핸들러만 분리")로 책임 단위 분리/통합 표 정제**. ADR-012가 "전부 분리"라는 단순 결정이 아니라 *책임마다 따로* 결정의 정합으로 진화.

### 🛠️ 어떻게 만들었나
- **PacketFormat.cs 템플릿 수정**: `Write()`가 `SendBufferHelper.Open/Close` 의존 제거 → `byte[]` 직접 할당 + `BinaryPrimitives.*LittleEndian` 명시. `using ServerCore` 제거 + `namespace Shared.Protocol;` 박음. `#if NET_LEGACY` 데드 분기 정리.
- **Program.cs 수정**: 인자 파싱(`--no-manager`/`--no-wait`). 출력 폴더 분리(`98_Shared/Protocol/Generated/`로 패킷, manager는 양쪽 분리 폴더). PDL 디렉토리 기준 상대 경로 계산.
- **ToMemberType 정정**: `ToInt64` → `Int64` (BinaryPrimitives 메서드명 형식). bool은 BinaryPrimitives에 LittleEndian 변종 없음 — 미래 정정 필요(주석으로 박음).
- **Phase 05 임시 코드 삭제**: PingPacket/PongPacket/PacketId.cs (3파일). 생성된 GenPackets.cs로 대체.
- **양쪽 dispatch 정합**: GameSession + UnityClientSession + NetworkBootstrap 3파일. `PacketId` → `PacketID`, `Ping`→`C_Ping`, `Pong`→`S_Pong`, PascalCase 멤버 → camelCase, `ToBytes()` → `Write()`.
- **고려했지만 안 고른 대안**: ① Network 코어 통째 통합(98_Shared/Net/) → ADR-012 변경 필요, sunk cost 큼. ② 부분 추출 → 경계 자의적. ③ *책임 단위*가 정답 (사용자 통찰).
- **신규 개념**: BinaryPrimitives.*LittleEndian (wire format = 플랫폼 무관 약속), `<auto-generated />` 헤더 컨벤션 (자동 생성 코드 표시), 책임 단위 분리/통합 (각 책임의 환경 의존성 기준).

## 결정 흐름 (학습 일지 쓸 때 참고용)

- **사용자 통찰로 ADR-012 *진화*** — "전부 분리"라는 첫 채택을 *책임마다 따로* 결정으로 정제. AI는 처음에 ① 통합 / ② 양쪽 별도 출력 갈래만 제시했고 *③ 책임 단위*는 사용자가 짚어줌. 시니어 사고 시범.
- **AI sliding 패턴 자기관찰** — 추천을 ① → ② → ③로 두 번 변경. 매번 검증 부족. 사용자가 *멘토 역할 짚어줌* — "어느 정도 리딩, 모호하면 짧게 묻기, 헌법 준수". 메모리(`feedback_decision_leadership.md`)에 박음.
- **"현업 표준" 카테고리 정합** — Mirror/FishNet은 *Unity 인디 멀티* 카테고리. 본 프로젝트는 *MMO 백엔드*. Rookiss = NCSoft/Nexon/Smilegate 실무 패턴. ADR-012 본문에 카테고리 맥락 추가.
- **Write() byte[] 반환 패턴** — Phase 05 PingPacket.ToBytes() 패턴이 *이미 정합*. 본 Phase에서 메서드명만 `Write()`로 통일. 호출자(GameSession)는 `Send(packet.Write())`로 직접 ArraySegment 전달.
- **`--no-manager` 옵션** — Phase 07엔 PacketManager 미사용 (직접 switch dispatch 유지). Phase 08+에서 manager + PacketHandler 도입 시 옵션 제거.
- **`--no-wait` 옵션** — Console.ReadKey CI 차단 함정 해소. `dotnet run` 자동화 가능.
- **출력 디렉토리 PDL 기준 상대 경로** — `Path.GetFullPath(pdlPath)` → `pdlDir/../..` = 프로젝트 루트. dotnet run 호출 위치와 무관하게 정확.
- **bool 처리 미해결** — `BinaryPrimitives.ReadBooleanLittleEndian` 없음. Ping/Pong엔 bool 없어 본 Phase 미발현. 미래 bool 사용 시 ReadByteFormat 패턴으로 별도 처리. ToMemberType에 ⚠️ 주석.

## 막혔던 지점

- **옛 출력 파일 잔재**: Phase 06에서 *현재 디렉토리에 출력*된 GenPackets.cs / ServerPacketManager.cs / ClientPacketManager.cs가 99_Tools/PacketGenerator/에 박혀 *생성기 자체 컴파일과 충돌*. 정리 후 출력 폴더 분리(2단계) 진행.
- **ReadFormat/WriteFormat 시그니처 변경**: Read는 3 인자였는데 Write는 2 인자였음. BinaryPrimitives 정합으로 둘 다 3 인자(변수명/메서드명/sizeof형식)로 통일. Program.cs 호출도 정정.
- **AI sliding 두 번**: 추천을 ① → ② → ③로 흔들었음. 사용자가 멘토 역할로 짚어줌. *결정의 본질* (책임 단위)을 처음에 못 본 게 본질 부족.

## 학습 일지 후보 키워드

- **decision-revisitation-pattern** — 결정을 굳히지 않고 *지속 재검증*. ADR-012가 6일 전 박혔지만 Phase 07에서 *책임 단위 정제*로 진화. 시니어 사고 시연. 면접 답변 강력.
- **responsibility-based-split** — *전부 분리* 또는 *전부 통합*이 아닌, *책임마다 환경 의존성*을 기준으로 따로 결정. 본 프로젝트의 5개 책임(socket/buffer/패킷/manager/핸들러)에 적용 사례.
- **wire-format-platform-agnostic** — `BinaryPrimitives.*LittleEndian` 명시의 의미. BitConverter 호스트 endian 함정. 게임 wire format이 *플랫폼 무관 약속*이라야 하는 이유.
- **code-generator-output-organization** — XML 단일 소스 → *책임에 맞는 위치*로 출력 분리. Generated 폴더 컨벤션. 미래 사람이 *어디를 직접 수정해야 하는지* 즉시 파악.
- **ai-mentor-sliding-pattern** — AI가 결정 떠넘기기 + 추천 흔들기 함정. 사용자 멘토링으로 정제된 *AI 행동 룰* 메모리화.
- **mmo-backend-vs-unity-indie** — 한국 MMO 백엔드(Rookiss/NCSoft) vs Unity 인디 멀티(Mirror/FishNet) 카테고리 차이. *현업 표준*은 카테고리 맥락 명시 필수.
