M4.9 Phase 01 — 스킬 이펙트 Prefab 제작 가이드

Unity 에디터에서 직접 만드는 이펙트 prefab 9개(기존 5 + Dash·Teleport 4) + MageVisual 채널링 — 옆에 띄워놓고 따라 만드는 설명서
영호 직접 작업 (외관) M4.9 Phase 01 코드 변경 없음 · 에셋만

🎯 지금 무슨 상태이고, 왜 이걸 하나

썬더볼트와 Mage 평타의 서버 로직은 이미 다 돌아갑니다. 데미지도 들어가고, 적도 맞고, freeze도 걸립니다. 그런데 화면에는 아무것도 안 보입니다.

이유는 단순합니다. 클라이언트 코드가 이펙트를 그릴 때 Resources.Load<GameObject>("Effects/이름") 으로 prefab을 런타임에 이름으로 찾아 불러옵니다. 그런데 그 prefab이 아직 없어서, 코드는 "VFX 미존재" 경고만 콘솔에 찍고 조용히 넘어갑니다. 게임은 안 멈추지만 연출이 빠진 거죠.

그래서 이번 Phase의 일은 "코드가 찾는 이름 그대로, 그 폴더에 prefab 5개를 만들어 채워 넣는 것"입니다. 코드는 한 줄도 안 건드립니다. 영호가 Unity 에디터에서 스프라이트·애니메이터를 prefab으로 묶기만 하면, 그 즉시 경고가 연출로 바뀝니다.

왜 하필 Resources 폴더여야 하나? 코드가 Resources.Load<GameObject>("Effects/이름") 으로 문자열을 써서 런타임에 로드하기 때문입니다. Unity는 Resources/ 라는 이름의 폴더 안에 있는 것만 이 방식으로 찾을 수 있어요. 그래서 폴더 이름이 한 글자라도 다르면 (예: Effect vs Effects, 또는 prefab 이름 오타) 코드가 못 찾고 warn만 찍고 끝납니다 — 에러도 안 나서 눈치채기 어렵습니다.

참고 기준점: 같은 폴더에 이미 BossAttackPattern0.prefab 이 있습니다. SpriteRenderer 설정(특히 Sorting Layer / Order in Layer)을 어떻게 맞춰야 캐릭터 위/아래로 자연스럽게 깔리는지, 그 prefab을 열어 그대로 복사 기준으로 삼으세요.

🛠️ prefab 만드는 순서 (5개 공통 패턴)

아래 4단계를 5개 prefab 각각에 반복합니다. 한 개 만들어 보면 나머지는 똑같습니다.

  1. 빈 GameObject를 만들고 컴포넌트를 붙입니다.
    씬(Hierarchy)에 빈 GameObject 생성 → SpriteRenderer 추가 + Animator 추가 → Animator의 Controller 칸에 해당 .controller를 할당합니다. 컨트롤러는 이미 만들어져 있어요: Art/Characters/Playable/Mage/Skill_Effect/Animator/ 폴더에서 이펙트에 맞는 걸 고르면 됩니다.
  2. EffectLifetime 컴포넌트를 직접 붙이고 수명을 맞춥니다.
    EffectLifetime 컴포넌트를 추가하고, _lifetime 값을 애니메이션 클립 길이에 맞춰 설정합니다. 이걸 안 붙이면 코드가 자동으로 부착해 주긴 하는데 기본값 1.5초로 고정됩니다 — 클립이 1.5초보다 짧으면 마지막 프레임이 멈춘 채 남아 있고(잔상), 길면 중간에 뚝 잘립니다. 그래서 직접 맞추는 게 좋습니다.
    예외: Projectile / RemoteProjectile 둘은 EffectLifetime이 필요 없습니다. 투사체는 ProjectileVisual이 목표에 도착하는 순간 직접 파괴하기 때문입니다.
  3. 애니메이션 클립의 Loop Time이 꺼져 있는지 확인합니다.
    이펙트는 한 번 재생하고 사라져야 합니다. Loop Time이 켜져 있으면 이펙트가 무한 반복되며 화면에 계속 남습니다. 클립을 클릭해 Inspector에서 Loop Time 체크가 해제되어 있는지 보세요.
  4. Prefab으로 만들고 임시 원본을 지웁니다.
    Hierarchy의 GameObject를 Project 창의 Assets/Resources/Effects/ 폴더로 드래그하면 prefab이 됩니다. 이름을 표의 이름과 정확히 맞춘 뒤, 씬에 남아 있던 임시 원본 GameObject는 삭제하세요 (prefab만 파일로 남으면 됩니다).

방향성(좌우 반전) 함정

이펙트는 코드가 회전·반전 없이 Quaternion.identity 로 그대로 스폰합니다. 그래서:

• LightningStrike / SkillCast / ProjectileImpact 는 좌우 방향성이 없는 그림이어야 자연스럽습니다 (낙뢰·캐스팅·폭발은 어느 방향이든 똑같이 보이게).

• Projectile / RemoteProjectile 투사체만 ProjectileVisual이 방향을 처리합니다. 스프라이트는 기본적으로 오른쪽(→)을 향하게 만드세요. 왼쪽으로 쏠 때의 반전이 제대로 되는지는 검증 단계에서 실측으로 확인합니다.

🎞️ MageVisual 본체에 채널링 애니메이션 추가

위 5개는 별도 이펙트 prefab이고, 이건 캐릭터 본체(MageVisual.prefab)에 시전 자세를 추가하는 작업입니다.

코드(AnimatorDriver)가 하는 일은 단 하나 — Animator의 AnimState 라는 int 파라미터를 6(Channeling)으로 바꿔주는 것뿐입니다. 그러니 영호 쪽에서는 그 6번 상태에 들어갈 클립과 전이(transition)만 만들어 주면 됩니다.

  • MageVisual의 Animator Controller를 엽니다.
  • 캐스팅 클립을 재생할 새 State를 추가합니다 (예: Channeling).
  • 기존 Walk / Attack 상태들이 쓰던 AnimState == N 전이 패턴을 그대로 흉내 내서, 새 상태로 들어가는 전이 조건을 AnimState Equals 6 으로 추가합니다.

핵심은 "기존에 이미 쓰고 있는 패턴을 그대로 한 줄 더 복제한다"는 점입니다. Walk 상태가 어떤 조건으로 전이되는지 먼저 살펴본 뒤, 그 조건에서 숫자만 6으로 바꾼 전이를 새 상태에 걸어주면 됩니다.

  • Mage 평타: EnergyVolt 투사체가 날아가고, 적중 시 임팩트가 표시된다.
  • 콘솔 깨끗함: "VFX 미존재" 경고 0건 + error CS 컴파일 에러 0건.
