### 3. DB 스키마

| 컬럼 | 타입 | 값 |
|---|---|---|
| `Title` | TITLE | `YYYY-MM-DD — 한 줄 요약` |
| `Date` | DATE | 세션 날짜 (오늘). **expanded key**: `"date:Date:start": "YYYY-MM-DD"` |
| `Topic` | RICH_TEXT | 한 줄 주제 |
| `Tags` | MULTI_SELECT | **JSON 배열 문자열**: `"Tags": "[\"GitHub\", \"Harness\"]"` |
| `Status` | SELECT | 보통 `completed`. 진행 중이면 `in progress` |
| `PR Link` | URL | 대화에 PR URL 있으면 채움 |

**태그 자동 매핑**:
- ADR 작성/갱신 → `ADR`
- 팀원 미팅 결과 → `팀미팅`
- GitHub repo/PR/git → `GitHub`
- Phase 작업 → `Phase`
- 개념 풀이 → `학습`
- 큰 결정 → `결정`
- 기존 코드 분석 → `코드분석`
- 헌법/Harness/CLAUDE.md/CONTEXT.md 변경 → `Harness`

⚠️ **인규/유현 자기 DB**: 스키마 동일하면 그대로. 다르면 본인 자산에 맞게 매핑 조정.

### 4. 본문 분석 (대화 → STAR)

대화에서 추출 → STAR 4섹션:

| 신호 | STAR 어디로 |
|---|---|
| 외부 맥락 (미팅·마감·팀 변동) | **상황** |
| 풀어야 했던 핵심 질문 1개 | **정해야 했던 것** |
| 옵션 A/B/C 비교, 트레이드오프, 채택 + 이유 | **한 행동** |
| 코드/문서 변경, git commit, PR URL, ADR-NNN | **결과** (구체 산출물) |
| 사용자 개념 풀이 / "오 그럼 X도 돼?" 깨달음 | **결과**의 "배운 것 3가지" |
| "다음 세션", "머지 후", 남은 것 | 하단 italics |

**"배운 것 3가지" 추출 시 주의**:
- **단편 사실 나열 X** — 사전적 정의보다 "왜 가치인지"
- **3개 우선순위 매기기** — 가장 큰 통찰만 남김
- **"내가 처음 알게 된 것"** vs "이미 알던 것" 구분 — 후자 뺌

#### 4.1 8단 사고 체크리스트 (출력 직전 점검)

STAR 4섹션 박기 전 다음 8 항목이 *어딘가에* 들어가 있는지 점검:

| 8단 항목 | STAR 어디로 |
|---|---|
| TL;DR | 제목 + 상황 첫 문장 |
| 배경/용어 맥락 | 상황 |
| 핵심 결정 | 정해야 했던 것 |
| 구현 변경 | 한 행동 |
| 검증 결과 | 결과 (앞부분 bullet) |
| 막힌 지점 | 한 행동 (녹임) |
| 학습/면접 포인트 | 결과 → 배운 것 3가지 |
| 다음 액션 | italics 한 줄 (말미) |

1. **[개념/사실]** — 한두 줄 풀이. 면접에서 답할 수 있게.
2. **[개념/사실]** — ...

*다음: [핵심 다음 액션 1~2개]*

### 7. 노션 페이지 생성 — 분기

#### 7-A. `executor == "codex"` — 본인(유영호) 흐름

Claude가 Bash로 Codex CLI 호출. Codex가 readonly로 ClaudeDev 읽고 본 명세 따라 박음. 분업 절차는 [`../templates/done-md-template.md`](../templates/done-md-template.md) "Notion 협업 분업 원칙 / 핸드오프 절차" 참조.

#### 7-B. `executor == "claude"` — Claude 단독

Claude가 `mcp__claude_ai_Notion__notion-create-pages` 직접 호출.

⚠️ 사용자가 알려준 `notion_target` 사용. 본인(유영호) 자산은 인규/유현 환경에서 X.

⚠️ **`properties`는 SQLite-flat 형식**. Notion 직접 API 중첩 객체 형식 *아님*:

```json
parent: {
  "type": "data_source_id",
  "data_source_id": "{사용자가 1.5-부수에서 알려준 ID}"
}
pages: [{
  "properties": {
    "Title": "2026-MM-DD — 한 줄 요약",
    "date:Date:start": "2026-MM-DD",
    "Topic": "한 줄 주제",
    "Tags": "[\"GitHub\", \"Harness\"]",
    "Status": "completed",
    "PR Link": "https://github.com/.../pull/N"
  },
  "icon": "🛠️",
  "content": "## 상황\n..."
}]
```

핵심:
- **Date** → `date:Date:start` expanded key
- **Tags** → JSON 배열을 **문자열**로 인코딩
- **Status / Topic / Title** → 그냥 문자열
- **PR Link** → 없으면 키 자체 생략

**알려진 함정**:
1. **JSON escape** — 한글 직접 박기 (잘못 escape 파싱 깨짐)
2. **content 길이** — 너무 길면 100 char 에러. 30~50줄 지키기
3. **parent 누락** — workspace 레벨 떨어짐
4. **properties 중첩 객체** — Notion 직접 API 형식 거부됨. SQLite-flat만 동작
5. **단일 페이지 vs DB row** — 사용자 답 따라 분기
6. **권한 없음 에러** — Claude.ai 설정 → Connectors → Notion 안내
