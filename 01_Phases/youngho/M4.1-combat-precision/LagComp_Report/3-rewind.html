Chapter 3

되감기 — Rewind

이 페이지에서 배울 것
이제 서버는 과거 위치를 기억하고 있습니다. 이 페이지에서는 공격이 들어왔을 때 서버가 "이 플레이어가 공격을 인지한 그 시점의 위치"로 어떻게 되돌려 판정하는지를 봅니다. 그리고 이 설계에서 가장 중요한 통찰 — "클라이언트는 자기 좌표가 아니라 시점 번호만 보낸다" — 가 왜 보안의 핵심인지 이해합니다.

되감기의 흐름

플레이어가 공격할 때, 클라이언트는 공격 패킷(C_Attack)에 "내가 마지막으로 받은 서버 틱 번호"를 함께 실어 보냅니다. 이 값을 attackerClientTick이라 부릅니다. 서버는 현재 틱(N)에서 공격을 처리하지만, hit 판정에 쓸 attacker의 위치는 현재 위치가 아니라 그 시점(보통 N-4쯤)의 ring buffer 위치를 꺼내 씁니다.

서버는 현재 틱 N에서 공격을 처리하되, attacker 위치만 N-4 시점으로 되감아 판정한다. (적은 현재 위치 그대로 — 이유는 아래 참고)

핵심 통찰 — 클라는 좌표가 아니라 "시점 번호"만 보낸다

💡 이 설계의 심장

클라이언트는 자기 좌표(x, y)를 절대 보내지 않습니다. 오직 시점 번호(틱)만 보냅니다. 위치는 서버가 자기 ring buffer에서 직접 꺼냅니다.

만약 클라이언트가 좌표를 보냈다면 어땠을까요? 핵 사용자는 "나는 적 바로 옆 좌표에 있었다"고 거짓 좌표를 보내 어디서든 공격을 명중시키는 텔레포트 핵을 만들 수 있습니다. 이는 헌법 #1(서버 권위)의 정면 위반입니다. 시점 번호만 받으면, 그 시점에 서버가 직접 기록한 위치만 쓰이므로 위치 조작이 원천 불가능합니다.

이 점이 바로 코드 리뷰어(Opus)가 칭찬한 부분입니다: "신뢰 경계를 시점 인덱스에만 둔 설계가 상용 FPS(Valve의 lag compensation)의 정석 패턴"이라는 평을 받았습니다. 신뢰해야 할 untrusted 입력의 표면적을 "정수 하나(틱 번호)"로 최소화한 것이 핵심입니다.

왜 적(target)은 되감지 않나요?

이번 구현에서는 attacker(공격자)만 되감고, target(적)은 현재 위치를 그대로 씁니다. 둘 다 되감으면 더 정밀하지만, 적도 시간을 거꾸로 돌려야 하므로 구현 복잡도가 올라가고, 우리 데모(고정 위치 더미 적)에서는 이득이 거의 없습니다. 그래서 "둘 다 되감기"는 의도적으로 M4.3 backlog로 미뤘습니다. 보스 AI가 도입되어 적이 활발히 움직이게 되면 그때 가치가 생깁니다. 지금 둘 다 시도하면 작업 범위가 불필요하게 커지는 scope creep(범위 과잉)이 됩니다.

실제 코드 — ProcessAttack의 되감기 부분

아래는 서버가 신뢰 경계 검증(다음 페이지에서 자세히)을 통과한 직후, ring buffer에서 위치를 꺼내는 부분입니다.

02_Server/GameServer/Maps/GameMap.cs — ProcessAttack (rewind 부분)
// 4.5) rewind 범위 검증 (3분기 — 다음 페이지 참고)
if (attackerClientTick < 0) return;                  // (a) 음수
if (attackerClientTick > _currentTick) return;        // (b) 미래
if (_currentTick - attackerClientTick > 4) return;     // (c) 200ms 초과

// rewind: attacker가 공격 버튼을 눌렀을 당시 tick의 서버 저장 위치로 되돌림.
// target은 현재 위치 사용 (target rewind는 M4.3 backlog).
Vector2 rewindedPos = attacker.GetPositionAtTick(attackerClientTick);

// 5) AABB precision hitbox (옛 dist² < range² 교체)
AABB attackBox = GetAttackHitbox(rewindedPos);
if (!attackBox.Intersects(target.Hitbox)) return;

클라이언트 쪽 — 시점 번호를 어떻게 채우나

클라이언트는 서버로부터 받는 위치 스냅샷(S_Snapshot)마다 그 안의 serverTick 값을 기억해 둡니다(LastReceivedServerTick). 공격할 때는 이 "마지막으로 본 서버 틱"을 그대로 패킷에 담습니다. 즉 "내가 화면에서 본 세계는 이 틱의 것이었다"고 서버에 알리는 것입니다.

03_Client/Assets/Scripts/Input/LocalPlayerController.cs — OnAttack
// attackerClientTick = 마지막으로 수신한 S_Snapshot의 serverTick.
// 서버 ProcessAttack이 이 tick으로 position history를 rewind해 hitbox 판정.
C_Attack pkt = new C_Attack
{
    targetEntityId     = targetEntityId,
    attackerClientTick = session.LastReceivedServerTick
};
session.SendIntent(pkt.Write());

되감기 자체는 이렇게 단순합니다. 하지만 untrusted 입력인 attackerClientTick을 그냥 믿으면 안 됩니다. 다음 페이지에서 이 값을 어떻게 검증해 핵을 막는지 봅니다.
