Chapter 4

신뢰 경계 — Cheat 차단

이 페이지에서 배울 것
클라이언트가 보내는 attackerClientTick은 신뢰할 수 없는 입력(untrusted input)입니다. 핵 사용자가 마음대로 조작할 수 있으니까요. 이 페이지에서는 이 값을 음수 / 미래 / 범위 초과 세 갈래로 검사해 부정한 공격을 조용히 버리는(silent drop) 방어 로직과, 그 바탕에 깔린 fail-closed(닫힘 우선) 사고방식을 배웁니다.

untrusted 입력이라는 전제

⚠️ 헌법 #3 — Trust Boundary (신뢰 경계)

클라이언트 소켓에서 들어오는 모든 것은 신뢰할 수 없는 입력입니다. 항상 범위를 검증하고, 소유권을 확인하고, rate-limit(횟수 제한)을 걸고, 의심스러운 패턴을 로깅합니다. attackerClientTick도 예외가 아닙니다 — 핵 사용자는 이 정수를 -9999든 999999든 마음대로 채워 보낼 수 있습니다.

3개의 검사 게이트

되감기 위치를 꺼내기 전에, 서버는 attackerClientTick이 정상 범위 안인지 세 개의 게이트로 검사합니다. 하나라도 걸리면 즉시 silent drop — 응답도, HP 변화도, broadcast도 전혀 일어나지 않습니다. 핵 입장에서는 "아무 일도 안 일어난" 것처럼 보입니다.

세 게이트 중 하나라도 걸리면 즉시 silent drop. 모두 통과해야만 되감기 위치를 꺼내 hit 판정으로 넘어간다.

세 게이트의 의미

게이트조건왜 막나
① 음수tick < 0정상 틱 번호는 음수가 될 수 없습니다. 미초기화 값이거나 조작입니다.
② 미래tick > 현재 서버 틱클라이언트가 아직 오지도 않은 미래 틱을 안다는 건 불가능합니다. 명백한 조작입니다.
③ 범위 초과현재 틱 - tick > 4200ms보다 더 옛날로 되감으려는 시도입니다. cheat 후보이거나 정상 범위를 넘은 과도한 지연입니다.

경계값 — diff=4는 통과, diff=5는 차단

게이트 ③의 조건이 > 4(4 초과)라는 점이 중요합니다. 즉 차이(diff)가 정확히 4이면 통과(hit), 5이면 차단(drop)입니다. ring buffer 깊이가 4슬롯이므로, 마침 되감을 수 있는 가장 오래된 슬롯(diff=4)까지는 허용하고, 그보다 한 틱이라도 오래되면(diff=5) 데이터가 없으니 막습니다. 버퍼 깊이와 검증 경계가 정확히 맞물리도록 설계한 것입니다. 이 경계값은 테스트로 직접 검증했습니다(7장 참고).

fail-closed 라는 사고방식

💡 fail-closed (닫힘 우선)

보안 설계에는 두 가지 기본 자세가 있습니다. fail-open(열림 우선)은 "애매하면 일단 허용", fail-closed(닫힘 우선)는 "애매하면 일단 거부"입니다. 게임 전투 판정처럼 핵 위험이 있는 곳에서는 항상 fail-closed가 정답입니다.

그래서 의심스러운 입력은 막되, 연결을 끊거나 에러를 돌려주지 않고 그냥 조용히 버립니다(silent drop). 에러를 돌려주면 핵 제작자에게 "이 값은 거부됐다"는 힌트를 주는 셈이라, 우회 방법을 찾기 쉬워집니다. 아무 반응이 없으면 핵이 무엇이 막혔는지 알기 어렵습니다.

왜 rate-limit 다음, range 검사 전에 두었나

이 3분기 검증은 코드상 rate-limit(500ms 횟수 제한) 통과 직후, AABB hitbox 검사 직전에 위치합니다. 순서에 이유가 있습니다. rate-limit을 먼저 통과시켜야 "초당 수천 번 공격"을 먼저 거를 수 있고, 그 다음 되감기 범위를 검사해야 rate-limit을 통과한 공격이 무한히 옛 시점으로 되감는 것을 막을 수 있습니다.

실제 코드 — 3분기

02_Server/GameServer/Maps/GameMap.cs — ProcessAttack (4.5단계)
// 4) rate-limit 500ms silent drop
long now = Environment.TickCount64;
if (now - attacker.LastAttackTickMs < CombatConstants.AttackCooldownMs) return;

// 4.5) rewind 범위 검증 (헌법 #3 Trust Boundary — 3분기 silent drop)
if (attackerClientTick < 0) return;                  // (a) 음수
if (attackerClientTick > _currentTick) return;        // (b) 미래
if (_currentTick - attackerClientTick > 4) return;     // (c) 200ms 초과

// rewind: 통과한 경우에만 위치 획득
Vector2 rewindedPos = attacker.GetPositionAtTick(attackerClientTick);

이제 부정한 공격은 걸러졌고, 정상 공격은 되감긴 위치를 손에 쥐었습니다. 다음 페이지에서는 그 위치로 실제 "맞았는지"를 판정하는 AABB hitbox를 봅니다.
