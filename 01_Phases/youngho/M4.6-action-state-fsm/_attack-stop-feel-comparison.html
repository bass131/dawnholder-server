M4.6 · Phase 02 전투 상태 + commit window 설계 보고서

공격을 누르면 어떻게 멈출 것인가?

"공격 중 이동 잠금(commit window)"을 넣을 때, 멈추는 감각을 어떻게 만들지 결정합니다. 제가 처음 드린 선택지("콱 정지" vs "마찰로 자연 감속")가 공정한 비교였는지, 실제 Physics.cs를 실측해서 정정합니다.

⚠️ 먼저 정정 — 이 게임엔 "마찰"이 없어요

실측 결과, 수평 속도는 매 틱 이렇게 결정돼요 (Physics.StepFlat):

vx = inputX × MoveSpeed

관성·가속도 항이 아예 없습니다 (코드 주석 그대로: "수평 velocity = inputX × MoveSpeed (즉시 반응, 관성 X)"). 입력이 0이 되면 다음 틱에 vx도 즉시 0이에요. 그래서—

  • 콱 정지는 입력만 0으로 막으면 저절로 됩니다. 추가 코드 0줄.
  • 마찰 감속은 고를 수 있는 옵션이 아니라, Physics.cs에 관성 모델을 새로 추가해야 하는 별도 작업이에요.

→ 즉, 진짜 결정은 "콱 정지 vs 마찰"이 아니라 "입력 게이트(공짜) vs 관성 시스템 신규 도입(별도 마일스톤)"입니다.

📈 같은 상황, 세 가지 결과

전사(Warrior, MoveSpeed=4)가 오른쪽으로 달리는 중 틱 3에서 공격 버튼을 누름. 이후에도 오른쪽 키는 계속 누르고 있다고 가정. 틱 간격 50ms(20 TPS), commit window 8틱(틱 3~10).

현재 (버그) — 공격해도 안 멈춤 commit window (콱 정지) — 입력 게이트 마찰 (가정) — 관성 신규 도입 시
① 수평 속도 (vx) — 틱마다의 속도

commit: 공격 순간 vx가 즉시 0 → 8틱 뒤 입력이 살아있으면 다시 4로 복귀. 버그: 공격해도 vx=4 그대로. 마찰: 4→0으로 ~7틱에 걸쳐 미끄러짐.

② 실제 위치 (x) — "공격 중에 얼마나 미끄러지나"

버그: 공격 애니는 도는데 캐릭터는 ~1.4 units 계속 전진 (= "공격중에 이동"). commit: 공격 구간 동안 위치 완전 고정(0 미끄러짐). 마찰: ~0.3u 미끄러진 뒤 정지.

⚖️ 그래서 실제 선택지는 둘

① 입력 게이트 = 콱 정지 추천

commit window 동안 입력을 inputX=0으로 막음. 끝.

  • 물리에 관성이 없어 저절로 즉시 정지 — 추가 코드 0
  • 이 게임 이동 자체가 무관성 → 일관된 감각 (걷기 멈춤도 즉시)
  • 클라 예측이 같은 규칙(상수 1개)만 따르면 끝 → 고무줄 0
  • 회귀 면적 작음 — 기존 이동 물리 안 건드림

단점: 공중 공격 시 수평 vx도 즉시 0(뚝). 단, 무관성 게임이라 점프 이동도 원래 그래서 이질감 적음.

② 관성/마찰 시스템 도입 범위 밖

Physics.cs에 가속/마찰 항을 새로 넣어 4→0 감속.

  • 모든 이동에 영향 — 걷기·점프·공격 정지 전부 바뀜
  • 클라 예측 공식도 똑같이 바꿔야 (헌법 #1 결정론)
  • 기존 이동/물리 테스트 대거 회귀 가능 (Physics는 단일 진실)
  • 새 상수(마찰계수) + 튜닝 → "이동 감각" 그 자체가 별도 마일스톤감

가치: 더 묵직한 손맛. 단 Phase 02(전투 구조 통일) 범위를 한참 넘음.

제 추천 = ①. 이번 Phase는 "공격 중 이동 잠금"이라는 규칙을 서버 권위로 도입하는 게 목표예요. 무관성 물리에서는 입력 게이트만으로 의도한 "콱 정지"가 공짜로 나오고, 회귀 위험도 가장 작습니다. "묵직한 감속 손맛"은 나중에 이동 감각 전용으로 다룰 가치가 있는 별도 주제예요 (외관/연출 마일스톤 옆 주차).
