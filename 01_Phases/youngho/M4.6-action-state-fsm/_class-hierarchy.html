M4.6 · Phase 02 플레이어 전투 State 클래스 계층 설계

플레이어 ActionFsm — 클래스 계층

누더기 latch 카운터 3개를 걷어내고, 플레이어 행동을 하나의 추상 베이스(ActorState)에서 파생된 6개 State 클래스로 통일한다. 상태는 클래스로 캡슐화되고, StateMachine이 스왑한다.

🆕 신규 ✏️ 수정 ✅ 기존 유지 commit·불가침

① 상속 계층 — ActorState 추상 베이스

▲ 6개 State가 모두 ActorState 한 베이스에서 파생. 빨강=AttackState만 이동잠금+불가침을 스스로 소유. *Death는 즉시부활이라 실게임엔 거의 안 뜸(구조 완성용).

② 구성/소유 — PlayerEntity ◇ StateMachine ◇ ActorState

▲ ◆ = 합성(소유). PlayerEntity가 StateMachine을, StateMachine이 현재 ActorState를 소유. 6개 상태는 정적 홀더가 1개씩만 들고 있어 틱 루프에 new가 없다(헌법 #5).

④ 이 계층의 핵심 정신 3가지

  • 단일 베이스 ActorState — 6개 상태가 전부 같은 추상 계층에서 파생. "지금 무슨 상태"가 타입으로 드러남 (옛 카운터 3개와 정반대).
  • 규칙은 State가 소유 — LocksMovement/InterruptibleByHit를 State가 들고, 틱 루프·전투 시스템은 그 플래그만 읽음. "공격 중 이동잠금/불가침"이 AttackState 안에 캡슐화 → 새 상태(구르기 등) 추가 시 그 클래스만 보면 됨.
  • StateMachine은 generic 유지 — 특정 상태를 모름. 설익은 추상화 회피 차원에서 Phase 04(적)에서 두 번째 케이스로 검증된 뒤 인터페이스화 검토 (지금 미리 일반화 X).

⑤ 넉백 — Physics 임펄스 채널 (HitState 전용)

이 게임 물리는 관성이 없다 (vx = inputX × MoveSpeed, 매 틱 덮어씀) → 넉백 속도를 Velocity.X에 박으면 다음 틱에 사라진다. 그래서 틱을 넘어 유지·감쇠하는 좁은 임펄스 채널을 Physics에 추가한다.

요소구분내용
PhysicsInput.ExternalVelX
98_Shared/Physics.cs		 ✏️ 수정 vx = inputX×MoveSpeed + ExternalVelX (기본 0)
기본 0 = 일반 이동 영향 0 (전면 관성 ②안은 여전히 주차). 지형 X-스윕이 vx를 쓰므로 넉백도 자동으로 벽에 막힘.
Knockback 상수
98_Shared/Constants.cs		 🆕 신규 KnockbackInitialVx(≈7f) · KnockbackDecayPerTick(≈0.75f)
98_Shared = 클라가 Phase 03서 같은 값으로 예측.

EnterHitState(dirX) → KnockbackVx = KnockbackInitialVx × sign(dirX) // 공격자 반대 방향
틱 루프 → PhysicsInput(.. , externalVelX = KnockbackVx) → Physics가 지형 충돌까지 처리
HitState.Tick → KnockbackVx ×= Decay // hitstun(8틱) 동안 감쇠 → 정지
HitState.Exit → KnockbackVx = 0 // 채널 닫음

  • 불가침 commit 중엔 넉백 X — EnterHitState가 !InterruptibleByHit면 no-op → 공격 중엔 안 밀림(rooted).
  • 서버 권위 = Phase 02 (서버가 넉백 계산·broadcast) / 클라 부드러운 예측 = Phase 03 (미러, 같은 상수로 역산).
  • 수평 only(수직 팝업 X). 밀림 거리·감쇠는 playtest 튜닝값.
