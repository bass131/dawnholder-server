Race window 다이어그램 — "두 이벤트 사이"
┌────────────────────────────────────────────────────────────────┐
│  IOCP thread                  ConcurrentQueue       Tick thread │
├────────────────────────────────────────────────────────────────┤
│  ① OnConnected               ─enqueue AddPlayer─→               │
│                                                                 │
│  ② OnDisconnected            ─[BEFORE Phase 10]                │
│     ▸ _entityId < 0          early-return ✗                    │
│       (cleanup 누락!)                                           │
│                                                                 │
│  ③                                                  ─execute─→ │
│                                                     AddPlayer  │
│                                                     ↳ ghost!   │
└────────────────────────────────────────────────────────────────┘

[AFTER Phase 10]
─────────────────

public override void OnDisconnected(EndPoint endPoint)
{
    // 이미 닫혔으면 두 번째 호출 — enqueue 안 함 (멱등성)
    if (Interlocked.Exchange(ref _closing, 1) == 1) return;

    Console.WriteLine($"[GameSession] OnDisconnected from {endPoint}");

    // 제거: if (_entityId < 0) return;

    GameMap? map = GetMap();
    if (map == null) { ... shutdown race log ... return; }
    GameSession self = this;
    map.EnqueueJob(() =>
    {
        bool removed = map.RemovePlayerBySession(self);  // owner-ref 멱등
        self._entityId = -1;  // Codex β 권장: 낡은 id 잔존 차단
    });
}

📚 학습 일지 후보 ★★★ 신규 3건

1. γ 방식 2회차 효과

1회차(audit)는 Phase 분해 *생성*에 활용. 2회차는 Phase 분해 + Phase 실행 자체를 *검증*. Codex β의 "추가 발견" 패턴 — 코드 흐름은 OK인데 주변 안전망(e.g. _entityId reset, drift verify, [Collection])이 누락된 곳을 grep + 정적 분석으로 잡음. 분해 단계 검증이 *우선순위 자체 뒤집을* 만큼 효과적.

2. "주석으로 박힌 약속은 가짜다" — 실제 봉합 순간

Phase 04 rate-limit 주석 "차단은 여전히 안 함 (Phase 05+에서 정책 결정). 기록만." — 약 2주간 코드 동작과 약속이 따로 살아있음. Phase 09에서 return; 한 줄 추가로 봉합. *헌법이 코드 동작까지 박혀야 안전망 진짜*가 되는 순간을 직접 시연. 1번째 증명(ProtocolVersion)은 미구현, 2번째 증명(rate-limit)은 봉합. 미래 봉합 후보 ProtocolVersion 핸드셰이크는 M3 첫 Phase로.

3. Connect/Disconnect Race — Deterministic 재현

분산 시스템의 "두 이벤트 사이" race가 ConcurrentQueue 순서 의존만 잡으면 *결정론적*으로 재현됨. CPU race 시뮬레이션 불필요 — IOCP thread + tick thread를 *동시 실행*하지 않고도 queue enqueue 순서만 제어. ScenarioA가 그 본질. M3 broadcast 첫 데모에서 ghost player 시각화 사고 사전 차단.
