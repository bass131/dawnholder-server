🎯무엇을 만들었나

Mage를 진짜 원거리 직업으로 만들고 첫 스킬을 붙였다. ① 평타 원거리 — 서버가 명중을 즉발 확정(lag-comp)한 뒤 S_ProjectileLaunch(23)로 발사 통보, 클라가 그때 스폰(선예측 폐지). 도착 틱에 지연 데미지 + 도착 후 StunTicks freeze. ② 최소 스킬 시스템 + 썬더볼트 AoE — C_SkillUse(24, 쿨다운만 서버 권위) → 공격자 중심 X,Y 박스 스캔 → 박스 내 적 각자 위치 낙뢰 + 광역 지연 데미지, S_SkillCast(25) 캐스팅 연출.

🤔왜 필요한가

M4.7 시점 Mage는 구조상 근접이었다. GetAttackHitbox에 class 분기가 없어 Knight·Mage 둘 다 ±1.5f AABB로 판정했고, 클라 투사체는 콜라이더 0이라 멀리 쏘면 그림만 나가고 데미지 0. 평타 1종뿐이라 스킬 발동 채널도 없었다. 추후 광역기를 붙이려면 "도착 시 범위 내 N개 판정"으로 일반화된 토대가 처음부터 필요했다.

🔀 결정 흐름

  1. 서버 확정 후 발사 — 클라 선예측 스폰 폐지("그림은 맞았는데 데미지 0" 구조적 제거). 명중 즉발 확정 → S_ProjectileLaunch 통보 → 클라 스폰. 로컬/원격 단일 경로 = 중복 0.
  2. 지연 데미지 = RespawnSystem 패턴 재사용 — "N틱 뒤 데미지"를 틱 카운트다운으로(await/Sleep 0 = 헌법 #5). 도착 시 id 재조회 + null/IsDead 재확인(late binding) = stale impact 자동 무효.
  3. freeze 서버 권위 + Boss 면역 — FrozenUntilTick + EnemyAISystem 가드. Boss는 가드 앞에서 continue + BossBehaviorSystem 가드 없음 = 면역. ApplyFreeze max(기존,신규) 중첩.
  4. PDL list 미지원 → 적별 S_HitResult 회피 — PacketGenerator 고정 필드만. 썬더볼트 타격을 적별 S_HitResult(hitEffect byte append)로 = 도구 확장 0 + 평타·썬더볼트 도착 처리 공유. append-only = 바이트 오프셋 안정성.
  5. 최소 스킬 시스템 = 쿨다운만 서버 권위 — C_SkillUse(skillId 검증+auth, caster entityId session 강제). 쿨다운 tick 기반(ms 시계 의존 회피), 초기값 -(쿨다운+1)로 long.MinValue 오버플로우 회피.
  6. freeze 강화 (도착 후 StunTicks) — 영호 결정: "도착까지"는 stun이 거의 없어 도착 + StunTicks(8틱=400ms) 더 = 진짜 stun-lock. 부수 효과로 봇 측정도 안정화.
  7. 봇 검증 경계 — Boss freeze 면역(이동)은 보스 FSM Idle dwell로 비결정 → dotnet 위임. 봇은 통합 흐름(C_SkillUse→S_SkillCast→S_HitResult hitEffect=2)만. "봇으로 뭘 측정하지 말지"의 경계.
