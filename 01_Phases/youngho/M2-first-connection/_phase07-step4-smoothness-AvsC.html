Step 4 부드러움 — 옵션 A vs C

Phase 07에서 본인 머신에 박힌 *뚜두두둑* 끊김 — 두 해결책의 trade-off 시각화.
(A) Phase 06 패턴 복귀
Predict 매 frame + Time.deltaTime. 시뮬레이션 자체가 부드러움. drift는 reconcile (S_Snapshot)로 흡수. Phase 06이 이미 검증한 방식.
(C) 50ms cadence + visual lerp
Predict는 50ms cadence 유지 (현재 Step 4) + frame 사이 보간 레이어 추가. 시뮬레이션은 fixed dt 결정론, transform은 별도 lerp.

2. 코드 패턴 비교

(A) Phase 06 패턴 복귀 — 5분 작업

// LocalPlayerController.Update()
void Update() {
    // 매 frame: Predict (Time.deltaTime 가변)
    sbyte encoded = EncodeInputX(_moveInput.x);
    _predictor.Predict(encoded, _jumpEdgeThisTick, Time.deltaTime);  // dt 인자 복귀
    transform.position = _predictor.Position;

    // 50ms cadence: 송신 only (Predict 호출 X)
    _sendAccumulator += Time.deltaTime;
    if (_sendAccumulator < Constants.TickDuration) return;
    _sendAccumulator -= Constants.TickDuration;

    // 송신 직전 jumpEdge 확정 + reset
    bool jumpEdge = _jumpEdgeThisTick;
    _jumpEdgeThisTick = false;

    _localTickCounter++;
    byte input = InputBits.Encode(encoded, jumpEdge);
    session.SendIntent(new C_MoveIntent { input = input, clientTick = _localTickCounter }.Write());
    _predictor.NotifySent(_localTickCounter, encoded, jumpEdge);
}

(C) 50ms cadence + visual lerp — 30분+ 작업

// PlayerPredictor — 추가 필드
Vector2 _prevPosition;   // lerp 시작점 (이전 tick 위치)
float _lerpAccumulator;  // 0 ~ TickDuration 범위

// LocalPlayerController.Update()
void Update() {
    _sendAccumulator += Time.deltaTime;
    _lerpAccumulator += Time.deltaTime;

    if (_sendAccumulator >= Constants.TickDuration) {
        _sendAccumulator -= Constants.TickDuration;
        _lerpAccumulator = 0;  // 새 tick 시작 = lerp 리셋

        // 50ms cadence: Predict + 송신
        sbyte encoded = EncodeInputX(_moveInput.x);
        bool jumpEdge = _jumpEdgeThisTick;
        _jumpEdgeThisTick = false;

        _predictor.SnapshotPrevPosition();  // lerp 시작점 박기
        _predictor.Predict(encoded, jumpEdge);

        _localTickCounter++;
        // ... 송신 + NotifySent (같음)
    }

    // 매 frame: lerp로 부드럽게
    float t = Mathf.Clamp01(_lerpAccumulator / Constants.TickDuration);
    Vector2 lerped = Vector2.Lerp(_predictor.PrevPosition, _predictor.Position, t);
    transform.position = lerped;
}

3. trade-off 표

(A) 매 frame Predict(C) 50ms + lerp
부드러움★★★ (시뮬 자체 부드러움)★★★ (lerp로 부드러움)
결정론★★ (근사 + reconcile 흡수)★★★ (fixed dt 정확)
코드 복잡도★★★ (Phase 06 패턴 그대로)★★ (lerp 누적기 + prev 박기)
작업 시간5분 (시그니처 + Update 정정)30~60분 (lerp 박기 + 검증)
reconcile 빈도가끔 (drift 차이 누적 시)거의 없음 (서버 fixed = 클라 fixed)
현업 사례일반 prediction 표준 (Source/Quake 등)fixed step 게임 (격투 / 콘솔 RTS)
면접 가치중 (Phase 06 패턴 일관)강 ("왜 lerp까지 박았나" 답변 재료)
완료 조건 4번 만족✓ (200ms lag 부드러움)✓ (보간으로 부드러움)
Phase 06 학습 일지 후보그대로 유지"결정론 vs 부드러움 trade-off" 별도 추가
지금 시점 권장 (A) 즉시 정정 — Phase 06 검증된 패턴 + 5분 작업 + 부드러움 회복. 본인이 Step 4 박을 때 *재해석 잘못*한 거 정직하게 인지 + 정정.
(C)는 M3+ 또는 별도 Phase 후보로 박을 가치 — 더 엄격한 부드러움이 필요한 시점에. 결정론 정확도 강함 + 면접에서 "fixed simulation + visual lerp" 패턴 설명 가능. CONTEXT.md "보류 중" 섹션에 추가:
