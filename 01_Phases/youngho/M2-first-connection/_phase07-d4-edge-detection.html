악성 클라가 정상 입력 무시하고 매 tick jumpPressed=true로 패킷 위조. 공중에서도 무한 점프 노림.

cheat 분석 (a) — 땅 닿을 때마다 점프 1회 적용 = "신나게 뛰는 캐릭터". 부정 이득 거의 없음. 정상 점프와 구분 X.
(b) — 땅 닿아도 prev=true 상태라 에지 검출 안 됨. 100% 차단. 단 cheat가 영리해서 "땅 닿기 직전에만 false 한 번 보내고 다시 true" 하면 (b)도 뚫림. 결국 양쪽 다 같은 한계.

4. Phase 06 패턴과의 연결

현재 C_MoveIntent.inputX가 어떻게 동작하는지 떠올리면:

값의미패턴
-1"왼쪽 가고 싶어"의도(intent)
0"정지"의도
+1"오른쪽 가고 싶어"의도

이미 의도 패턴이에요. 패킷 이름도 C_MoveIntent — 직역 "이동 의도". jumpPressed도 같은 결로 가면 (a) "지금 점프하고 싶어"가 자연 일관. 만약 (b)로 가면 한 패킷 안에 의도(inputX)와 상태(jumpPressed)가 섞임 — 디자인 불일치.

  1. 정의 파일 #85 명시 — "보통 에지, 클라 1tick만 true"
  2. inputX와 같은 *의도* 패턴 — 패킷 디자인 일관
  3. OnGround 안전망으로 cheat가 무한 점프 못 함 (땅 닿을 때만)
미래 강화 더 엄격한 cheat 방어 원하면 별도 anti-cheat Phase에서:
  • last-jump-tick + cooldown N tick — "점프 직후 N tick 안에 또 점프 X"
  • 비행 시간 검증 — 포물선 공식대로 떨어졌나 확인
  • velocity 일관성 — 클라 prediction과 서버 권위 거리 모니터링
