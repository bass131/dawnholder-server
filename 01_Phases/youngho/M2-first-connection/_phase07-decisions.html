Phase 07 결정 갈림 4건

중력 + 점프 도입 전, 4 가지 갈림길 정리. 각 trade-off + 현업이 어디로 가는지.
(a) — 권장 / 학습 단계 적합
(b) — 현업 정석 또는 대안
현업 출처는 각 카드 "현업"란 참조
D1 Physics.Step 함수의 인자/반환 타입은?
Shared의 공유 물리 함수는 양쪽이 쓰는데, 서버는 System.Numerics.Vector2, 클라(Unity)는 UnityEngine.Vector2 사용. 두 타입은 메모리는 같지만 컴파일러는 다르게 봄. 함수 인자를 어떻게 받을까?
● (a) System.Numerics.Vector2 사용
Shared에서 Vector2 Step(Vector2 pos, Vector2 vel, sbyte inputX, bool jumpPressed, float dt) 식. 서버는 그대로, 클라는 변환 한 줄: new UnityEngine.Vector2(v.X, v.Y).
  • 서버에서 이미 쓰는 패턴 그대로 — 일관성
  • .NET BCL 표준 타입 — 새 의존성 0
  • PDL 주석에 "양쪽 변환 필요" 박혀있는 패턴 자연 재사용
  • 클라 측에서 변환 헬퍼 한두 줄 박아야 함
● (b) float x, float y 분리 인자
(float newX, float newY, bool onGround) Step(float posX, float posY, float velX, float velY, sbyte inputX, bool jumpPressed, float dt). 양쪽 같은 시그니처, 변환 0.
  • 양쪽 변환 코드 완전 제거
  • 인자 7개 → 호출 가독성 ↓ ("이게 pos.x였나 vel.x였나?")
  • tuple 반환 → 호출 측에서 unpack 부담
  • 벡터 연산(add/scale) 직접 못 씀 → 수식이 더 빽빽해짐
현업 한국 게임 서버(Lineage·MapleStory·MIR 계열) + Unity 멀티플레이어 90%+가 Vector2 struct 표준. Riot/Blizzard 내부 엔진도 자체 Vec struct. float 분리 인자는 네트워크 wire format에서만 쓰이고 코드 안에서는 거의 안 씀.
권장(a) System.Numerics.Vector2. 현업 표준 일치 + 학습 비용 거의 0.
D2 jumpPressed 입력을 어떻게 패킷에 박을까?
C_MoveIntent가 현재 sbyte inputX + uint clientTick 두 필드. 여기에 점프 의도를 어떻게 끼울까? 향후 공격/스킬/방어 같은 다른 입력도 들어올 수 있다는 점 고려.
● (a) byte jumpPressed 단독 (0/1)
PDL에 <byte name="jumpPressed"/> 한 줄 추가. 패킷이 1 byte 더 늘어남. 클라는 pkt.jumpPressed = 1, 서버는 if (pkt.jumpPressed != 0)로 체크.
  • 가독성 최강 — 누가 봐도 "아, 점프 입력이구나"
  • PDL XML 한 줄 추가로 끝
  • 비트 연산 학습 안 해도 OK (학부 첫 학습 부담 ↓)
  • 1 bit면 충분한 정보에 8 bit 사용 (낭비)
  • 향후 입력 5~6개 추가되면 매번 byte 1개씩 → 패킷 비대
● (b) inputX와 비트필드로 합치기
PDL에 byte input 한 필드 — 비트 0~1: inputX(-1/0/1 인코딩), 비트 2: jumpPressed, 비트 3~7: 미래 입력용 여유. 디코드는 sbyte inputX = (sbyte)((input & 0x03) - 1); 식.
  • 패킷 비대 차단 — 1 byte에 8 입력 가능
  • 향후 공격/방어/스킬 추가 시 비트만 추가 → 패킷 모양 변경 X
  • 현업 정석
  • 비트 마스킹·시프트 학습 필요 (학부 백지엔 부담)
  • 디버그 시 "이게 무슨 값이지" 한 단계 더 풀이
현업 비트필드가 표준 중의 표준. Quake3 usercmd_t.buttons 8-bit, Source CUserCmd::buttons 32-bit, Overwatch input frame도 비트필드. 한국 MMORPG도 input/action mask는 거의 비트필드. 다만 학습용 토이 프로젝트는 byte 단독으로 시작하는 경우 많음.
권장 학습 단계 = (a), 진짜 라이브 게임 만들 거면 (b). Phase 07은 (a)로 가되 학습 일지에 "M3+ 입력 종류 늘어나면 비트필드 전환" 후보 박기. 현업에서 "왜 비트필드가 정석인지" 면접 답변 재료로 가치.
D3 Protocol.Version bump 하나?
기존 C_MoveIntent와 S_Snapshot에 필드를 추가하는 건 wire format 변경 = breaking change. 헌법 #2 "패킷 모양이 바뀌었다면 Protocol.Version 상수를 bump" 명시. 지금은 양쪽 동시에 새 코드로 갱신하니까 호환성 충돌이 즉시 일어나진 않음.
● (a) bump (Protocol.Version = 2 신설)
98_Shared/Protocol/에 public const ushort ProtocolVersion = 2; 박기 (Constants.cs 또는 별도 ProtocolVersion.cs). Phase 07 이전이 v1, 이후가 v2.
  • 헌법 #2 정합 — 룰을 룰대로 지킴
  • 향후 핸드셰이크 시 클라/서버 버전 비교 코드 박을 자리 확보
  • 옛 클라가 새 서버에 붙으면 "버전 불일치" 명시 disconnect 가능 (별도 Phase)
  • 학습 가치 — 실제 라이브 게임이 어떻게 클라 버전 강제하는지
  • bump 자체로는 효과 없음 — 비교 로직 별도 박아야 함
  • 지금은 한 줄 추가로 끝, 비교는 별도 Phase
● (b) skip
양쪽 동시 update니까 충돌 없음. Protocol.Version 한 줄 안 박고 진행.
  • 한 줄 덜 만짐
  • 헌법 #2 명시 위반 — "버전 관리 없으면 breaking change" 룰
  • 버전 상수 자리 없으면 후일 핸드셰이크 박을 때 처음부터 시작
  • "룰은 룰대로" 학습 기회 누락
현업 버전 bump + 핸드셰이크 비교 + 불일치 시 즉시 disconnect가 표준. Steam VAC, World of Warcraft 클라 버전 체크, 거의 모든 라이브 MMORPG가 동일. 옛 클라 접속 막아야 핵·취약점 노출 차단 + 강제 업데이트 유도.
권장(a) bump. Step 2에서 한 줄만 박기. 비교 로직은 후속 Phase로 미루기 OK.
D4 jumpPressed "에지(눌린 순간 1tick)" 처리 위치?
Space 키를 계속 누르고 있어도 점프는 *한 번*만 일어나야 함. "누른 순간 1tick"만 true로 보내는 처리(에지 검출)를 클라가 할지, 서버가 할지. 헌법 #3 (Trust Boundary) — 클라 입력은 untrusted.
● (a) 클라 에지 송신 + 서버 OnGround 안전망
클라: OnJump 액션의 "started" phase만 캡처 → 다음 송신 1회만 true. 서버: jumpPressed && OnGround일 때만 vy 부여. 공중 점프는 OnGround=false라 자연 차단.
  • Phase 07 정의 파일 #85 명시 — "보통 에지, 클라가 키 down 1tick만 true"
  • 통신량 ↓ (정상 클라는 점프 1회만 true 전송)
  • 서버 OnGround로 안전망 — cheat 클라가 매 frame true 보내도 ground 닿을 때 한 번만 적용
  • 클라가 *완전한 거짓말*하면 — cheat가 ground 도착 직후 매번 true → 정상 점프와 구분 X (의도된 한계)
● (b) 서버 에지 검출 (옛 상태 vs 현재)
클라는 누르는 동안 매 tick true 송신 (상태 보고). 서버가 prevJump==false && currJump==true일 때만 에지로 인정. 추가로 OnGround 검증.
  • 클라 신뢰 0 — 헌법 #3 가장 엄격 정합
  • cheat가 매 frame true 보내도 서버가 "옛 true → 현재 true는 에지 아님"으로 차단
  • 서버에 prev/curr 상태 필드 늘어남 (메모리 + 복잡도 ↑)
  • 통신량 ↑ — 정상 클라도 누르는 동안 매 tick 같은 값 송신
  • 정의 파일 명시와 어긋남
현업 (a) + (b) 부분 채택이 보통. 클라는 에지 송신 (정상 cadence, 통신량 절약) + 서버는 추가 검증 (OnGround 필수, 더 엄격하면 last-jump-tick + cooldown N tick까지). Source/Quake도 이 패턴. "클라 협력 가정 + 서버 검증 안전망" — 헌법 #1·#3 정신.
권장 (a). Phase 07은 OnGround 안전망만으로 충분 (땅 닿을 때만 점프). 더 엄격한 cooldown 검증(예: "점프 직후 N tick 안에 또 점프 X")은 M3+ 또는 anti-cheat Phase로 미루기 OK.
