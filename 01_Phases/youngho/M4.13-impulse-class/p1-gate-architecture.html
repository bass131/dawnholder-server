M4.13 · P1 — 행동 입력 게이트

아키텍처 결정 자료 · 옵션 A(점진) vs B(full) · 2026-06-13

한 줄 요약. 플레이어가 공격·스킬을 쓸 때 서버가 하는 "지금 이 행동 해도 되나?" 검사를 어디까지 한 곳에 모을지 정하는 문제예요. 지금 "상태 검사"가 빠져 있어 버그가 나는데, 그 빈칸만 메울지(A) / 검사 전부를 통합할지(B)의 갈림입니다.

1. 지금 무슨 일이 벌어지나

플레이어가 공격/스킬 패킷을 보내면 서버는 바로 실행하지 않고 3가지를 검사해요. 건물 정문의 검문소라고 생각하면 됩니다.

① 상태 검사 · 없음 ❌

"지금 다른 동작 중이라 새 행동 못 받는 상황 아닌가?"
예: 대쉬 중엔 평타를 막아야 함 — 이 검문이 통째로 빠짐

"이 기술 쿨타임 다 찼나?"
단, 공격은 밀리초·스킬은 게임 틱 — 시계가 둘

"이 직업이 이 스킬 쓸 자격 있나?"

🐛 그래서 생기는 버그 — "대쉬 중 평타"

대쉬는 자기 전용 상태가 없어요. 평타용 AttackState에 들어간 뒤 속도·감속값만 대쉬용으로 덮어쓰는 식으로 재활용합니다(SkillSystem.cs:94-96).

게다가 검사들이 여기저기 흩어져 있어요(공격은 CombatSystem, 스킬은 SkillUseHandler+SkillSystem). 그래서 새 기술을 추가할 때마다 검사를 손으로 다시 끼워 넣어야 합니다. "단일 입구"는 이걸 정문 하나로 모으자는 거예요.

2. 옵션 A — 빠진 검사만 추가 (점진)

지금 빠진 ① 상태 검사만 정문에 새로 세우고, 모든 공격·스킬이 그걸 먼저 거치게 해요. 쿨다운·클래스는 지금 자리에서 잘 돌고 있으니 그대로 둡니다.

3. 옵션 B — 검사 전부 한 곳으로 통합 (full)

①②③을 정문 하나(ActionGate.TryPerform)로 모읍니다. plan 원안 모양이에요.

패킷공격/스킬
→

③ 클래스   ④ rewind

Execute*순수 실행
(검증 분리)

↑ 쿨다운·클래스 값은 메타 테이블 하나(행동별 쿨다운+요구 클래스 단일 진실)에서 읽음.

enum ActionKind { Melee, Dash, Teleport, Thunderbolt }

// 행동 메타 단일 진실
Melee       → 쿨다운 10틱(=500ms),  클래스 무관
Dash        → DashCooldownTicks,    Knight
Thunderbolt → ...,                  Mage

bool TryPerform(player, kind, clientTick):
    if (!player.CurrentState.AcceptsAction(kind))            return false;  // ①
    if (currentTick - player.LastActionTick(kind) < CD(kind)) return false;  // ② 틱 통일
    if (kind.RequiredClass != null
            && player.Class != kind.RequiredClass)           return false;  // ③
    if (!ValidateRewind(clientTick, currentTick))           return false;  // ④
    player.SetLastActionTick(kind, currentTick);
    return true;   // 통과 → 호출자는 Execute*(실행)만

SRP: 상태=정책 선언 / 게이트=검사 / 실행=mutation 으로 책임 3분할. 지금 검증+실행이 섞인 ProcessAttack/ProcessDash를 쪼개야 함.

4. 진짜 갈림목 — 공격 쿨다운의 "시계"

B가 위험한 단 하나의 이유예요. 두 검사가 서로 다른 시계를 씁니다:

⏱️ 공격 쿨다운 = 벽시계(밀리초)

Environment.TickCount64로 "정확히 500ms 지났나"를 잼. 서버 컴퓨터의 실제 시간 기준 (CombatSystem.cs:45).

🎮 스킬 쿨다운 = 게임 틱

map.CurrentTick으로 "몇 틱 지났나"를 잼. 게임 진행 기준 (SkillSystem.cs:82).

B로 한 입구에 합치려면 공격도 게임 틱(10틱)으로 바꿔야 해요. 평소 20TPS면 10틱=500ms로 같지만, 서버가 순간 버벅여 틱이 밀리면 체감 간격이 살짝 달라질 수 있어요. 무엇보다 이 코드가 공격 스팸을 막는 rate-limit(핵 방어)이라, 손대면 관련 테스트를 전부 다시 맞춰야 합니다. ← P1에서 가장 위험한 한 수.

💡 추천 — A로 깔고, '쿨다운 통일'은 따로

진짜 빠진 건 ① 상태 검사 하나뿐이고 ②③은 멀쩡히 돌아요. 이 코드는 신뢰 경계(클라가 보낸 걸 못 믿고 검증하는 보안 코드)라 적게 건드릴수록 안전합니다.

B의 "한 테이블·한 입구"는 분명 더 이상적인 최종 형태예요. 하지만 그 매력의 대부분은 '쿨다운 일원화'에서 오는데, SRP로 보면 그건 '상태 게이트'와 다른 관심사라 별도 리팩토링으로 떼는 게 맞아요. P1에서 공격 rate-limit까지 통째로 뜯으면 위험·회귀가 같이 커집니다.

제안: P1 = A(상태 게이트 + LungeDecayPerTick 상태 소유 봉합)로 토대를 깔고, '쿨다운 단일 입구 통합'은 나중에 작은 독립 리팩토링으로. 그래도 "이왕 하는 거 한 번에"가 좋으면 B도 합리적 — 대신 P1이 무거워지는 걸 감수하면 됩니다.
