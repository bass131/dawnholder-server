📌 TL;DR

게임에 사운드가 0이던 상태에서 사운드 시스템 + 33개 사운드를 입혔다. 야간 AutoMode가 인프라·wiring·에셋 생성 1패스를 완주하고, 영호가 인게임 청음으로 직접 검수하며 대대적 재튜닝을 지시했다.

핵심 재튜닝 3축: ① 사운드 키 분리(단일 hit/attack → 적종류·직업·보스별, 메이플스토리가 각 이벤트에 어떤 성격의 소리를 쓰는지 참고) · ② BGM 소스 증폭(원본이 엔딩보다 15~22dB 작아 안 들리던 것을 Unity 내 샘플 정규화) · ③ town BGM 전환 버그. 곁들여 플레이테스트 게임플레이 3건(보스 빈방 재출현 / 적 중력·낙사 / 캐릭터선택 포트레이트 애니)도 폴리시.

ProtocolVersion v16 무변경 — 사운드는 순수 클라 표현, 서버 게임플레이는 기존 패킷(S_EntityDeath/S_EntityState) 재사용. 영호 GO로 push/PR/admin merge.

🤔 왜 필요한가 — 결정 흐름

키 분리 = 적종류·직업·보스별 vs 단일 스탬프
메이플이 이벤트마다 다른 성격의 소리를 쓰는 걸 참고. 청각이 대상을 구분 → 타격감. 단점=키·에셋 수 ↑(13 신규).
BGM 소스 증폭 vs AudioSource.volume 상향
volume은 [0,1] 천장이라 작은 클립은 못 키움. GetData(★LoadAudioData+Decompress)로 샘플 읽어 정규화 후 WAV 재작성. "town 안 들림 = 사실 너무 작음".
사운드 = 전량 클라, 서버 무변경 vs 사운드 패킷 신설
헌법 #1 — 사운드는 렌더 계층. 적 종류=EnemyRegistry, 직업=ClassLoadout 로컬 보유. ProtocolVersion 무변경 + co-review 회피.
적 중력 = FSM 독립 매 틱 vs Chase 상태에 끼워넣기
ApplyEnemyGravity가 Physics.Step(inputX=0) 재사용 → 수평 AI 보존 + 수직만. Hit 상태도 낙하. AI 무오염 + 결정론 물리 재사용.
적 낙사 = 소멸 + 책임 분리 vs HandleEnemyDeath 재사용
killer 없는 소멸 → DespawnEnemyByFall 별도 경로. Normal/Golem=재출현, Boss=제거. StageClear·OnEnemyKilled 오발동 X.
캐릭터선택 = UI Image 재타겟 ★사고+복구
UI Image는 클립이 Image.m_Sprite에 바인딩돼야 함. 초기에 게임플레이 Idle 클립을 잘못 바꿔 인게임 캐릭터 정지 → git checkout 복원. 게임플레이=SpriteRenderer / select=ClassSelect/ 완전 분리.

📚 학습 일지 후보 키워드

  • GetData + LoadAudioData — 에디터에서 AudioClip.GetData는 LoadAudioData() + DecompressOnLoad 필수(아니면 빈 샘플).
  • AudioSource 천장 → 소스 증폭 — volume [0,1]은 작은 클립을 못 키움. 샘플 정규화 후 WAV 재작성이 진짜 해법.
  • UI Image vs SpriteRenderer 애니 바인딩 — UI는 Image.m_Sprite, 게임플레이는 SpriteRenderer. AnimationUtility로 재타겟.
  • 서버 keep-alive — sleep infinity | dotnet run(stdin EOF 방지). 종료=fuser -k 7777/tcp.
  • WSL 중첩 셸 이중 전개 — $PATH/$() 이중 전개로 (x86) 괄호 syntax error. 리터럴 경로로 박기.
