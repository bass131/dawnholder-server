# 구조 개선과 AI 작업 준비도 비교 방법

이 문서는 이번 프로젝트의 로컬 비교 기준이다. 외부 공인 AI Readiness 점수나 모델 전체 능력을 뜻하지 않는다. 측정 전 점수는 **미측정**이며, M0 기준선과 M3 재평가의 조건·답변·실제 점수는 각각의 `goal.md`에만 기록한다.

## 고정 과제 v1

평가자는 각 과제를 동일한 문구로 제공한다. 피평가자는 읽기만 수행하며 코드 변경·테스트 실행·추가 위임은 하지 않는다. 각 답에는 실제 파일/심볼 근거, 확인한 사실과 가설, 미확인 부분을 포함한다. 이번 평가는 코드 근거에 기반한 로컬 평가이며, 기존 감사를 아는 작업자가 참여하면 사전 노출을 명시하고 blind benchmark로 부르지 않는다.

| 과제 | 동일하게 제공할 요청 |
|---|---|
| T1 연결 수명 | 클라이언트 자연 연결 종료 후 재접속까지 양쪽 상태 소유자와 정리 경로를 찾고, 실패·중복 완료를 확인할 최소 검증을 설명하라. |
| T2 맵 진입 | 맵 이동 중 연결 종료가 발생할 때 엔티티 소유와 클라이언트 씬·초기 상태 적용 순서를 설명하고 검증 경계를 제시하라. |
| T3 파티·퀘스트 | 파티 처치 적립부터 보스 포탈 해금까지 상태 소유자·호출 흐름을 찾고, 해산 시 진행 정책을 바꾼다면 영향 범위와 필요한 결정을 설명하라. 실제 정책은 바꾸지 말라. |
| T4 상태 전달 | 직업 기본 스탯·현재 HP·맵 이동값·저장 후보 스냅샷의 수명과 복사 경계를 설명하고, 원본 변경이 전달값에 영향을 주는지 확인할 검증을 제시하라. |

## 비교 조건

- 각 회차의 commit, 평가 시각, 모델 정확한 ID/버전과 reasoning 설정, 도구·권한·OS, 시작 문서, 검색 가능 범위를 기록한다. 모델을 임의로 고정하거나 실행 권한을 확대하지 않는다.
- 두 회차 모두 AGENTS와 해당 commit의 CURRENT를 시작점으로 제공하고 저장소의 현재 문서/소스를 읽게 한다. 기존 감사/설계·이전 답안의 사전 노출 여부를 기록한다. 새 문맥에서 후속 정답을 제공하지 않는 평가와 기존 맥락을 가진 평가를 같은 조건으로 취급하지 않는다.
- 비교 실행의 벽시계 제한은 과제당 10분이다. 실제 시작/종료, 읽은 고유 파일 수, 검색/읽기 도구 호출 수를 수집할 수 있으면 남긴다. 이미 아는 근거를 평가하거나 계측하지 못한 경우 시간/탐색량은 미측정으로 표시하며 추정 통계를 만들지 않는다. 도구 호출 수는 배치 크기와 함께 해석하며 적을수록 좋다고 단정하지 않는다.
- 가능한 한 같은 모델·설정·도구·시간 조건을 사용한다. 조건이 달라지면 차이를 명시하고 점수 차이를 리팩토링 효과로 단정하지 않는다. 전체 파일 일괄 읽기나 이전 답변 재사용으로 탐색 비용을 숨기지 않는다.
- 독립 평가자가 해당 commit의 실제 코드·계약으로 채점한다. 검토자의 기존 감사 맥락 보유 여부도 기록하고 구현자 설명이나 이전 답안을 정답으로 삼지 않는다. 시간 제한을 적용한 실행은 종료 시점 답안으로 평가하고, 실행 자체가 없으면 미측정으로 둔다.

## 채점

각 과제에 아래 4항목을 0–2점으로 평가한다. 항목별 근거/오류를 한 줄씩 남긴다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 위치와 흐름의 정확성 | 핵심 경로가 틀리거나 근거 없음 | 주요 경로는 맞지만 일부 소유자/순서 누락 | 관련 소유자·경로·순서를 코드 근거로 정확히 설명 |
| 경계와 영향 범위 | 권한·상태 수명 또는 소비자를 잘못 설명 | 주요 경계는 맞지만 관련 소비자/실패 경계 누락 | 필요한 경계·영향·정책 결정을 구분 |
| 검증의 적합성 | 무관한 검증 또는 미실행 성공 주장 | 정상 경로만 확인하거나 중요한 경쟁 순서 누락 | 해당 동작의 정상·실패/경쟁 경계와 실제 실행 한계를 구분 |
| 사실과 불확실성 | 가설·주석·과거 기록을 현재 사실로 단정 | 일부 불확실성만 표시 | 코드 사실·가설·미확인을 근거와 함께 분리 |

4과제×8점 = 32점이며 전 과제 측정 시에만 `획득점/32×100`을 보조 요약으로 쓴다. 일부 미측정이면 완료 과제의 원점수와 측정 범위만 보고하며 분모를 줄여 전체 점수처럼 표시하지 않는다. 점수 외에 누락된 핵심 경계 수, 독립 평가자의 사실 수정 요청 수, 시간·탐색 부담을 함께 비교한다.

## 구조 지표

M0와 M3에서 같은 경계(서버 수명주기, 클라이언트 연결/진입, 파티·퀘스트, 플레이어 상태 전달)를 대상으로 다음 증거를 비교한다. 파일 수·주석 삭제량·패턴 개수는 개선 지표가 아니다.

| 지표 | 기록할 근거 |
|---|---|
| 상태 소유 | 상태별 writer/실행 흐름 표, 서로 다른 곳의 중복 원본 여부 |
| 도메인 결합 | 다른 도메인 상태를 직접 변경하는 지점과 필요한 변경 파일 |
| 검증 가능성 | 소유 경계를 독립 검증할 진입점, 기존 통합 검증과 남은 공백 |
| 계약 정확성 | 실제 코드와 다른 현재 주석·문서, 수정 여부와 근거 |

초기 비교 대상은 세션/월드 전이 소유, 클라이언트 연결 상태 미러, Quest의 PartyState 직접 변경, PlayerStats/Entity/Snapshot의 수명 구분이다. 실제 건수는 측정 후 적는다. 새 구조로 코드가 늘어도 소유권·검증 경계가 명확해졌는지로 판단한다.
