# phases/ — 작업을 작은 단위로 쪼개기

> **이 디렉토리의 역할**: 큰 작업("서버 만들기" 같은)을 본인이 한 세션에
> 다룰 수 있는 작은 Phase로 쪼개 둡니다. 한 Phase = 1~3시간 작업.

---

## 왜 Phase로 쪼개나

큰 프로젝트 처음 할 때 가장 막막한 게 "어디서부터 시작?"입니다.
Phase 시스템은 이걸 명시적으로 해결해요:

1. **AI한테 "다 만들어줘"라고 하면** → AI는 무모하게 폭주하거나, 아니면
   너무 적게 하고 멈춥니다. 학습도 안 돼요.
2. **Phase로 쪼개면** → 한 번에 한 단계씩, 각 단계가 끝나면 5단계 보고로
   학습 정리, 다음 Phase로 넘어감.

- 한 Phase = 한 마크다운 파일

## Phase 파일 형식

각 Phase는 다음 섹션을 가집니다:

1. **목표** — 이 Phase 끝나면 무엇이 동작해야 하는지
2. **사전 조건** — 이걸 시작하려면 뭐가 먼저 끝나있어야 하는지
3. **작업 내용** — 구체적으로 뭘 만들지 (체크리스트)
4. **완료 조건** — 어떻게 "끝났다"를 판단하는지 (객관적 기준)
5. **테스트** — 어떻게 검증할지
6. **학습 포인트** — 이번 Phase에서 새로 배우는 개념 미리보기
7. **상태** — pending / in-progress / done / blocked

`phases/_template.md`를 복사해서 시작하면 됩니다.

## 워크플로우

### Phase 작성 (`/work:plan` 커맨드)

```
/work:plan M1 (또는 구체적 목표)
```

→ AI가 docs/ 읽고 적절한 Phase들로 쪼개서 파일 생성. 본인이 검토하고
필요하면 조정.

### Phase 실행

```
phases/M1-foundation/01-server-bootstrap.md 시작하자
```

→ AI가 해당 Phase 파일을 읽고 그 범위 안에서만 작업. 끝나면 5단계 보고.
완료 조건 충족하면 상태를 done으로.

### Phase 리뷰 (`/work:review` 커맨드)

Phase 끝났을 때 `/work:review`로 헌법/ADR/테스트 준수 여부 자동 체크.

## 중요 원칙

### 1. 한 번에 하나씩

`execute.py` 같은 자동 순차 실행은 우리 학습 모드에 안 맞아요.
**한 Phase 끝 → 보고 받고 이해 → 다음 Phase 수동 시작**.

### 2. Phase가 막히면 더 쪼개기

한 Phase가 너무 커서 답답하면, 그 Phase를 다시 더 작게 쪼개세요.
"3시간 안에 못 끝낼 것 같다"가 신호.

### 3. Phase 안에서 scope 늘리지 말기

Phase 작업하다가 "아 이거도 같이 해야겠네"가 떠오르면 → **새 Phase로
적어두기**, 지금 Phase에는 추가 안 함. AI한테도 같은 규칙.

### 4. 완료 조건은 객관적으로

"잘 작동함" 같은 모호한 표현 금지. "10000번 연결하고 끊어도 누수 없음"
같이 측정 가능하게. 안 그러면 "끝났다 / 안 끝났다" 논쟁 발생.
