03 / CHANGES

V1.0 정본 PR에서 바뀐 것

아래 diff는 base 89a2c02와 head 36b76d9의 실제 git diff -U1 결과입니다. 긴 hunk는 표시한 범위만 잘랐습니다.

1. 기록 양식 한 줄

원천을 옮겨 적을 때 원천의 확인 수준을 유지합니다. 관측과 추론도 나눠 적습니다. 리드가 원천 요약을 goal·BACKLOG·계약으로 옮기다 확인 수준을 올려 적은 일이 두 번 있었습니다. 교정 층 규칙에 따라 두 번째 발생에서 반복 규칙으로 올렸습니다.

2. 규칙 맞춤과 합류점 절차

규칙 문서 PR이 병합되면 살아 있는 리드는 다음 안전 지점에 최신 main을 받습니다. 안전 지점은 새 계약이나 세션을 열기 전입니다. 닫힌 파트는 재진입 첫 일로 받습니다. 떠 있는 세션은 시작 때 읽은 규칙을 계속 씁니다.

합류점에서는 branch 상태 네 가지로 처리를 가릅니다. 처리 표는 5절에 있습니다. ORCA R-8은 이 절을 가리키기만 합니다.

3. 사용자 차례 알림

작업자가 사용자에게 명령이나 입력 차례를 넘기면 리드에 status를 보냅니다. 보고를 마칠 때도 같습니다. 리드는 판단 없이 바로 메인에 한 줄 status로 넘깁니다. 메인의 폴더 감시는 보조 그물입니다.

4. V1.0 판 표시

AGENTS 맨 앞에 판 이름과 합류점 태그 이름을 적었습니다. 태그 자체는 아직 만들지 않았습니다.

5. 구현자 난이도 라우팅 시범

사용자는 Sol max만 쓰면 어려운 작업에서 힘들어한다고 보았습니다. 그래서 구현자를 gpt-6.1-sol max와 gpt-6-astra xhigh 둘로 나눴습니다. 리드는 위임 계약을 쓸 때 난이도 신호로 모델을 고릅니다. 신호가 하나라도 있으면 Astra, 애매해도 Astra, 없으면 Sol입니다.

신호는 Sol max 시기 사례 14개에서 뽑았습니다. 같은 결함 번호가 다시 실패한 사례는 0건이었습니다. 그래서 확정 실패 3회 규칙은 한 번도 발동하지 않았습니다. 이 공백을 신호 5가 메웁니다. Astra 구현 표본은 아직 0이라 2026-10-31에 사용자가 평가합니다.

6. 규칙 문서 bytes 상쇄

여섯 파일 묶음은 PR마다 base보다 늘지 않아야 합니다. 새 문장이 늘린 만큼 지난 기록 문장 일곱 곳을 goal로 옮겼습니다. 옮긴 원문은 goal 「정본에서 옮긴 적용 기록」에 그대로 있습니다. AGENTS 전환 문단은 끝난 Core 명칭 전환 부분만 줄였습니다.

06 / USER DECISIONS

이 안건은 BACKLOG report-response-format의 두 갈래입니다. 첫째는 ASD-STE100 문장 규칙입니다. 둘째는 answer-me-with-html 보고 방식입니다. 둘 다 2026-10-03 사용자 요청에서 왔습니다.

출발점

Andrej Karpathy는 2026-10-02 X 게시물에서 LLM 출력을 읽는 형식을 네 단계로 제안했습니다. 단계는 글, 도식, 웹 페이지, 설명 영상 순서입니다. 글 단계에서는 LLM에게 ASD-STE100으로 설명하게 하라고 합니다. 규격이 엄격해 「80% of the way to ASD-STE100」로 완화하기도 한다고 적었습니다. 원문은 메인이 2026-10-09에 사용자의 Chrome으로 확인했습니다.

이 안건의 두 갈래는 그 단계와 맞물립니다. STE 문장 규칙은 글 단계에 해당합니다. HTML 보고 방식은 웹 페이지 단계에 해당합니다.

answer-me-with-html은 MIT 라이선스의 공개 저장소입니다. 에이전트는 짧은 Markdown 초안만 씁니다. 동봉 CLI가 템플릿으로 단일 HTML을 만듭니다. CLI는 렌더할 때 STE를 응용한 문장 검사도 합니다.

README는 손으로 쓴 HTML보다 출력 토큰이 약 1/8이고 2.6배 빠르다고 주장합니다. 표본은 3주제를 3회씩 돈 중앙값입니다. 이 수치는 README 주장이며 재현하지 않았습니다. 2026-10-03 메모의 수치와도 달라 README가 그 뒤 바뀐 것으로 봅니다. 도구는 설치하지 않았고 도입은 사용자 승인과 코드 실사 뒤입니다.
