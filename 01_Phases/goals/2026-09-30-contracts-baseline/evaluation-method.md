# 계약 탐색 평가 v1

측정 대상은 고정 과제의 설명 정확도와 탐색 부담이다. 종합 코드 품질 점수나 PR 합격선이 아니다. P0 목표의 평가 방법 초안이며 baseline 실행·정답 작성·채점 완료를 뜻하지 않는다.

## 고정 질문

| ID | 응답자에게 제공할 질문 |
|---|---|
| T1 | 다른 플레이어의 파티 초대를 받은 사용자가 수락하는 흐름을 입력부터 결과 표시까지 추적하라. 로컬 접수와 서버 확정, 상태 변경 소유자·실패 경로·검증 진입점을 근거로 설명하라. |
| T2 | 메인 메뉴에서 서버 연결 확인을 시작한 뒤 응답 전에 해당 화면이 닫힌 경우를 추적하라. callback/구독의 생성·종료·늦은 결과 적용 책임과 현재 보장되지 않는 부분을 구분하라. |
| T3 | 최초 접속 후 첫 맵 진입에서 서버 상태 전달과 클라이언트 씬 준비·HP 표시의 순서를 추적하라. 맵 간 전환은 이 과제의 필수 대상이 아니다. 요청/완료 의미와 순서 회귀를 검출할 기존 검증 접점을 설명하라. |
| T4 | 현재 DB 설계와 구현을 구분해 actor 밖 저장/조회 결과를 게임 상태에 적용하는 데 필요한 소유권·실패·결과불명 계약을 설명하라. 구현 여부와 설계상 요구를 각각 근거로 표시하라. |
| T5 | 클라이언트에서 서버로 보내는 이동 요청 패킷에 정수 필드 하나를 추가한다고 가정하고 생성 입력부터 서버/클라이언트 소비까지 영향 경계를 추적하라. ID/버전·생성물·직렬화·양쪽 검증 접점과 확인하지 못한 부분을 구분하라. 실제 변경은 하지 않는다. |
| T6 | 패킷 생성 도구의 정상 종료·출력 실패·입력 파싱 실패 계약을 추적하라. 소비자가 관찰하는 종료/출력 차이와 격리 검증 진입점을 설명하라. |

답안은 소유/수명, 정상·실패 순서, 영향 경계, 검증/불확실성의 네 문단으로 쓰고 각 주장에 commit 내 경로와 심볼/문서절을 붙인다. 과제당 한국어 1,500자 이내, 근거 목록 별도. 파일명 정답·과거 보고서·이전 답안은 시작 prompt에 넣지 않는다.

## 채점과 중단

네 항목 각각 0–2점, 과제당 8점이다. 0은 핵심 오류·근거 없음·무응답, 1은 주요 설명은 맞지만 필수 내용 일부 누락, 2는 필수 계약과 근거를 정확히 설명한 경우다. 정답표는 과제별 필수 주장·허용 대안·부분점수·허용 불확실성·치명적 반대 주장을 실행 전에 고정한다.

미구현을 완료로, 로컬 접수를 서버/DB 완료로, 미실행을 성공으로 단정한 항목은 0점과 overconfidence flag를 기록한다. 별도 중복 감점은 없다. 모른다는 답은 과잉확신으로 처리하지 않으나 필수 내용 점수는 주지 않는다.

10분 안에 남긴 부분 답도 채점하고 timeout을 별도 기록한다. 탐색 실패를 인프라 실패로 숨기지 않는다. 도구 불가·필수 파일 누락·예기치 않은 답안 노출은 invalid로 남기고 수정 후 새 맥락에서 재실행한다. 최초 기록을 보존하고 점수가 좋아질 때까지 반복하지 않는다.

## 실행과 노출 조건

- 남은 PR 통합 및 P0 방법 검토 후 전체 commit B를 baseline으로 고정한다. 개선 후 A는 별도 commit이다. 실행 중 branch의 현재 파일 대신 지정 commit의 파일만 읽는다.
- 지정 모델은 gpt-6-astra, effort high, 각 과제·각 revision마다 이전 작업 대화를 제공하지 않은 새 맥락을 사용한다. 정답 작성자·검토자·기존 구현 담당자는 응답자가 되지 않는다. 각 과제 상한 10분, 최초 baseline은 6과제 각 1회로 진단한다.
- 동일 질문·rubric·시작 prompt·도구·locale·출력 형식·열람 규칙을 사용한다. 실제 모델·effort 적용을 확인할 수 없으면 unknown으로 기록한다. 모델명만 지정했다고 실제 모델이 증명된 것으로 쓰지 않는다.
- 허용 대상은 해당 commit의 추적된 02_Server/03_Client/04_ClientNet/98_Shared/99_Tools 소스·테스트·PDL·빌드/분석 설정, 루트 AGENTS/빌드·CI 설정, 00_Document의 INDEX/FEATURE_MAP/ARCHITECTURE와 conventions/domains/operations다. 라이브러리/바이너리/에셋 내용의 전수 열람은 제외한다. T4만 D0 goal/design/implementation-plan을 추가 허용한다.
- 실행 전에 git ls-tree로 허용 파일의 정확 목록과 blob ID를 manifest에 고정한다. 질문별 허용 규칙 차이도 양쪽에 동일하게 적용한다. 정답에 필요한 문서 누락은 실행 전에 해결한다.
- .backups, 평가 방법 외 정답/답안, 과거 reports/archive 및 다른 goals, 다른 revision/이력, 외부 검색, Management worktree는 열람 금지다. 의존 정보가 필요해도 허용 밖을 임의 확장하지 않고 불확실성으로 적는다. 빌드·테스트·소스 수정은 하지 않는다.
- 검색 후 필요한 구간만 읽는다. 전체 소스 dump를 하지 않는다. 공유 파일시스템의 prompt 규칙은 기술적인 접근 차단이 아니므로 “정답 접근이 완전히 차단됐다”고 주장하지 않는다. 노출/위반은 결과에 기록한다.

## 계측과 독립 확인

run manifest에는 task/run ID, B/A full SHA, allowlist·시작 prompt·rubric hash, 지정/확인 모델과 effort, 도구 버전, 시작/종료 UTC, 노출 조건과 중단 이유를 둔다.

명령 기록은 순번·시각·명령/인자·cwd·exit·출력 잘림·접근 경로/구간을 남긴다. 비밀값이나 전체 출력은 복제하지 않는다. tool 호출 수와 내부 검색/읽기 명령 수를 구분한다. 내용이 반환된 파일의 repo-relative 경로를 중복 제거하여 소스/테스트/설정/문서별 고유 파일 수를 센다. rg 내용 hit는 포함하고 파일명만 열거한 결과는 포함하지 않는다. 계측을 검증할 수 없으면 자기 보고 추정 또는 미측정으로 표시한다.

경과시간은 prompt 전달부터 답안 또는 cutoff까지의 wall clock이며 도구·모델 대기를 포함한다. 도구 시간을 빼서 순수 사고시간이라고 부르지 않는다. 실제 토큰·cache 상태는 관측할 수 없으면 미측정이다.

독립 작성자가 B의 정답표를 만들고 다른 Astra가 핵심 근거와 부분점수를 검토한다. 질문/rubric/정답표의 hash와 검토 시점을 기록한 뒤 응답자를 시작한다. 채점자는 익명 run ID 답안을 항목별 이유와 함께 채점하고 다른 Astra가 근거를 확인한다. A의 정답은 같은 질문/rubric을 사용하되 A의 실제 구현에 맞춰 독립 확인한다. B의 파일명을 A에 강요하지 않는다.

## 변경과 결과 해석

B는 변경하지 않는다. baseline 도중 소스/문서가 바뀌면 기존 B에서 마치고 새 commit은 별도 A/시리즈로 기록한다. 질문/rubric/시간/모델/열람 규칙 변경은 v2다. 정답 오류를 고치면 영향 항목과 이유를 공개하고 양쪽을 같은 기준으로 재채점한다. 답안을 본 뒤 유리한 과제만 제거하지 않는다.

결과는 과제별 4항목 점수, 오류/과잉확신/제약, 시간·파일·명령 수를 따로 보고한다. 보조 합계 48점은 이 여섯 답안의 적합도일 뿐이다. 1회 실행으로 통계적 유의성·생산성 개선을 주장하지 않는다. 실제 runtime unknown 또는 조건 차이가 있으면 코드 변경의 인과적 효과/속도 향상률로 귀속하지 않는다. 과거 29/32→31/32와 새 점수를 같은 추세로 연결하지 않는다. LOC·주석량·테스트 수·시간을 품질 점수로 합산하지 않는다.

이 평가는 진단용이다. 제품/PR의 필수 합격선, 대규모 반복 실험, 게임 정책 변경이나 DB 권한 확대가 필요해지면 사용자와 별도로 논의한다.

실행 전 보완: cutoff 요청 시각과 실제 답안/중단 시각을 각각 기록한다. 자동 hard cutoff를 확인하지 못하면 보장했다고 쓰지 않으며 deadline 이후 답은 late로 구분하고 정시 답안과 점수를 섞지 않는다. 명령 출력이 잘렸거나 batch 내부 접근을 재구성할 수 없으면 고유 파일 수를 정확한 값으로 단정하지 않고 하한/추정/미측정으로 표시한다. 자동 제공된 시스템·프로젝트 지침과 실제 allowlist도 manifest에 기록하고, 운영 문서에 포함된 과거 관찰 정보의 노출을 숨기지 않는다.
