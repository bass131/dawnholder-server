# M1 — 서버 수명주기와 클라이언트 연결·맵 진입

상태: 예정·미착수. 브랜치/구현/검증/PR 없음. [M0](../2026-09-29-refactor-baseline/goal.md) 결과 통합 후 최신 main에서 착수한다. 필요하면 서버와 클라이언트를 작은 목표/PR로 나누고 여기에 링크한다.

## 목표와 범위

세션 진입·이동·종료의 상태 전환 소유자를 명확히 하고 클라이언트 연결 종료/재접속과 맵 진입의 완료·취소 경계를 정리한다. 현재 맵 큐·단일 월드 틱·클라이언트 dispatcher/예측 기반을 유지한다.

- 서버: `Program`, `GameWorld`, `GameSession`, `MapMigration`의 초기화·진입·이동·종료를 검토하고, 준비 완료 후 수신 시작 및 종료 순서, 엔티티 등록/해제의 단일 소유 흐름을 만든다.
- 클라이언트: `NetworkService`, `UnityClientSession`, 맵 진입/전환 handler와 `SceneTransition`의 연결 상태·세션 세대·씬 준비·초기 상태 적용·입력 재개 책임을 정리한다.
- 설계 근거: 현재 서버 전이 상태는 소켓/틱에 나뉘고 클라이언트 전환 상태는 연결·씬·정적 pending 값에 걸쳐 있다. 자연 disconnect 뒤 연결 bool 불일치와 이동 중 종료 경쟁 후보는 실행 재현 전이며 별도로 확인한다.
- 대안과 비용: 작은 서버 수명주기 조정자/클라이언트 진입 조정자를 선택적으로 도입한다. 명시적 전이 계약이 늘지만 중간 상태 해석의 분산을 줄인다. 모든 handler를 전면 재작성하지 않는다.

제외: DB/로그인 인증 설계, 전투·퀘스트 정책 변경, 맵 이동 쿨다운 변경, 임의 패킷 확장, Unity 자산/GUID 재생성. 구조 정리 중 필요한 정책 변경은 사용자 결정으로 분리한다.

## 파일 소유와 병렬 경계

착수 시 선택 설계·이유·보존 계약·전환 인터페이스·검증 경계를 이 goal의 설계 절 또는 연결된 설계 문서에 기록한다. 이어 구현 범위와 파일 목록을 확정하고 작업 단위·담당 세션/agent를 나눈 뒤 구현한다. 위 대안 요약은 이 설계 산출물을 대신하지 않는다.

서버 작업자는 위 서버 소스/관련 서버 테스트, 클라이언트 작업자는 연결·전환 소스/관련 Unity 테스트를 각각 소유한다. 정확한 파일 목록은 착수 위임에 기록한다. 서버/클라이언트는 패킷 순서·완료/취소 계약을 합의한 뒤 병렬 가능하다. PDL/Shared/공유 테스트는 메인이 단일 쓰기 담당자를 지정하기 전 수정하지 않는다. 독립 검증자는 양쪽 결과를 통합 검토한다.

## 완료조건과 검증

- [ ] 구현 전에 설계 산출물·범위/계약·작업 분할/파일 소유를 확정하고 근거 링크를 이 goal에 남긴다.
- [ ] 전이 상태별 소유자·writer·실행 흐름과 종료/취소 책임이 설명 가능하다.
- [ ] 최초 패킷·직업 선택 게이트, 중복 진입/종료, 시작 직후 접속/종료 중 접속이 보존된다.
- [ ] 이동 단계별 연결 종료에서 세션당 전체 맵 엔티티가 0/1개라는 조건을 검증한다. 기존 테스트가 다루지 않는 순서는 재현 여부를 기록한다.
- [ ] 자연 종료·거절·실패·연결 중 취소·재접속, 맵 왕복·전환 중 패킷/종료·겹친 전환의 처리 정책과 결과를 확인한다.
- [ ] 기존 `GameSessionLifecycleTests`, `SessionStateMachineTests`, `MapMigrationTests` 및 영향받은 클라이언트 테스트/Unity 플레이를 실행하고 M0 기존 실패와 구분한다.
- [ ] 독립 검증과 PR 보고가 완료되고 각 병합 승인 여부가 기록된다.

## 실제 결과와 인계

미착수이므로 변경·실행 결과 없음. 착수 시 base/branch/HEAD·파일 소유자를, 완료 시 명령/환경·근거 경로·미실행 범위·PR/승인 상태를 이곳에 기록한다. 다음 [M2](../2026-09-29-refactor-domain-state/goal.md)에 전이 소유 계약·전달값 수명·유지한 게임 정책·남은 검증 공백을 인계한다.
