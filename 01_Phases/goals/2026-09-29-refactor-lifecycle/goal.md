# M1 — 서버 수명주기와 클라이언트 연결·맵 진입

[M0](../2026-09-29-refactor-baseline/goal.md) 다음 마일스톤이다. 서버 전송/틱 종료와 클라이언트 연결/씬 전환은 검증 경계가 달라 세 개의 목표·PR로 분할했다. 각 목표의 기준·상태·결과는 아래 goal 한 곳에만 기록한다.

| 순서 | 목표 | 선행 의존성 |
|---|---|---|
| M1a | [서버 시작·종료와 세션 해제](../2026-09-29-refactor-server-lifecycle/goal.md) | M0 통합 후 최신 main |
| M1b | [클라이언트 연결 수명](../2026-09-29-refactor-client-connection/goal.md) | M1a 통합·wire 계약 보존 |
| M1c | [클라이언트 씬 진입](../2026-09-29-refactor-client-entry/goal.md) | M1b 연결 generation/취소 계약 |

전체 방향은 세션 진입·이동·종료의 소유자를 명확히 하고 현재 맵 큐·단일 월드 틱·클라이언트 dispatcher/예측 기반을 유지하는 것이다. DB/인증·전투/퀘스트 정책·맵 이동 쿨다운 변경은 제외한다. Shared/프로토콜이나 기존 Unity GUID 변경을 자동 허용하지 않는다.

각 목표는 선택 설계 문서화 → 구현 범위·계약 → 작업자/파일 소유권 → 구현 → 다른 서브에이전트의 테스트 코드 작성·실행과 독립 리뷰 → 결과 문서화 → 사용자 승인 후 병합 순서로 진행한다. 다음 목표는 최신 main의 별도 브랜치에서 시작하며 이전 PR 승인을 재사용하지 않는다.

후속 [M2](../2026-09-29-refactor-domain-state/goal.md)는 세 목표의 통합 결과와 서버–Unity 검증 공백을 확인한 뒤 진행한다. 로드맵 분할은 M1 전체 구현 완료를 뜻하지 않는다.
