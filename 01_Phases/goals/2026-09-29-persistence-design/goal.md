# 후속 — DB 설계와 연동 작업 분할

상태: 예정·미착수. [M3](../2026-09-29-refactor-regression/goal.md) 이후 별도 설계 목표다. 브랜치/설계 확정/연동 구현/검증/PR 없음.

## 목표와 범위

기존 DB schema·접속 인계를 최신 코드 구조와 대조하고, GameServer 저장·로드·재접속 복구의 제품 범위와 책임 경계를 사용자와 확정한다. schema/접속 완료를 게임 연동 완료로 간주하지 않는다.

확인할 결정은 영속 캐릭터 ID와 런타임 entity ID의 구분, 인증/소유권, 최초 생성·로드 완료 전 진입, 저장 필드·맵/위치 복귀 정책, 저장 주기·순서·실패/재시도, 중복 접속·오래된 쓰기·종료 시 보장이다. 기존 schema를 가정만으로 확장하지 않는다. 게임 틱에서 I/O 완료를 기다리지 않는 저장/로드 경계를 설계한다.

제외: 이 예정 문서만으로 SQL/계정/비밀 변경, 실제 데이터 쓰기, 마이그레이션 적용, 게임 연동 구현을 시작하지 않는다. 설계 후 구현·통합·독립 검증을 작은 후속 목표/PR로 나누며 새 범위는 메인이 사용자와 확정한다.

## 파일 소유와 병렬 경계

설계 작업자는 최신 DB 인계·관련 schema·상태 모델을 필요한 부분만 읽고 설계 산출물과 이 goal을 소유한다. 별도 검증자는 식별·권한·저장 순서·실패 계약을 대조한다. 서버/클라이언트/DB 구현 파일의 소유권은 설계와 후속 목표 합의 후 지정한다. 접속 비밀은 문서/로그에 복제하지 않는다.

## 완료조건과 검증

- [ ] 기존 schema/접속에서 검증된 사실과 아직 없는 게임 저장 연동을 구분한다.
- [ ] 사용자 정책 결정과 비동기 저장/복원·권한·실패 계약을 확정한다.
- [ ] 계약별 서버/Unity/DB 검증 시나리오, 실행 전제·데이터 부작용·복구 범위를 정의한다.
- [ ] 구현 목표의 의존성·파일 소유·완료조건·독립 검증을 분할하고 로드맵에 링크한다.
- [ ] 설계 독립 검토와 PR·각 병합 승인 상태를 기록한다. 설계 검토를 실행 성공으로 보고하지 않는다.

## 실제 결과와 인계

미착수이며 DB 설계 결정·실행 결과 없음. 착수 시 최신 main/base/branch·인계 근거를, 종료 시 사용자 결정·설계 산출물·검토 근거·남은 질문·후속 구현 링크·PR/승인을 기록한다.
