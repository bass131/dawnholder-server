# Q-1 — 가독성 기준 정착 로드맵

이 파일은 실행 goal에서 **순서·의존성·후속 요구의 인계 지도**로 전환됐다. 기준·진행 상태·실측·판정은 각 하위 `goal.md` 한 곳에 둔다. 메인 결정 `msg_b7f867c99e0f`에 따라 P0-A/A, P0-B/B, C1~C5를 하위 목표로 나누고 R-8 세션 교체도 각 하위 목표 종료 시점에 적용한다.

목적은 사람도 읽고 고칠 수 있는 서버 C# 코드다. 포매터·정적 규칙과 독립 리뷰를 구분하고, 기존 코드도 기준선 집계→모듈별 동작 보존 정리→미해결 위반 0→전체 error 승격까지 추적한다. 함수/파일 줄 수·주석량·단일 AI 점수를 차단 기준으로 삼지 않는다. 메인 `msg_69bc8300f5b7`로 전달된 사용자 결정은 **조건부 자체 Roslyn 분석기와 위반 수 ratchet**이다. 이 정책 결정은 B의 실행·병합 승인이나 완료가 아니다.

### 사용자 결정 반영 — Q-1A와 독립

메인 `msg_69bc8300f5b7`(2026-10-01 14:32:28 UTC)이 전달한 사용자 결정이며 사용자 직접 입력으로 격상하지 않는다. 앞 메시지의 대기 상태를 다음 내용으로 대체한다.

1. **F-1 조건부 자체 분석기**: 고정 패키지 원문에 외부 AI 제한 조항이 확인되면 SonarAnalyzer를 채택하지 않고 저장소 안의 자체 Roslyn 분석기로 인지 복잡도·제어 흐름 중첩을 검사한다. 구현 근거는 SonarSource Cognitive Complexity 백서 같은 **공개 명세만** 사용한다. **Sonar 소스 코드를 복사하거나 참조 구현으로 사용하지 않는다.** 구현자에게 초기 조사의 Sonar 소스 코드를 참조 구현으로 전달하지 않는다. 메서드 15·중첩 3, 프로퍼티 별도값은 명세 근거로 제안한다. 원문에 해당 조항이 없으면 채택 전 메인에 다시 보고하며 그 경우의 정책은 아직 결정되지 않았다.
2. **F-14/M2 개수 ratchet**: 파일×규칙 개수를 판정 입력으로 삼고 증가하면 실패, 감소는 기록에 반영, 새 파일은 기준 0이다. 줄 번호 없는 결정적 기록, 증가 방향 갱신의 메인 승인, 갱신 diff/독립 검증, 병행 PR 충돌 처리를 B 설계의 필수 조건으로 둔다. 수량 불변 위반 교체는 진단 목록 diff와 리뷰로 보완한다. 모듈별 정리 뒤 0인 모듈의 전체 error 승격은 유지한다.

## C 배치로 넘길 검증 계약

- 규칙×모듈 기준선에는 commit·설정 hash·정확 SDK/분석기·Compile/생성물 목록·원시 진단 경로를 둔다. 실제 입력 누락/실패와 위반 0을 구별하고 같은 조건의 전후 수치만 비교한다.
- F-16: 신규 Opus의 동작 보존 테스트를 배치 parent와 head에서 모두 실행해 결과를 비교한다. 초기화 순서가 바뀐 선언 목록과 상호 참조 초기화식을 표시하고, Shared/ClientNet은 공개 API·양쪽 소비 계약을 비교한다. 테스트 코드 정리 담당과 최종 검증자는 별도의 신규 세션이다.
- 모듈 승격 조건은 전체 입력 분석 근거, 선택 규칙 미해결 0, 국소 예외의 독립 검토, 관련 동작 보존 테스트 통과, 미변경 파일에서도 신규 위반 차단 재현이다. 모든 대상의 전면 error 승격 전에는 Q-1 전체 완료로 보고하지 않는다.
- PacketGenerator의 기존 digest/exit 계약은 Q-1A와 C3에서 유지한다. 필드/static 초기화 순서, 락/await 경계, 실패·취소·종료, 할당/반복 비용·게임 틱 순서·패킷 바이트를 보존한다.
