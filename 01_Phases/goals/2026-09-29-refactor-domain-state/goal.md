# M2 — 파티·퀘스트 소유권과 상태 모델

상태: 예정·미착수. 브랜치/구현/검증/PR 없음. [M1](../2026-09-29-refactor-lifecycle/goal.md) 통합 후 최신 main에서 착수한다. 파티·퀘스트와 공유 상태 모델은 필요하면 작은 목표/PR로 분할한다.

## 목표와 범위

파티는 멤버십, 퀘스트는 진행·해금 상태를 소유하도록 경계를 정리하고, 기본 정의·런타임 상태·맵 이동값·저장 후보값을 수명에 맞게 구분한다.

- 파티·퀘스트: `QuestRegistry`의 `PartyState.KillCount` 직접 변경 및 `GameWorld`/`PartyNotifier`를 통한 전달 책임을 분리한다. 작은 멤버십 조회 계약과 진행 변경 결과/콜백부터 검토한다. 범용 이벤트 버스 도입 자체를 목표로 삼지 않는다.
- 상태 모델: `PlayerStats`, `PlayerEntity`, `PlayerSnapshot`과 이동 전달값의 HP/스탯 소유·복사 범위를 정리한다. readonly 외피가 mutable 참조의 불변성을 보장한다고 가정하지 않는다.
- 클라이언트: 메뉴 선택 요청·서버 확정 상태·시각 설정의 구분을 검토하고 Shared 변경 소비자를 맞춘다.
- 비용/정책: 상태 이동은 파티 생성·해산 시 진행도와 맵 이동 시 행동 상태의 수명을 드러낸다. 현재 전역 초기화·해금 유지·쿨다운 초기화 등 게임 정책은 보존하며 바꾸려면 메인이 사용자와 별도 결정한다.

제외: DB schema/저장 worker/인증 구현, 새 장비·성장 시스템, 자동 정책 변경, 무관한 Unity 자산 수정. 저장 후보 DTO 정리는 게임 영속화 완료가 아니다.

## 파일 소유와 병렬 경계

착수 시 선택 설계·이유·상태 소유와 수명·전달/통보 계약·검증 경계를 이 goal의 설계 절 또는 연결된 설계 문서로 남긴다. 구현 범위·공유 타입 계약을 확정한 뒤 작업 단위·담당 세션/agent·파일 소유를 나누고 구현한다.

파티·퀘스트 작업자는 해당 도메인/통보 경계와 관련 테스트를, 모델 작업자는 Shared의 PlayerStats 및 서버 Entity/Snapshot/이동 전달 경계를 소유한다. Shared 타입은 한 작업자만 쓴다. 클라이언트 소비자 수정은 Shared 계약 확정 뒤 별도 소유자로 진행한다. GameWorld/GameSession/MapMigration 등 접점 파일은 메인이 단계별 쓰기 소유권을 지정하며 동시 편집하지 않는다. 독립 검증자는 서버·Unity 양쪽 사용처를 확인한다.

## 완료조건과 검증

- [ ] 구현 전에 설계 산출물·범위/계약·작업 분할/파일 소유를 확정하고 근거 링크를 이 goal에 남긴다.
- [ ] 멤버십·진행·해금·통보 책임과 상태 소유자가 명확하고 교차 직접 쓰기 감소를 실제 코드로 설명한다.
- [ ] 솔로/파티 적립·해산/재결성·전역 초기화·해금 유지·보스 게이트·Party→Quest 순서를 현행 정책과 대조한다.
- [ ] 기본 스탯·현재 HP·전달값의 소유/불변성을 확인하고, 캡처 후 원본 변경 검증과 이동 시 ID/HP/합의된 행동 상태 검증을 수행한다.
- [ ] `QuestKillCountTests`, 보스 게이트/파티 통합, `PlayerSnapshotTests`, `MapMigrationTests`와 영향받은 Shared/Unity 소비자를 검증한다. 필요한 클래스 선택/HP 표시 실제 플레이도 별도 기록한다.
- [ ] Shared DLL 반영 부작용과 Unity 계약을 확인하며 DB 실행으로 잘못 보고하지 않는다.
- [ ] 독립 검증·PR·각 병합 승인 상태를 기록한다.

## 실제 결과와 인계

미착수이므로 변경·실행 결과 없음. 착수 시 base/branch/HEAD·정확한 소유 파일을, 종료 시 명령/환경·근거·미실행·PR/승인을 이곳에 기록한다. 다음 [M3](../2026-09-29-refactor-regression/goal.md)에 소유 계약·보존 정책·Shared 소비자 검증·남은 결합/주석 문제를 인계한다.
