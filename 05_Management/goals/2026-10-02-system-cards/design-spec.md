# M-2 시스템 카드 디자인 명세 — 혼합안 (사용자 확인용)

## 확인 요청

사용자가 확인할 것은 이 혼합안 목업이 고른 방향, 곧 앱은 상점 장부이고 시스템 카드는 퀘스트 게시판이라는 선택을 화면에 맞게 옮겼는지 하나다. 작성자 추천은 **이대로 확인**이다. "확인" 또는 "수정: 바꿀 점 한 줄"로 답하면 된다.

| 답 | 고르면 일어나는 일 |
|---|---|
| **확인 (추천)** | 10절의 R-12/D-09 갱신 제안을 승인 요청 단계로 넘긴다. 확인만으로 규칙 문서가 바뀌거나 제품이 구현되지는 않는다. |
| 수정 요청 | 신규 디자인 세션이 그 한 줄을 반영해 목업과 이 명세를 다시 고친다. |

추천 이유는 두 가지다. 사용자가 고른 두 방향을 한 화면에서 층으로 나눠 함께 보여 주고, 데이터와 문서 본문은 평평한 장부 면에 두어 읽기 쉬움을 지켰다. 이전 A/B 중 하나를 다시 고르는 질문이 아니다.

## 산출물 상태

- **방향:** 메인이 전달한 사용자 결정이다. 앱 전체는 B 상점 장부(밝은 장부 페이지, 호두나무색 사이드바)이고, 시스템 카드는 A 퀘스트 게시판의 핀 꽂은 종이 의뢰서다. 메인은 이를 장부 페이지 안에 게시판 영역을 두는 혼합안으로 해석했다. 이 문서와 목업은 그 해석을 화면으로 옮긴 것이다.
- **작성:** 신규 디자인 작성자 세션 `[Management 검증자]`가 썼다. 요청 모델과 최초 실행 명령은 `claude-opus-5-5`, backend 실제 모델은 `unknown`이다.
- **완료된 것:** 혼합안 [목업](mockup.html)과 이 명세의 수정, 작성자 자기 점검.
- **아직 아닌 것:** 사용자 확인, 독립 디자인 검증, R-12/D-09 갱신 승인, 제품 구현, 제품 화면 검증. 목업은 제품 코드가 아니다.
- **픽셀 제목 폰트:** 보류다. 메인이 이전 작성자 추천값을 채택해 기록했고, 사용자 명시 거절이나 영구 금지가 아니다. 목업에는 픽셀 폰트가 없다.
- **이전 A/B 비교:** 두 테마 비교본과 그 추천 문구(A 추천)는 최신 선택이 아니다. 비교본은 Git commit `aa0d9c5`의 같은 경로에만 남아 있고, 현재 목업에는 테마 전환이 없다.
- **범위 밖:** 사이드바 네 번째 메뉴의 전체 시스템 도식표는 M-2 밖의 후속 후보라 목업에 넣지 않았다.
- **자료:** 상위 7개·하위 39개 분할, 기존 기록 연결, 대표 문서 9개 본문은 이전 작성자의 샘플을 그대로 썼다. 실제 guide 자료나 데이터 계약으로 확정된 것이 아니다. 이번 수정은 새 설명 본문을 쓰지 않았다.

## 1. 혼합안의 층 구조

### 1.1 층 분담

화면을 두 장식 층과 하나의 데이터 층으로 나눈다. 장식 층은 위치와 분위기를 전하고, 데이터 층은 무늬 없이 읽힌다.

| 층 | 맡는 곳 | 모양 |
|---|---|---|
| **장부 층** (앱 전체) | 사이드바, 툴바, 페이지 머리, 개발 현황 탭, 장부 페이지(1단·2단 머리와 자료 줄), 색인 탭, 구현 문서, 검색, 개발 기록, 기록 편집, 서버 운영·유저 관리, 오류 패널 | 크림색 작업 영역 위에 펼친 장부 페이지. 왼쪽 붉은 여백 괘선, 머리 아래 이중선, 바탕(Batang) 계열 serif 제목. 사이드바는 호두나무색. |
| **게시판 층** (1단·2단 카드) | 장부 페이지 안의 나무 게시판, 이름판, 핀 꽂은 의뢰서 카드, 주의 느낌표, 로딩 자리표시 | 판자와 호두나무 틀, 핀으로 꽂은 종이 카드, 단단한 픽셀 그림자 |
| **데이터 층** (평평한 면) | 카드 안 글자 면, 문서 본문, 코드 매핑 표, 검색 결과 행, 기록·편집 화면 | 단색 면, 무늬·질감 없음, 본문 15px·줄 간격 1.75 |

### 1.2 두 층을 잇는 장치

게시판이 장부 안에 따로 박혀 보이지 않도록 다섯 가지를 공유한다.

| 장치 | 장부 층 | 게시판 층 |
|---|---|---|
| 같은 나무 | 사이드바 호두나무 `#3b2a1e`, 현재 메뉴 `#5d4432`, 표식 금색 `#e3b24a` | 게시판 틀 `#3b2a1e`, 이름판 `#5d4432`, 이름판의 놋쇠 못 `#e3b24a` |
| 같은 종이 | 장부 페이지 `#fffaf0`와 왼쪽 여백 괘선 `#d9998a` | 의뢰서 카드 `#fdf6e6`에 같은 여백 괘선. "장부에서 뜯어 핀으로 꽂은 쪽지"로 읽힌다. |
| 같은 도장 | 범례·문서 머리의 상태 도장(이중선·파선·점선) | 카드 안에 같은 도장을 찍는다. |
| 의뢰서 쪽지 | 구현 문서 머리에 카드와 같은 종이·테두리·핀을 가진 쪽지 "의뢰서 `server.session`" 하나 | 게시판에서 고른 카드가 문서의 출처라는 표시다. 문서 본문에는 나무·핀이 없다. |
| 움직임 분담 | 화면 전환은 장부가 맡는다: 오른쪽에서 14px 넘겨 들어오는 페이지 넘김 | 카드 반응은 게시판이 맡는다: 2px 들림, 핀 흔들림, 주의 느낌표 뜀(`steps()` 끊김) |

### 1.3 화면별 배치

| 화면 | 장부 층 | 게시판 층 |
|---|---|---|
| 1단 전체 시스템 | 장부 페이지 머리(제목·설명·상태 범례)와 자료 줄 | 머리 아래 "시스템 의뢰 게시판"에 상위 7장 |
| 2단 하위 시스템 | 색인 탭 7개, 이어지는 장부 페이지 머리(복귀 버튼·경로·요약·진입점·하위 상태·기존 기록 접힘) | "의뢰: 시스템 이름 · N장" 게시판에 하위 카드 |
| 구현 문서 | 색인 탭과 평평한 장부 페이지 한 장(목차·본문·매핑 표·출처·이전/다음) | 머리의 의뢰서 쪽지 하나만 |
| 검색 결과 | 장부 페이지의 색인 행 세 묶음 | 없음 |
| 카드 자료 읽는 중 | 페이지 머리와 안내 문구 | 게시판에 빈 종이 7장 자리표시 |
| 자료 오류·없는 ID | 장부 오류 패널 | 없음 |
| 개발 기록·기록 편집·운영·유저 | 기존 구성 그대로, 장부 토큰만 적용 | 없음 |

### 1.4 바뀌지 않는 것

- **데이터 의미:** 카드 제목·요약·사실 목록, 구현 문서 본문, 코드 매핑 표, 기존 기록 칩.
- **상태 의미:** 구현 상태 4종, 자료 상태(로딩·실패·손상·초과), 기준 commit과 자동 갱신 안 됨 표시. 모양·글자·테두리로 구분하고 색은 보조로만 쓴다.
- **흐름:** 1단 카드 → 2단 카드 → 구현 문서 → 상위·검색 복귀, 개발 기록·기록 편집 진입, 키 조작.
- **기존 화면 의미:** 서버 운영·유저 관리의 미수집·미연결·비활성 제어, 개발 기록 탐색, catalog 편집 초안 보존.

### 1.5 레퍼런스

이전 작성자가 확인한 공식 출처를 그대로 쓴다. 이번 수정에서 출처를 다시 조회하지 않았다. 개념만 빌렸고 실제 게임 아트·UI·폰트는 가져오지 않았다. 목업의 모든 그림은 문자 격자로 직접 적은 픽셀 SVG다.

| 층 | 레퍼런스 | 확인한 출처 | 빌린 표현 의도 |
|---|---|---|---|
| 장부 | Moonlighter (Digital Sun 개발, 11 bit studios 배급) | [Steam 공식 상점 페이지](https://store.steampowered.com/app/606150/Moonlighter/) | 낮의 상점에서 진열·가격·재고를 관리하는 장부. 밝은 장부 페이지와 장부 도장을 앱 바탕·문서·상태 표시에 썼다. |
| 게시판 | Stardew Valley의 Help Wanted 게시판 (ConcernedApe) | 공식 사이트 [stardewvalley.net](https://www.stardewvalley.net/)의 Wiki 링크가 가리키는 [Quests 문서](https://stardewvalleywiki.com/Quests) | 벽의 의뢰서를 훑어보고 하나를 집는 탐색, 알릴 것에만 노란 느낌표를 다는 신호 절제를 1단·2단 카드에 썼다. |

Recettear와 Sea of Stars는 1차 출처 확인과 반영을 하지 않았다.

## 2. 화면 흐름

### 2.1 진입

개발 현황 안에 보기 탭 세 개를 둔다: **시스템 카드**(기본), **개발 기록**(기존 탐색), **기록 편집**(기존 catalog 편집). 페이지 제목·설명·"관리 기능 미연결" 안내 문구는 지금 App.tsx의 문장을 그대로 쓴다. 시스템 카드 탭 옆에 검색 입력이 붙는다.

### 2.2 1단 → 2단 → 구현 문서

| 단계 | 보이는 것 | 고르면 |
|---|---|---|
| 1단 전체 시스템 | 게시판의 상위 7장: 이름, 저장소 경로, 요약, 하위 수, 하위 상태 집계, 연결된 기존 ID 수. 자료 정보는 장부 머리의 한 줄 요약으로 접혀 있다. | 그 시스템의 2단으로 간다. |
| 2단 하위 시스템 | 색인 탭, 상위 시스템 머리(경로·요약·진입점·하위 상태·기존 기록 ID 접힘 목록), 게시판의 하위 카드: 이름, 하위 ID, 요약, 상태, 코드 매핑 수, 기존 ID, 문서 상태. | 그 하위 카드의 구현 문서로 간다. |
| 구현 문서 | 머리: 의뢰서 쪽지(하위 ID), 상위 이름 › 하위 시스템 · 구현 문서, 제목, 한 줄 설명, 상태, 기준 commit(전체 SHA 펼침), 자동 갱신 안 됨, 목업 표시. 몸: 목차와 절(책임, 입력→처리→출력, 상태·수명주기, 구현 경계, 주요 코드 위치, 검증 범위·한계, 기존 기록·정본 출처). 끝: 같은 상위의 이전·다음 하위 카드. | 목차는 해당 절로 focus를 옮긴다. 기존 기록 칩은 개발 기록 탭의 그 시스템으로 간다. |

미구현·미연결 하위 카드도 문서에 도달한다. 그 문서는 "현재 상태"와 "없는 코드"를 먼저 설명하고, 코드가 없는 부분의 매핑은 비워 둔다. 가짜 경로는 만들지 않는다.

### 2.3 복귀와 focus

| 조작 | 결과 | focus |
|---|---|---|
| 카드·결과 선택 | 한 단계 들어간다. | 새 화면의 제목 |
| `Esc` 또는 "↑ 상위" 버튼 | 문서 → 2단 → 1단으로 한 단계 올라간다. 검색에서 들어왔으면 검색어를 유지한 채 올라간다. | 방금 나온 카드의 링크 |
| "← '검색어' 검색 결과로" | 검색 결과로 돌아간다. | 방금 열었던 결과 링크 |
| 목차 링크 | 같은 문서 안의 절로 스크롤한다. 주소는 바뀌지만 기록은 늘지 않는다. | 해당 절 제목 |
| `/` | 입력 중이 아닐 때 검색 입력으로 간다. | 검색 입력 |
| 브라우저 뒤로 | 목업은 해시 주소라 뒤로가기로도 같은 흐름이 된다. 제품 Electron 창에는 기본 뒤로가기 키가 없으므로 앱 안 버튼과 `Esc`를 주 경로로 둔다. | 위와 같음 |

`Esc`는 입력 필드에 글자가 있으면 입력 지우기에 쓰이고, 빈 검색 입력에서만 상위 이동으로 동작한다. 1280×720에서 2단·문서·검색 화면은 페이지 제목 줄을 한 줄로 줄여 본문이 첫 화면에 더 많이 들어오게 한다.

### 2.4 검색

카드 이름, 하위 ID, 코드 경로와 역할, 기존 기록 ID, 문서 본문을 대상으로 공백으로 나눈 낱말을 모두 포함하는 항목을 찾는다. 결과는 장부 페이지 안에 상위 시스템·하위 시스템·문서 본문 세 묶음의 색인 행으로 나누고, 일치 부분을 강조한다. 결과 수는 `role="status"`로 읽어 준다. 결과가 없으면 찾은 범위, 다른 낱말 예시, 개발 기록에서 같은 검색어로 찾는 링크, 전체 시스템으로 돌아가는 버튼을 보여 준다.

### 2.5 개발 기록과 기록 편집

- 구현 문서의 기존 기록 칩은 개발 기록 탭에서 그 시스템을 선택한 상태로 연다. 개발 기록의 시스템 상세에는 반대 방향 링크 "이 기록과 연결된 시스템 카드"를 둔다. 다대다 연결을 양쪽에서 따라갈 수 있다.
- 문서 끝에 "개발 기록에서 보기"와 "기록 편집 열기"를 둔다. 시스템 카드 자료는 앱에서 편집하지 않는다는 문장을 함께 둔다.
- 편집 초안이 있으면 툴바에 "미저장 초안 있음" 배지가, 기록 편집 탭에 "· 미저장 초안"이 붙는다. 카드 탐색·탭 이동·검색·카드 자료 다시 읽기는 초안을 지우지 않는다.
- 저장·취소·검증 버튼에 위계를 준다. 저장은 주 버튼, 검증은 보통 버튼, 초안 버리기는 위험 버튼이다.
- 목업의 저장은 흉내만 내고 파일을 쓰지 않는다. 기존 불러오기 2 MiB 제한, 초안이 있을 때 다른 파일 불러오기 차단 문구는 기존 화면대로 보존했다.

### 2.6 서버 운영·유저 관리

사이드바 세 메뉴의 순서와 의미, 미수집 표시(—), 빈 로그·빈 유저 표, 비활성 서버 시작·종료 버튼을 그대로 둔다. 장부 토큰만 입힌다. 운영 수치나 성공 결과를 만들지 않는다. 네 번째 메뉴는 추가하지 않는다.

### 3.6 움직임

화면 전환은 장부 층, 카드 반응은 게시판 층이 맡는다. 문서 본문 안에는 움직임이 없다.

| 효과 | 층 | 시간·거리 | 곡선 | 동작 감소 |
|---|---|---|---|---|
| 화면 진입 (페이지 넘김) | 장부 | 200ms, 오른쪽에서 14px | ease-out | 0ms, 이동 0 |
| 카드 들림 (hover·focus) | 게시판 | 120ms, 2px | `steps(2)` | 0ms, 이동 0 |
| 핀 흔들림 (hover) | 게시판 | 300ms, 1회 | `steps(3)` | 끔 |
| 느낌표 뜀 (주의 카드 hover) | 게시판 | 360ms, 1회 | `steps(3)` | 끔 |
| 로딩 자리표시 깜빡임 | 게시판 | 1.2s 반복 | `steps(4)` | 끔 |
| 문서 안 스크롤 | 장부 | 부드러운 스크롤 | — | 즉시 이동 |

모든 시간은 `--motion` 배수(1 또는 0)를 곱한다. `prefers-reduced-motion: reduce`이면 `--motion`이 0이 되고 반복·장식 효과는 꺼진다. 내용과 기능은 그대로다. 무한 반복 장식은 로딩 자리표시 하나뿐이다.

### 4.3 기준 commit과 자동 갱신

- 문서마다 기준 commit 7자리와 "전체 SHA 보기"를 둔다. 펼치면 40자리 SHA를 선택해 복사할 수 있다.
- "자동 갱신 안 됨 · 현재 HEAD와 비교하지 않음"을 모든 문서 머리에 둔다.
- 1단 자료 줄은 카드 자료와 개발 기록 자료의 경로·버전·기준일을 따로 적고, hash도 자료별로 따로 표시한다. 목업은 카드 자료 hash 자리에 예시 값을 두고 개발 기록 hash는 "따로 셈"이라는 문구만 두었다. 두 자료를 하나의 snapshot으로 보이지 않게 한다.

## 5. 접근성과 반응형

- **의미 구조**: 카드는 `article` 안 제목의 링크 하나를 카드 전체로 늘린다. 지금 화면처럼 `button` 안에 `h4`·`dl`을 넣는 콘텐츠 모델 위반을 피한다. 위치는 `nav aria-label="현재 위치"`의 순서 목록과 `aria-current="page"`로 나타낸다.
- **장식**: 게시판 이름판, 핀, 느낌표, 놋쇠 못, 시스템 아이콘은 모두 `aria-hidden`이다. 이름판과 같은 정보는 화면 제목과 숨긴 목록 제목이 전한다.
- **키보드**: 모든 탐색이 링크·버튼이다. 화면이 바뀌면 제목으로 focus를 옮기고, 올라오면 직전 카드로 돌려준다. 앱 맨 앞에 "본문으로 건너뛰기"가 있다. 단축키는 `/` 검색과 `Esc` 상위 두 개뿐이다.
- **focus 고리**: 3px 실선 + 2px 간격이다. 밝은 장부 면은 파랑, 사이드바와 게시판 나무 위는 노랑을 쓴다. 카드는 카드 바깥 4px의 나무 위에 노랑 고리를 그려 들림 효과와 겹치지 않게 한다.
- **읽어 주기**: 검색 결과 수, 기록 결과 수, 편집 알림은 `role="status"`, 편집 오류는 `role="alert"`다.
- **한국어 줄바꿈**: 앱 전체에 `word-break: keep-all`과 `overflow-wrap: anywhere`를 준다. 경로는 `/` 뒤에 줄바꿈 기회를 넣고 고정폭 글꼴로 표시한다. 말줄임으로 자르지 않는다. 이름판도 줄바꿈을 허용한다.
- **폭 단계**: 창 폭이 아니라 앱 컨테이너 폭으로 판단한다(`@container`).

| 앱 폭 | 바뀌는 것 |
|---|---|

- 지금 CSP는 `style-src 'self'`, `img-src 'self'`, `default-src 'none'`이다. 묶음 CSS와 React가 CSSOM으로 넣는 style은 문제없다. 생성 이미지를 쓰면 Vite가 4 KiB 미만 파일을 data URI로 넣는 기본값 때문에 `img-src 'self'`에서 막힐 수 있다. 이 경우 파일로 내보내도록 설정을 정하거나 CSP를 바꿔야 하며, 어느 쪽이든 승인 대상이다.
- 목업은 `:has()`, `@container`, `color-mix()`, `width: max-content`를 쓴다. Chromium 111 이상이 필요하다. Electron 44의 Chromium 판이 이를 넘는지 구현 단계에서 확인한다.
- 화면 위치는 해시 대신 앱 상태로 들고, `Esc`·버튼을 주 경로로 둔다. Electron 창에는 기본 뒤로가기 키가 없다.
- root/body 배경이 R-12의 `#10151e`에서 장부 바탕으로 바뀐다. 지금 `styles.css`의 root/body와 `electron/main.ts`의 창 `backgroundColor`가 모두 `#10151e`다. 창이 처음 그려질 때 어두운 색이 번쩍이지 않도록 세 값을 함께 맞춘다.

## 9. 목업 사용법과 한계

- 파일 하나를 브라우저로 열면 된다. 외부 요청은 문서 머리의 CSP가 막는다(`connect-src 'none'`, `img-src data:`, `font-src data:`). 링크는 누를 때만 열린다.
- 위쪽 회색 막대는 목업 제어용이며 제품 화면이 아니다. 층 경계 표시, 자료 상태 8종, 긴 글·긴 경로, 창 폭(1280×720·760·420·브라우저 폭), 동작 감소, 바로 가기(대표 문서·미완료 카드·미연결 카드·결과 없음), 출처·라이선스 창이 있다. 테마 선택은 없다.
- **층 경계 표시**를 켜면 장부 층(파란 점선)과 게시판 층(노란 점선)의 경계와 이름표가 보인다. 두 층이 어디서 만나는지 확인하는 용도다.
- 주소 뒤에 `?frame=760&state=guide-fail&motion=reduce&stress=1&dirty=1&layers=1`처럼 붙이면 같은 상태로 바로 열린다. 창 폭과 동작 선택은 브라우저 저장소의 `m2-mockup-hybrid`에 남는다. 이전 목업의 `theme` 매개변수와 저장 값은 읽지 않는다.
- 본문이 있는 대표 문서는 9개다: `server.session`, `client.network`, `client-net.session`, `shared.protocol`, `tools.bot`, `management.mcp`, `automation.ci`, 미완료 예시 `server.persistence`, 미연결 예시 `management.operations`. 나머지 30개는 요약·매핑·기존 ID와 "목업: 본문 생략" 표시만 있다.
- 개발 기록 탭은 catalog의 시스템 18개·기록 18개 제목과 상태만 옮겼다. 근거 35개 목록과 동작 상세는 생략했다.
- 기록 편집의 저장은 흉내만 낸다. 검증은 JSON 구문과 최상위 필드만 본다.
- 작성자 자기 점검은 헤드리스 Chrome 브라우저 렌더에서 했다. Electron 실행, 실제 데이터 파일, MCP, 화면 낭독기는 이번 범위에서 실행하지 않았다.

## 10. 확인 뒤 갱신할 규칙 (제안, 정본 미수정)

아래는 사용자 확인과 갱신 승인 뒤 정본에 반영할 **제안 문구**다. 이 작업은 `requirements.md`와 `decisions.md`를 고치지 않았다.

**R-12 확정 항목 대체 제안:**

> 시각 방향은 상점 장부 앱과 퀘스트 게시판 카드의 혼합안이다. 앱 전체는 밝은 장부 페이지(작업 영역 `#ece3cf`, 페이지 `#fffaf0`)와 호두나무색 사이드바(`#3b2a1e`)를 쓰고, root/body 배경은 `#e9dfc9`다. 개발 현황의 1단·2단 시스템 카드만 장부 페이지 안의 나무 게시판에 핀으로 꽂은 종이 의뢰서로 표시한다. 구현 문서·검색·기록·편집·운영 화면의 데이터 면은 무늬 없이 평평하게 두고, 상태는 모양·글자·테두리로 구분한다. 가는 사이드바·낮은 헤더·상태 요약과 넓은 로그 영역·반응형 구성은 유지한다.

**R-12 설계 선택 추가 제안:**

> 게시판·핀·느낌표·아이콘은 직접 그린 픽셀 SVG/CSS로 만들고 실제 게임 아트·UI·폰트를 가져오지 않는다. 화면 전환은 장부 페이지 넘김, 카드 반응은 게시판 들림·핀 흔들림으로 나누며 `prefers-reduced-motion`에서 끈다. 제목 픽셀 폰트는 보류이며 도입하려면 출처·라이선스·CSP를 따로 승인받는다.

R-12의 보존 요구는 그대로 둔다. 향후 완료조건에는 "두 층의 경계, 동작 감소, 1280×720과 좁은 창의 실제 데스크톱 표시"를 독립 검증 대상으로 더한다.

**D-09 후속 단락 추가 제안 (기존 단락은 이력으로 보존):**

> 2026-10-02 메인을 통해 전달된 사용자 결정에 따라 R-12의 시각 방향을 다크 운영 콘솔에서 상점 장부 앱 + 퀘스트 게시판 카드 혼합안으로 바꾼다. 개념 참고는 장부 층에 Moonlighter(Steam 공식 상점 페이지), 게시판 층에 Stardew Valley Help Wanted 게시판(공식 사이트가 가리키는 Wiki Quests 문서)이다. 실제 게임 아트·UI·폰트는 복사하지 않고 픽셀 SVG를 직접 그린다. 제목 픽셀 폰트는 보류한다. 기존 shadcn·Tabler 레이아웃 참고는 사이드바·헤더 구조의 근거로 남긴다.
