## 현재 승인과 다음 확인

메인을 통한 사용자 확인으로 r2 수정 목업 `bd0f9afa…`의 디자인이 확정됐고, 메인 `msg_b1aa36494e55`가 2026-10-02 네 내부 동작과 설치/자산/격리 계약 승인을 전달했다. 이 명세는 승인된 제품 목표이며 제품 구현·실행 완료를 뜻하지 않는다. 목업의 기존 캡처·자기 점검 수치는 당시 브라우저 결과다.

다음 사용자 확인은 **실제 guide 대표 도식 3종의 시각 복잡도 관문**이다. 라이선스 관문을 먼저 확인한 뒤 실제 Electron 125%에서 호출·패킷·상태 도식을 렌더하고 신규 Opus가 글 설명과 비교한다. 메인이 사용자에게 캡처를 보여 확인받기 전에는 전체 도식을 작성하지 않는다. 기준과 실패 시 비교할 대안은 2.8절이다.

## 1. 혼합안의 층 구조

### 1.1 층 분담

화면을 두 장식 층과 하나의 데이터 층으로 나눈다. 장식 층은 위치와 분위기를 전하고, 데이터 층은 무늬 없이 읽힌다.

| 층 | 맡는 곳 | 모양 |
|---|---|---|
| **장부 층** (앱 전체) | 사이드바, 머리 한 줄, 위치 줄, 상태 표시줄, 2단 머리 띠, 구현 문서, 검색, 개발 기록, 기록 편집, 서버 운영·유저 관리, 오류 패널 | 크림색 작업 영역과 장부 페이지. 왼쪽 붉은 여백 괘선, 머리 아래 이중선. 사이드바와 상태 표시줄은 호두나무 띠이고 사이드바 위에 장부 머리 그림이 있다. |
| **게시판 층** (1단·2단 카드) | 나무 틀, 코르크판, 이름판, 의뢰서 카드, 안내 쪽지, 핀, 로딩 자리표시 | 나무 질감 틀 안의 코르크판. 종이 카드는 테두리 없이 그림자와 기울기로 뜬다. |
| **데이터 층** (평평한 면) | 카드 안 글자, 문서 본문, 코드 매핑 표, 검색 결과 행, 기록·편집 화면 | 단색 면, 무늬 없음, 시스템 글꼴. 문서 본문 15px·줄 간격 1.75. |

### 1.2 두 층을 잇는 장치

| 장치 | 장부 층 | 게시판 층 |
|---|---|---|
| 같은 나무 | 사이드바에 나무 질감을 62% 어둡게 덮어 깐다. 상태 표시줄도 같은 호두나무색이다. | 게시판 틀과 이름판이 같은 나무 질감이다. |
| 같은 종이 | 장부 페이지 `#fffaf0`와 왼쪽 여백 괘선 `#d9998a` | 의뢰서 `#fbf3df`에 같은 여백 괘선. 장부에서 뜯어 꽂은 쪽지로 읽힌다. |
| 같은 도장 | 문서 머리·검색·안내 쪽지에 같은 도장 그림과 글자 | 1단은 하위 상태 도장 집계, 2단은 큰 도장 |
| 의뢰서 쪽지 | 구현 문서 머리에 엠블럼·핀이 달린 종이 쪽지 하나 | 게시판에서 고른 카드가 문서의 출처라는 표시다. 문서 본문에는 나무·핀이 없다. |
| 움직임 분담 | 화면 전환: 오른쪽에서 14px 넘겨 들어오는 페이지 넘김 | 카드 반응: 기울기를 펴며 3px 들림, 핀 흔들림, 고르면 핀이 빠지며 들리는 선택 전환 |

### 1.3 화면별 배치

| 화면 | 장부 층 | 게시판 층 |
|---|---|---|
| 1단 전체 시스템 | 머리 한 줄, 위치 줄, 상태 표시줄 | 화면 전체가 게시판이다. 이름판 "전체 시스템"이 화면 제목이고, 상위 일곱 장과 안내 쪽지 한 장을 4열 두 줄로 꽂는다. |
| 2단 하위 시스템 | 색인 탭 7개, 장부 머리 띠(엠블럼·이름·경로·요약·하위 상태·이동 꼬리표, 진입점과 기존 기록은 접힘) | "하위 의뢰 N장" 게시판에 하위 카드 |
| 구현 문서 | 색인 탭과 평평한 장부 페이지 한 장(목차·본문·매핑 표·출처·이전/다음) | 머리의 의뢰서 쪽지 하나만 |
| 검색 결과 | 장부 페이지의 색인 행 세 묶음 | 없음 |
| 카드 자료 읽는 중 | 상태 표시줄 | 빈 종이 일곱 장 자리표시와 안내 쪽지 자리의 읽는 중 문구 |
| 자료 오류·없는 ID | 장부 오류 패널 | 없음 |
| 개발 기록·기록 편집·운영·유저 | 기존 구성 그대로, 장부 토큰과 역할별 컨트롤만 적용 | 없음 |

### 1.4 바뀌지 않는 것

- **데이터 의미:** 카드 제목·요약·사실, 구현 문서 본문, 코드 매핑 표, 기존 기록 칩. 1단 카드에서 뺀 경로·기존 기록 수는 2단 머리에서 그대로 보인다.
- **상태 의미:** 구현 상태 4종, 자료 상태(로딩·실패·손상·초과), 기준 commit과 자동 갱신 안 됨 표시. 모양·글자로 구분하고 색은 보조로만 쓴다.
- **흐름:** 1단 카드 → 2단 카드 → 구현 문서 → 상위·검색 복귀, 개발 기록·기록 편집 진입, 키 조작.
- **기존 화면 의미:** 서버 운영·유저 관리의 미수집·미연결·비활성 제어, 개발 기록 탐색, catalog 편집 초안 보존.

## 2. 화면 흐름

### 2.1 진입과 머리 한 줄

- **머리 한 줄:** 화면 제목(Galmuri 24px) · 보기 탭 세 개(시스템 카드·개발 기록·기록 편집) · 검색 입력과 찾기 · 미저장 초안 배지. 높이는 52px다.
- **부제:** 개발 현황의 부제 "목표부터 변경 내역과 검증 결과까지 확인합니다."는 머리 자리를 아끼려고 화면 낭독기용으로만 남겼다. 서버 운영·유저 관리는 탭과 검색이 없어 부제를 그대로 보인다. 제품에서 부제를 숨길지는 사용자 확인 때 함께 정한다.
- **미연결 의미:** "관리 기능 미연결 · 시스템 기록은 로컬 파일에서 읽습니다. 서버의 실시간 상태는 미연결입니다."를 상태 표시줄 왼쪽에 항상 보인다. 문장은 지금 App.tsx와 같다.
- **자료 기준:** 상태 표시줄 오른쪽에 "카드 자료 mock-2026-10-02-a · 문서 기준 333fe20 · 자동 갱신 안 됨 · 자세히"를 한 줄로 둔다. 자세히를 누르면 위로 펼쳐져 두 자료의 경로·버전·hash와 다시 읽기 버튼을 보인다. 읽는 중이거나 읽지 못한 자료는 버전 자리에 상태 글자를 둔다(4.2절 표).
- **위치 줄:** 본문 맨 위에 상자 없는 위치 줄(Management › 개발 현황 › …)을 둔다. "로컬 워크스페이스"는 사이드바 아래로 옮겼다.

### 2.2 1단 → 2단 → 구현 문서

| 단계 | 보이는 것 | 고르면 |
|---|---|---|
| 1단 전체 시스템 | 의뢰서 일곱 장: 엠블럼 64px, 이름, 한 줄 요약, 하위 상태 도장 집계(예: 코드 있음 11 · 미완료 1), "하위 N장 →". 여덟 번째 칸의 안내 쪽지에는 카드 수, 보는 법, 도장 범례가 있다. | 선택 전환(2.5절) 뒤 그 시스템의 2단으로 간다. |
| 2단 하위 시스템 | 색인 탭, 장부 머리 띠(엠블럼·이름·경로·전체 요약·하위 상태·↑ 전체 시스템, "세부" 접힘 안에 진입점과 기존 기록 ID 칩), 하위 의뢰서: 이름, 하위 ID, 요약, 큰 상태 도장, 상태 글자, 연결 수(코드 N곳 · 기존 ID N개), 문서 상태 | 그 하위 카드의 구현 문서로 간다. |
| 구현 문서 | 머리: 이동 꼬리표, 의뢰서 쪽지, 상위 › 하위 시스템, 제목, 짧은 설명, 상태·기준 commit·자동 갱신 안 됨. 본문은 제한 section과 흐름 diagram·대체 설명·원천 보기, 클릭 가능한 코드 매핑을 포함한다. 목업 표시는 실제 제품 자료의 실적과 구분한다. | 목차는 해당 절로 focus를 옮긴다. 기존 기록 칩은 기록 탭의 시스템으로, 코드 이름은 아래 읽기 전용 원문 보기로 간다. |

미구현·미연결 하위 카드도 문서에 도달한다. 그 문서는 현재 상태와 없는 코드를 먼저 설명하고, 코드가 없는 부분의 매핑은 비워 둔다. 가짜 경로는 만들지 않는다.

**도식:** flowchart·sequenceDiagram·stateDiagram-v2만 사용한다. 원천/title/한국어 description은 guide section에 있고 sourceCommit/sourceRefs를 상속한다. 현재 열린 문서의 블록을 순차 렌더하며 외부 요청·문서 설정/HTML/클릭/이미지/사용자 CSS·Markdown 문자열·수식은 허용하지 않는다. 구조/byte 오류와 개별 도식 문법/표시 실패를 분리한다. 로드 실패/무응답·잘못된 결과도 원천·대체 설명·실패 상태로 읽는다. 실제 자료의 모든 도식은 성공 렌더를 별도 전수 확인한다.

**코드 보기:** file 매핑은 파일, directory 매핑은 파일/하위 디렉터리 목록을 거쳐 연다. 원문은 매핑 SHA의 Git blob이며 경로·전체 기준 SHA·읽기 전용을 표시한다. 앱 checkout(현재 management-active)의 고정 HEAD 전체 SHA와 내용 같음/다름/파일 없음/비교 실패를 보여 주되 신구 판정은 하지 않고 작업 트리 미비교를 알린다. 256 KiB UTF-8 원문은 한 번 전달하고 UI만 200줄씩 표시한다. 총 줄 수·현재 구간·줄 번호·고정폭 글꼴·가로 스크롤을 제공한다. 디렉터리는 100개씩, 총 2,000개/원시 1 MiB 상한이다. 누락 SHA/파일·경로/종류·인코딩·크기·Git/timeout/busy·guide 충돌을 빈 화면으로 숨기지 않는다.

### 2.3 복귀와 focus

| 조작 | 결과 | focus |
|---|---|---|
| 카드·결과 선택 | 한 단계 들어간다. | 새 화면의 제목(1단은 이름판) |
| `Esc` 또는 "↑ 상위" 꼬리표 | 문서 → 2단 → 1단으로 한 단계 올라간다. 검색에서 들어왔으면 검색어를 유지한다. | 방금 나온 카드의 링크 |
| "← '검색어' 검색 결과로" | 검색 결과로 돌아간다. | 방금 열었던 결과 링크 |
| 목차 링크 | 같은 문서 안의 절로 스크롤한다. 기록은 늘지 않는다. | 해당 절 제목 |
| 코드 이름 / 디렉터리 항목 | 검증된 매핑 원문 / 하위 목록을 연다. | 코드 화면 제목 / 새 목록 제목 |
| 코드 보기의 문서로 돌아가기 / `Esc` | 원래 문서와 읽던 위치로 복귀한다. | 클릭했던 매핑 링크 |
| 도식의 문서로 돌아가기 | sandbox의 제한된 focus 반환 메시지를 보낸다. | 부모 문서의 해당 도식 제목 |
| `/` | 입력 중이 아닐 때 머리의 검색 입력으로 간다. 입력 칸 오른쪽에 `/` 키 표시가 있다. | 검색 입력 |
| 브라우저 뒤로 | 목업은 해시 주소라 같은 흐름이 된다. 제품 Electron 창에는 기본 뒤로가기 키가 없어 앱 안 버튼과 `Esc`를 주 경로로 둔다. | 위와 같음 |

`Esc`는 검색 입력에 글자가 있으면 입력 지우기에 쓰이고, 빈 입력에서만 상위 이동으로 동작한다.

### 2.4 검색

r1과 같다. 카드 이름, 하위 ID, 코드 경로와 역할, 기존 기록 ID, 문서 본문에서 공백으로 나눈 낱말을 모두 포함하는 항목을 찾고, 장부 페이지에 세 묶음으로 보인다. 결과 수는 `role="status"`로 읽어 주고, 결과가 없으면 찾은 범위·다른 낱말 예시·개발 기록 검색 링크·전체 시스템 버튼을 보인다.

### 2.5 선택 전환

의뢰서를 고르면 약 0.18초 동안 핀이 빠지며 카드가 10px 들리고 3% 커진다. 나머지 카드는 반쯤 흐려진 뒤 다음 화면이 페이지 넘김으로 들어온다. 문서에 들어가면 머리의 의뢰서 쪽지가 위에서 떨어지듯 0.22초 동안 자리 잡는다. 키보드 Enter도 같은 경로다. 보조 키를 누른 클릭과 동작 감소에서는 전환 없이 바로 이동한다.

### 2.6 개발 기록과 기록 편집

초기 보기인 SystemRecord와 DevelopmentRecord 모두 제목·분야/유형·상태 원문·짧은 summary를 먼저 보인다. summary는 1~2문장·160 Unicode code point다. 시스템의 responsibility/behavior·상세 상태, 기록의 reason/details/limitations/nextSteps·연결/근거는 항목 상세에 둔다. 시스템 카드에는 area와 implementationStatus, 기록 카드에는 type과 status 원문을 쓰며 임의 분류나 말줄임을 하지 않는다. 목업 대비 기록 카드에 summary를 추가하고 연결 시스템은 상세로 옮긴다.

새 항목/summary 변경에만 UI와 저장 경계의 빈 값·길이 검사를 적용한다. 기존 긴 요약은 정비 안내와 상세 원문을 보존하고 다른 필드 저장을 막지 않는다. MCP preview는 기존 UTF-16 단위 계약이며 UI summary 원본으로 사용하지 않는다. schemaVersion 1·기존 필드·원문·ID·MCP 5도구는 보존한다. JSON 도움말에 필드 역할을 설명하고 새 body 필드는 만들지 않는다.

미저장 초안 배지는 다른 메뉴에서도 보인다. 카드/탭/검색/다시 읽기가 초안을 지우지 않는다. 저장은 주 버튼, 검증은 보통 버튼, 초안 버리기는 위험 버튼이다. **디자인 재비평 N-01**에 따라 기록 읽기 실패·초안 없음에서는 마지막으로 읽은 기록이 있다고 안내하지 않는다.

### 2.7 서버 운영·유저 관리

사이드바 세 메뉴의 순서와 의미, 미수집 표시(—), 빈 로그·빈 유저 표, 비활성 서버 시작·종료 버튼을 그대로 둔다. 운영 수치나 성공 결과를 만들지 않는다. 네 번째 메뉴는 추가하지 않는다.

### 2.8 대표 도식의 시각 복잡도 관문

아래 수치는 Astra가 이번 관문용으로 정한 설계 기준이며 이미 통과한 측정값이 아니다. 실제 기준 commit에서 확인한 호출 흐름·패킷 흐름·상태 전이 각각 한 개를 사용하고, 같은 절의 한국어 설명과 함께 비교한다. 사실과 다른 축약은 하지 않고 범위를 나눴으면 연결 지점과 생략 범위를 명시한다.

| 대상 | 한 도식의 상한과 배치 |
|---|---|
| 호출 흐름 | 처리 노드 8개·연결 10개 이하. 시작→종료를 위→아래 또는 왼쪽→오른쪽 한 방향으로 읽고 필요한 되돌림은 이름을 붙임 |
| 패킷 순서 | 참여자 4개·메시지 8개 이하. 위→아래 시간 순서, 송수신 주체와 방향·패킷 이름을 명시 |
| 상태 전이 | 상태 6개·전이 8개 이하. 초기/종료와 전이 조건을 명시하고 중첩 상태는 별도 도식으로 분리 |

상한을 넘으면 기능/단계별로 분리한다. 단순히 글자를 줄여 한 장에 밀어 넣지 않는다. 겹친 노드/레이블·가려진 화살촉은 0건이어야 하며 흐름 선 교차는 1곳 이하로 제한하고 방향을 읽을 수 있어야 한다. 동기 호출/일반 흐름은 갈색 실선, 비동기 전달은 청록 파선, 오류 경로는 적갈색 점선과 관계 글자를 함께 써 색만으로 구분하지 않는다. 화살표와 레이블은 의미를 일관되게 유지한다.

본문 도식은 시스템 글꼴 최소 16 CSS px, 텍스트 대비 4.5:1·선/화살촉 대비 3:1을 목표로 확인한다. 장식·픽셀 글꼴·애니메이션은 쓰지 않는다. 라벨은 1~2줄의 짧은 설명을 우선하고 긴 코드명 원문은 아래 매핑과 연결한다. 125%의 CSS 1280×720 내용 영역에서 대표 도식 자체는 960×520 CSS px 안에 수평 스크롤 없이 읽히도록 배치하며 원천/대체 설명은 별도 펼침/문단에 둔다.

신규 Opus는 실제 Electron 창 크기/DIP/zoom과 캡처 원본을 확인하고 각 도식에서 시작/끝·주체·방향·분기/실패 조건을 읽어 글 설명과 대조한다. 내용 정확성, 위 시각 기준, 글 설명보다 관계를 찾기 쉬운지를 도식별 통과/보완으로 판정하고 구체적인 읽기 장애를 적는다. 캡처 3종과 판정 원문은 Astra를 거쳐 메인에 전달한다. 메인의 사용자 확인 전 전체 도식 작성은 금지한다. 브라우저 스크린샷만으로 이 관문을 통과 처리하지 않는다.

| 관문에서 복잡할 때 비교할 대안 | 이점 | 비용/한계 |
|---|---|---|
| 구조화 데이터 → 자체 SVG/CSS 컴포넌트 | 텍스트 원천·diff·읽기 MCP·향후 쓰기를 유지하며 표현을 좁게 제어 | 배치·분기·접근성·테마를 직접 유지하고 독립 검증 필요 |
| 도식별 손 CSS | 작은 고정 도식을 섬세하게 배치 | 자료/배치가 결합되고 수정·규모 증가·MCP 쓰기에서 재작성 부담; 구조화 원천과 내용 일치 검증 필요 |
| GPT-Image | 장식이나 개념 분위기를 빠르게 시각화 | 사실 라벨 오기·정확 수정·텍스트 diff/쓰기의 한계. 사실 흐름에는 부적합하고 장식에 한정하자는 메인 의견을 함께 제시 |

대안은 비교 후 메인에 올리며 임의 전환하지 않는다. Mermaid 제거와 lock 복구는 승인된 되돌리기 범위이나 실제로 수행했을 때만 기록한다.

### 3.6 움직임

화면 전환은 장부 층, 카드 반응은 게시판 층이 맡는다. 문서 본문 안에는 움직임이 없다. 모든 시간은 `--motion` 배수(1 또는 0)를 곱한다.

| 효과 | 층 | 시간·거리 | 곡선 | 동작 감소 |
|---|---|---|---|---|
| 화면 진입 (페이지 넘김) | 장부 | 200ms, 오른쪽에서 14px | ease-out | 0ms, 이동 0 |
| 카드 서기·들림 (hover·focus) | 게시판 | 120ms, 기울기 0과 3px | ease-out | 기울기만 0, 이동 0, 즉시 |
| 핀 흔들림 (hover) | 게시판 | 300ms, 1회 | `steps(3)` | 끔 |
| 선택 전환 (핀 빠짐·들림·나머지 흐림) | 게시판 | 180ms, 10px·3% | `cubic-bezier(.2,.8,.3,1)` | 전환 없이 바로 이동 |
| 의뢰서 쪽지 자리 잡기 (문서 진입) | 장부 | 220ms, 위에서 12px | ease-out | 끔 |
| 로딩 자리표시 깜빡임 | 게시판 | 1.2s 반복 | `steps(4)` | 끔 |
| 문서 안 스크롤 | 장부 | 부드러운 스크롤 | — | 즉시 이동 |

`prefers-reduced-motion: reduce`이면 `--motion`이 0이 되고 반복·장식 효과는 꺼진다. 카드의 정지 기울기는 움직임이 아니라 그대로 둔다. 무한 반복 장식은 로딩 자리표시 하나뿐이다.

## 4. 상태 표시

### 4.1 구현 상태

도장 그림은 장식(`aria-hidden`)이고, 같은 정보는 옆의 글자가 전한다. 색을 빼도 바깥 원과 안쪽 기호로 넷이 구분된다.

| 상태 | 글자 | 도장 그림 | 쓰는 경우 |
|---|---|---|---|
| `present` | 코드 있음 | 실선 이중 원 + 체크 | 기준 commit에 매핑한 코드가 있다. 기능 완성이나 검증 통과를 뜻하지 않는다. |
| `partial` | 일부만 있음 | 실선 원 + 왼쪽 반 채움 | 일부 경로만 있다. 목업 자료에서는 범례에만 나온다. |
| `absent` | 미완료 | 파선 원 + 가운데 막대 | 설계·형식만 있고 구현이 없다. 예: 저장 경계. |
| `disconnected` | 미연결 | 점선 원 + 끊긴 사슬 고리 | 코드나 화면은 있으나 게임·서버와 연결되지 않았다. 예: DB 준비 도구, 서버 운영·유저 관리. |

1단 카드는 하위 상태를 도장과 수로 집계한다(예: 미완료 1, 미연결 1). 2단 카드는 큰 도장과 상태 글자를 둔다. 주의 카드에 따로 표식을 달지 않는다.

- r1의 점선 안쪽 테두리는 깨진 focus처럼 읽혀 없앴다.
- r2의 노란 느낌표도 뺐다. 줄 사이 틈에 떠서 위 카드의 표식처럼 보였고, 게임에서는 "새 의뢰"로도 읽힌다. 같은 정보는 도장 글자가 이미 전한다. 안내 쪽지에 범례를 더하면 1280×720 첫 화면 세로 예산도 줄어든다.
- 기존 ID 연결 실패와 코드 매핑 기준 불일치는 2단 카드의 붉은 알약 글자와 문서 머리 경고로 보인다. 하위가 모두 "코드 있음"이면서 연결만 실패한 경우를 1단에 따로 셀지는 구현 전에 정한다.

### 4.2 자료 상태와 실패

r1과 같은 계약에 상태 표시줄 규칙을 더했다. 읽는 중이거나 읽지 못한 자료의 버전·기준일·hash·문서 기준 commit을 보이면 그 자료를 읽은 것처럼 보인다. 그래서 그런 자료에는 상태 글자·경로·다시 읽기만 두고, 정상으로 읽은 다른 자료는 어디에 쓰이는지 밝힌다.

| 상태 | 상태 표시줄 오른쪽 | 자세히: 시스템 카드 자료 | 자세히: 개발 기록 자료 | 다시 읽기 | 보기 탭 수 |
|---|---|---|---|---|---|
| 정상, 기존 ID 연결 실패, 매핑 기준 불일치 | 카드 자료 버전 · 문서 기준 commit · 자동 갱신 안 됨 | 경로·버전·기준일·hash | 경로·revision·asOf·sourceCommit | 카드 자료 | 7·39 / 18 |
| 카드 자료 읽는 중 | "카드 자료 읽는 중" · 자동 갱신 안 됨 | "읽는 중" · 경로 | "정상으로 읽음 · 개발 기록 탭과 기록 편집에만 쓰며 카드 자료와 별개" + 경로·revision | 없음 | 읽는 중 / 18 |
| 카드 자료 읽기 실패·검증 실패·크기 초과 | "카드 자료 읽기 실패"(또는 검증 실패·크기 초과) · 자동 갱신 안 됨 | 상태 글자 · 경로 | 위와 같음 | 카드 자료 | 상태 글자 / 18 |
| 개발 기록 읽기 실패 | 카드 자료 버전 · 문서 기준 commit · "개발 기록 읽기 실패" · 자동 갱신 안 됨 | "정상으로 읽음 · 시스템 카드와 구현 문서의 기준" + 경로·버전·기준일·hash | "읽기 실패" · 경로 | 카드 자료, 개발 기록 | 7·39 / 읽기 실패 |

- 상태 글자는 낱말로 뜻을 전하고 색(상태 표시줄 `--status-alert`, 자세히의 빨간 글자)은 보조다. 읽는 중은 보조 글자색이다.
- 560px 이하에서는 상태 표시줄 오른쪽에 첫 항목(카드 자료 버전 또는 카드 자료 상태)과 실패 항목, 자세히만 남는다(5절).
- 1280 폭에서 개발 기록 읽기 실패 요약은 상태 표시줄을 두 줄로 늘린다. 1단 일곱 장은 그대로 첫 화면에 보인다.

| 상태 | 표시 | 기존 기능 영향 |
|---|---|---|
| 카드 자료 읽는 중 | 게시판에 빈 종이 일곱 장, 안내 쪽지 자리에 "자료 하나를 끝까지 읽고 검증한 뒤에만 표시합니다"(`role="status"`), `aria-busy` | 없음 |

### 4.3 기준 commit과 자동 갱신

- 문서마다 기준 commit 7자리와 "전체 SHA 보기"를 둔다. 펼치면 40자리 SHA를 선택해 복사할 수 있다.
- 문서 머리는 "자동 갱신 안 됨"과 문서 기준 SHA를 보인다. 문서 본문을 현재 코드와 자동 대조했다는 뜻은 아니다. 코드 보기 화면에서만 요청 시 고정한 앱 checkout HEAD 전체 SHA와 blob 내용 비교를 명시하며 신구 판정·미커밋 작업 트리 비교와 구분한다.
- 상태 표시줄의 자료 기준은 카드 자료와 개발 기록 자료의 경로·버전·기준일·hash를 따로 적는다. 두 자료를 하나의 snapshot으로 보이지 않게 한다. 읽지 못한 자료는 4.2절 표처럼 버전 대신 상태만 적는다.

## 5. 접근성과 반응형

창 내용 1600×900 DIP·125%를 첫 값으로 쓰며 75·100·125·150·175·200%와 Ctrl +/-/0(125%)을 제공한다. 마지막 정상 외곽 bounds/최대화/배율은 checkout의 `frontend/.verification/desktop-profile/window-preferences.json`에 저장한다. 잘못된 값은 기본값, 화면 밖이면 주 모니터, 겹치면 가장 많이 겹치는 작업 영역 안으로 보정한다. 작은 화면에서는 무스크롤 7장 조건보다 내용 접근을 우선한다.

main의 저장 작업은 변경 뒤 500ms debounce·직렬 마지막 값·임시 파일 교체를 소유한다. X 숨김은 기다리지 않으며 명시 종료는 대기값을 버리지 않고 즉시 저장을 시작해 최대 500ms 기회를 준다. 실패 이유와 마지막 정상 값은 보존한다. 살아 있는 창의 저장 실패는 즉시 비차단 안내하되 연속 실패 중 한 번만 보이고 저장 성공 때 안내 상태를 초기화한다. 명시 종료의 저장 실패나 500ms 초과는 다음 실행에 한 번 안내한 뒤 기록을 지운다. 이는 메인 `msg_f85b875114b7`의 Q-01 해석 정정이다. 전역 설정과 트레이 수명은 바꾸지 않는다. 독립 검증은 저장 중 숨김/종료·연속 변경·깨진 설정·모니터 축소·실제 125%의 그림/폰트 외곽선을 포함하며 보조 모니터 미실행은 분리한다.

- **의미 구조:** 카드는 `article` 안 제목 링크 하나를 카드 전체로 늘린다. 1단 이름판은 실제 `h3` 화면 제목이다. 안내 쪽지는 카드 목록(`ul`) 밖의 `aside`라 "상위 시스템 7개" 목록에 섞이지 않는다. 배치는 CSS subgrid로 여덟 번째 칸에 둔다.
- **장식:** 엠블럼·도장 그림·핀·못·사이드바 머리 그림은 모두 `aria-hidden`이다. 상태는 글자, 하위 상태는 "하위 상태:" 숨김 머리말과 글자로 읽힌다.
- **키보드:** 모든 탐색이 링크·버튼이다. 화면이 바뀌면 제목으로 focus를 옮기고, 올라오면 직전 카드로 돌려준다. 앱 맨 앞에 "본문으로 건너뛰기"가 있다. 탐색 단축키는 `/` 검색과 `Esc` 상위, 창 배율은 Ctrl +/-/0이다. 검색 입력에 `aria-keyshortcuts="/"`가 있다.
- **focus 고리:** 밝은 면은 파랑 3px, 나무·상태 표시줄 위는 노랑 3px이다. 의뢰서는 기울기를 펴고 진갈색 3px + 밝은 크림 3px 이중 고리를 그린다. 종이와 코르크 양쪽에서 3:1을 넘는다.
- **읽어 주기:** 검색 결과 수, 기록 결과 수, 편집 알림, 로딩 안내는 `role="status"`, 편집 오류는 `role="alert"`다.
- **한국어 줄바꿈:** 앱 전체에 `word-break: keep-all`과 `overflow-wrap: anywhere`를 준다. 경로는 `/` 뒤에 줄바꿈 기회를 넣는다. 말줄임으로 자르지 않는다.
- **폭 단계:** 창 폭이 아니라 앱 컨테이너 폭으로 판단한다(`@container`).

## 8. 글꼴·그림·의존성

### 8.1 제목 글꼴 Galmuri

- Astra가 공식 Galmuri v2.40.4 배포의 `Galmuri11-Bold.woff2`(166,632 B) 하나를 받아 목업 안 data URI로 넣었다. 출처·고정 commit·SHA-256·OFL-1.1 전문은 목업의 `galmuri-license` 블록, [assets/fonts/](assets/fonts/), [자산 명세](asset-spec.md) 4절에 있다.
- 목업의 출처·라이선스 창에서 메타데이터와 라이선스 전문을 펼쳐 볼 수 있다.
- 제품 도입이 승인됐다. 같은 WOFF2를 파일 번들하고 `font-src 'self'`, OFL-1.1 전문·저작권 표시를 동봉한다. SHA-256은 `8643094f395aa2dbad6bc4385cc043314801eaec2e759d549435ec8ac4f2d078`다. 제목 font 토큰으로 사용하며 125% 실제 렌더는 별도 확인한다.

### 8.2 생성 그림

- Astra가 Codex 내장 이미지 생성으로 14종을 만들고 Node 내장 기능으로 최종 크기·팔레트·알파를 가공했다. 목록·예산·prompt·hash는 [자산 명세](asset-spec.md)와 [generation-manifest.json](assets/generation-manifest.json)에 있다.
- 목업에는 최종 PNG 13,586 B만 data URI로 들어갔다. 원본은 넣지 않았다. 실제 게임 아트를 흉내 내는 prompt는 쓰지 않았고, 그림 안에 글자를 넣지 않았다.
- 그림이 없을 때도 화면이 무너지지 않는다. 엠블럼과 도장은 r1 픽셀 SVG로, 질감은 같은 계열 단색으로, 머리 그림은 작은 D 표식으로 대신한다.
- 직접 그린 것은 r1의 픽셀 SVG(사이드바 메뉴 아이콘, 핀, 못)뿐이다. r2에서 새 장식 그림을 SVG로 그리지 않았다.

### 8.3 의존성

목업은 외부 요청이 없다. 제품 도입 명령은 frontend에서 `npm install --save-exact --ignore-scripts mermaid@12.0.0`이며 다른 버전·CDN·CLI·서버·구문 강조 패키지를 추가하지 않는다. 설치/실행 결과는 goal과 원시 근거에만 기록한다. lock 기준 하위 의존성/라이선스 목록과 기존 Electron 실행파일 보존을 확인하고, 번들 byte·첫 렌더 시간은 실제 생성 뒤 보고한다. 배포 원본 unpacked size를 앱 bundle 크기로 대신하지 않는다.

후속 결정 `msg_d442a1ace671`은 허용 목록에 Unlicense를 더했다. 허용 라이선스는 MIT, BSD-2-Clause, BSD-3-Clause, Apache-2.0, ISC, 0BSD, CC0-1.0, Unlicense와 폰트의 OFL-1.1이다. DOMPurify는 Apache-2.0 선택을 기록하고 원래 고지 문구는 보존한다. khroma는 동봉 MIT 원문을 근거로 기록한다. elkjs의 EPL-2.0은 설치만 허용하며 제품 산출물에서 배제하는 조건이다. 그 밖이나 누락/미확인 한 건이라도 있으면 번들·commit 전에 메인 판단을 받는다.

**공개 저장소 조건:** Mermaid 버전은 12.0.0을 유지하고 `overrides`로 lodash-es 4.18.1을 고정한다. 최초 지정 4.18.0의 deprecated 빌드 결함 때문에 메인 `msg_a7ffb3ccb82e`가 버전을 조정했다. `--save-exact --ignore-scripts` 설치 후 `npm ls lodash-es`의 단일 4.18.1 해소, audit의 lodash 계열 권고 해소와 실제 렌더의 파서·배치 경로를 확인한다. 입력은 package exports의 `mermaid.core.mjs` ESM 원천이고 Vite가 빌드 때 자체 classic/IIFE를 만든다(`msg_a1146ac1df16`). 배포된 mermaid.min.js/mermaid.esm.mjs를 복사해 쓰지 않는다. elkjs import는 빈 대체 모듈로 연결하고 elk 레이아웃은 사용하지 않는다. 최종 import graph와 산출물 모두에서 EPL 코드 제외와 lodash-es 4.18.1 포함을 확인한다. 가능하면 template의 importsKeys 검사 코드도 대조하되 tree-shaking에 따른 미포함과 버전 증거를 구분한다. 단순 문자열 검색만으로 완전한 배제를 주장하지 않는다. 설치 중 새 경고나 이상이 나오면 다시 번들을 보류하고 원문으로 보고한다.

생성 번들은 Git 제외 dist에만 둔다. public/src 등 추적 경로로 제3자 코드·minified 산출물을 복사하지 않았는지 commit 전 diff로 검사한다. 최종 포함 패키지의 복합 라이선스·원래 저작권 고지, Galmuri OFL-1.1, 생성 픽셀 그림 출처를 `05_Management/THIRD_PARTY_NOTICES.md`에 모은다. 이 경로는 같은 폴더의 README/MCP 등 안내 문서 관례를 따른다. 실제 포함 목록과 고지 작성은 빌드 근거 확인 뒤 진행하며 완료를 미리 주장하지 않는다.

**격리/CSP:** 고정 로컬 `diagram-renderer.html` + 단일 classic/IIFE bundle, `sandbox="allow-scripts"`로 표시까지 자식 안에 둔다. allow-same-origin·preload·팝업·상위 탐색·다운로드 권한을 주지 않는다. 초기 opaque file 자식의 JS/CSS 차단 뒤 메인 `msg_b67b1860b10c`가 전달한 사용자 승인에 따라 부모 file index/IPC는 유지하고 도식 전용 `dh-diagram://renderer/`에서 HTML·IIFE·CSS 정확한 3파일만 GET으로 제공한다. app ready 전에 standard/secure만 등록하며 bypassCSP·supportFetchAPI·ServiceWorker·corsEnabled 등의 추가 특권을 사용하지 않는다.

메인 `msg_f9952b4413ea`가 전달한 사용자 승인으로 URL 조건을 다음과 같이 확정했다. Chromium 정규화 뒤 **handler가 실제로 받은 URL이 고정 주소 3개와 문자열로 정확히 같을 때만 허용**한다. 원래 표기의 port·userinfo·dot-segment·host 대소문자 변형을 모두 거부한다는 보장은 두지 않는다. **응답 파일은 고정 표에서만 선택하며 URL의 경로·쿼리 등으로 filesystem 경로를 만들지 않는다.** GET 외는 405, 고정 주소 3개 외는 404를 반환하고 MIME/nosniff·파일 부재/읽기 오류를 명시한다. 자산을 늘릴 때도 고정 표 선택과 URL로 파일 경로를 만들지 않는 조건을 유지한다. 근거는 로컬 [독립 판정 O-02](../../../.backups/verification/2026-10-03-system-cards-resume/asset-review/verdict.md)와 [실제 renderer 경계 행렬](../../../.backups/verification/2026-10-03-system-cards-resume/asset-review/runtime/boundaries/renderer-frame-matrix.json)이다.

부모 frame-src에는 이 고정 origin만 추가하고 Electron은 정확한 최초 renderer URL만 허용하며 이후 탐색/redirect/새 창은 거부한다. 쿼리·fragment·인코딩·다른 파일명·file 주소의 이동 단계 차단과 handler 수신 단계 판정을 구분한다. main IPC의 senderFrame === mainFrame 검사는 유지한다. 자식은 default/connect/img/frame/object/base/form none, script와 외부 style은 해당 고정 로컬 자산만 허용하고 기존 도식용 unsafe-inline style 및 시스템 글꼴을 유지한다. 부모 inline style·unsafe-eval은 허용하지 않고 webSecurity를 끄지 않는다. URL 조건 정정은 CSP나 scheme 특권 확대 승인이 아니다. 실제 125% 3종 통합과 거부 경로는 신규 Sol 실행 후 신규 Opus가 독립 확인한다.

고정 표 선택·URL로 경로를 만들지 않는 성질은 자동 테스트로 고정한다. Electron 버전을 바꾸면 실제 net.fetch/iframe 경계 행렬 하네스도 다시 실행한다. 정규화 변화로 수신 URL이 고정 주소에서 벗어나면 정확 비교에서 거부하며, 정규화 동작만으로 고정 표 밖의 파일 접근이 허용되지 않는다.

**렌더 수명:** 부모는 원천/제목/설명·요청 ID·인스턴스 토큰을 보내고 자식은 숨긴 영역에서 렌더한 SVG(최대 256 KiB)를 반환한다. 부모의 형식/참조/byte 검사 후 렌더 승인 ACK를 보내면 자식이 표시하고 표시 완료 ACK를 회신한다. 부모가 후자 ACK를 받은 시점이 로드 시작 후 5초 제한의 종점이다. source WindowProxy·세대·토큰·스키마를 함께 확인하며 opaque null origin이나 targetOrigin '*'만으로 신뢰하지 않는다. SVG는 부모 DOM에 넣지 않는다.

로드 오류·무응답·ACK 실패는 원천/대체 설명으로 표시하고 iframe·요청·타이머·리스너를 정리한다. 렌더 문서 자체가 열리지 않으면 같은 세대 나머지 블록은 기다리지 않고 즉시 실패로 표시한다. 개별 블록 실패는 다음 블록으로 진행한다. 전환/취소/종료의 늦은 결과는 폐기한다. iframe 높이는 120~720 CSS px 안에서만 반영하고 내부 스크롤·명시적 문서 focus 반환만 제공한다. 같은 프로세스의 동기 CPU 강제 중단은 보장하지 않으며 실제 통합에서 검증한다.

**입력/조회:** strict·htmlLabels false·startOnLoad false, 허용 3종만 사용한다. source UTF-8 4 KiB·description 2 KiB·section당 1개·guide 2 MiB·MCP 직렬화 응답 16 KiB를 검사한다. 구조/자료형/byte 오류는 guide 오류, 금지 DSL/문법/렌더 실패는 해당 블록 표시 실패다. title/description과 source는 일반 텍스트로 안전하게 보여 준다. 외부 참조·이벤트·foreignObject를 성공 SVG로 허용하지 않는다.

첫 통합은 세 도식·로컬 로드·부모 DOM/IPC 접근 거부·잘못된 메시지·로드 실패/무응답/문서 전환을 확인한다. 성립하지 않으면 다른 CSP 방식으로 임의 전환하지 않고 메인에 올린다. 단위/통합 시험과 신규 Opus 시각 비평은 별개로 수행한다.

## 9. 목업 사용법과 한계

- 파일 하나를 브라우저로 열면 된다. 외부 요청은 문서 머리의 CSP가 막는다(`connect-src 'none'`, `img-src data:`, `font-src data:`). 링크는 누를 때만 열린다. 파일 크기는 약 430 KB이며 대부분 글꼴 data URI다.
- 위쪽 회색 막대는 목업 제어용이다. 층 경계 표시, 자료 상태 8종, 긴 글·긴 경로, 창 폭(1280×720·760·420·브라우저 폭), 동작 감소, 바로 가기, 출처·라이선스 창이 있다.
- 주소 뒤에 `?frame=760&state=guide-fail&motion=reduce&stress=1&dirty=1&layers=1`처럼 붙이면 같은 상태로 바로 열린다. 창 폭과 동작 선택은 브라우저 저장소의 `m2-mockup-hybrid`에 남는다.
- 본문이 있는 대표 문서는 9개다: `server.session`, `client.network`, `client-net.session`, `shared.protocol`, `tools.bot`, `management.mcp`, `automation.ci`, 미완료 예시 `server.persistence`, 미연결 예시 `management.operations`. 나머지 30개는 요약·매핑·기존 ID와 "본문 생략" 표시만 있다.
- 개발 기록 탭은 catalog의 시스템 18개·기록 18개 제목과 상태만 옮겼다. 기록 편집의 저장은 흉내만 낸다.
- 1280×720 기본 자료에서는 상위 일곱 장과 안내 쪽지가 스크롤 없이 첫 화면에 온전히 보인다. "긴 글·긴 경로"를 켜면 긴 서버 제목이 첫 줄 카드 높이를 늘려, 첫 줄 네 장만 온전히 보이고 둘째 줄 세 장은 아래 끝이 잘려 스크롤이 필요하다. 실제 제목 길이의 상한은 구현 전에 정한다.
- 2단 첫 화면에는 하위 카드 첫 줄 네 장이 온전히 보인다.
- 작성자 자기 점검은 헤드리스 Chrome에서 했다. Electron 실행, 실제 데이터 파일, MCP, 화면 낭독기, 다른 OS 글꼴은 실행하지 않았다.
