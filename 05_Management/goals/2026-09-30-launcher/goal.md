# Management 실행 배치 목표

> 아래 정본·작업 경로와 권한은 이 목표 수행 당시의 기록이다. 현재 Management 정본 경로는 [README](../../README.md)를 따른다. 과거 실행 경로·결과는 소급 변경하지 않는다.

## 목표와 범위

사용자의 “실제로 띄워 보여줘 + 종종 확인할 실행용 배치” 요청에 따라 정본 `C:/Dev/DawnHolder_Project/05_Management/Start-Management.bat`와 README 실행 안내를 만든다. 추가 요청인 다음 실행의 기본 창 `1280×720`은 별도 구현 작업자가 main의 두 크기 값만 수정한다. 이 문서가 범위·상태·결과의 원본이다.

구현 지정 `gpt-6.1-sol`, 독립 검증 지정 `gpt-6-astra`, 확인된 실제 모델은 각각 `unknown`이다. 구현자는 배치/문서만 작성하며 테스트는 독립 검증자가 맡는다. 추가 위임하지 않는다.

## 완료조건

1. ASCII/CRLF 배치가 호출 위치와 경로 공백에 관계없이 `%~dp0frontend`로 이동한다.
2. Node/npm/로컬 의존성/Electron 바이너리가 없으면 자동 설치·네트워크 다운로드 없이 오류 안내·pause·nonzero 종료한다.
3. `call npm.cmd run desktop:build`가 성공한 경우에만 로컬 Electron EXE로 현재 frontend를 `start ""`로 연다. 실패하면 이전 산출물을 실행하지 않고 오류·pause·nonzero 종료한다.
4. 성공하면 더블클릭으로 열린 콘솔은 종료되고 앱은 독립 실행된다. 이미 열린 앱과 별도 창이 중복 실행될 수 있음을 안내한다. single-instance 기능은 추가하지 않는다.
5. 독립 검증자가 정상/누락/빌드 실패·경로 계약을 확인하고, 사용자 앱/기존 프로세스는 건드리지 않는다.
6. 기본 창 외곽 크기는 `1280×720`으로 다음 실행부터 적용한다. 현재 사용자 창 PID `12744`는 변경하거나 종료하지 않는다.

## 권한과 제외 범위

`05_Management/**`만 수정하고 브랜치 전환·커밋·푸시·공통 문서/CURRENT 변경은 수행하지 않는다. 새 의존성·WSL/백엔드/게임서버·자동시작·보안설정·Electron single-instance 변경은 없다. main의 width/height 두 값은 별도 작업자 소유이며 이 배치 작업자는 수정하지 않는다. 사용자가 보고 있는 앱 PID `12744`를 종료하지 않는다. 배치 작업자는 배치를 실제 실행하지 않는다.

## 현재 상태

당시에는 배치·실행 안내·기본 창 크기 설정의 구현과 독립 분기/계약 검증을 완료했다. 실제 배치 detached 기동과 새 1280×720 창 관찰은 미실행이었고 로컬 미커밋 상태였다.

후속 [system-records 목표](../2026-09-30-system-records/goal.md#현재-상태)에서 PR147 병합과 실제 Electron main의 1280×720 창 관찰을 기록했다. **실제 배치 더블클릭·START detached 실행의 끝까지 이어지는 성공은 여전히 미검증**이다. 배치 구현·분기 검증 완료와 완료조건 4의 사용자 진입점 검증 완료를 구분한다. 저장소 [dotnet-tests CI](../../../.github/workflows/dotnet-tests.yml)는 05 npm test/build를 실행하지 않으므로 그 공백을 채우지 않는다.

## 결과와 미실행

- 배치 구현자는 ASCII-only/CRLF와 분기 흐름을 정적으로 점검했으며 배치/빌드/새 앱을 실행하지 않았다.
- [독립 보고](verification.md): 실제 cmd의 공백 경로/무관한 cwd·정상/누락/빌드 실패/실행 요청 실패 등 배치 12분기, 기본 외곽 1280×720 설정을 포함한 main 7계약, strict 테스트 타입검사·최종 desktop build 통과. START는 기록용 stub으로 검증했으므로 실제 detached 앱 실행 성공을 주장하지 않는다. 임시 fixture 잔존 0.
- 사용자 앱 PID `12744`는 이 작업에서 조작하지 않았다. 메인의 최초 직접 기동은 기존 1040 창이었으며 다음 실행 크기/배치 결과와 구분한다. 현재 앱 생존 여부를 확약하지 않는다. 이 목표 당시 실제 배치 더블클릭·새 1280×720 창 확인은 미실행이었다. 이후 창 관찰은 위 후속 목표에 별도로 기록하며 배치 경로 실행으로 소급하지 않는다.
