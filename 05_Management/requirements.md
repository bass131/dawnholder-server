# Management 요구사항

2026-09-30 사용자 합의와 2026-10-02·2026-10-06 메인이 전달한 후속 승인 기준. **확정**은 사용자 요구/선택과 승인된 구체화, **제안**은 설계 후보, **미결정**은 추가 합의 대상이다. 아래 향후 완료조건은 실제 구현·검증 실적이 아니다. 각 구현 작업의 범위·상태·결과는 [README](README.md)가 연결하는 목표 문서에만 둔다. R-12~17의 최신 승인 출처와 기술 한도는 [시스템 카드 goal](goals/2026-10-02-system-cards/goal.md#구현-승인과-도식-시각-복잡도-관문--2026-10-02)에, R-18·R-19의 출처는 [기록 원본 일원화 goal](goals/2026-10-06-record-source-unification/goal.md#적용-중인-사용자-결정)에 있다.

## R-01

- **확정:** 우선순위는 라이브 서버 운영 → 유저/GM 관리와 이상행동 근거 기반 → 개발 현황과 사람·에이전트 공통 근거다.
- **후속 작업 순서와 구분:** 위는 장기 제품 우선순위다. PR147 이후의 제한된 후속은 처음에 개발 기록 공동 조회 → 서버 등록·로그 조회로 합의했다([공동 합의](goals/2026-09-30-system-records/shared-read-agreements.md#순서와-첫-범위)). 실제 진행은 공동 조회 MCP(PR159) → 개발 현황 시스템 카드(PR179) → 개발 기록 탐색(PR189) → 기록 원본 일원화(진행 중)였다. 서버 등록·로그와 서버 운영 시각화는 DB 연동 뒤 후보로 남았다([BACKLOG `server-operations-view`](../00_Document/operations/BACKLOG.md)). 이 정정은 실제 기록을 적은 것이며 위 장기 우선순위를 바꾸지 않는다. 우선순위 재논의를 올린다는 전달만으로 기존 합의가 취소된 것으로 보지 않는다.
- **향후 완료조건:** 각 영역의 정보 출처·갱신 시점·관찰 범위를 확인할 수 있다. 개발 보고를 실시간 운영 상태로 오인하지 않는다.

## R-02

- **확정:** 현재 개발 PC의 단일 라이브 서버를 관리한다. 게임 접속의 외부 제공과 별개로 관리 UI/관리 API는 외부와 LAN에서 접근할 수 없어야 한다. 브라우저보다 Windows 독립 실행 앱/창을 원한다.
- **확정된 장기 방향:** 같은 PC의 Docker 다중 서버와 마스터 조정 구조를 원한다. 현재 분산처리·컨테이너 도입을 확정한 것은 아니다.
- **미결정:** 관리 인증 방식, Windows 창과 WSL 사이의 통신/접근 경계, Docker·마스터 전환 시점.
- **향후 완료조건:** 허용된 로컬 경로에서만 관리 기능에 접근하고 외부/LAN 접근은 실패한다. 현재 게임 접속 계약은 별도로 보존한다.

## R-03

- **확정:** 화면은 React + TypeScript + Vite, Windows 독립 창은 Electron, WSL 관리백엔드는 C# ASP.NET Core를 채택한다. 게임서버 실행 환경도 WSL이다. 기술 채택과 실제 구현·실행 실적은 구분한다.
- **현재 PC 정책(메인 전달):** 사용자가 이 PC의 SAC를 직접 껐고 메인이 확인했으며, 2026-10-04 22:39 KST부터 Off다. 이 빌드에서는 재활성화가 가능하다는 전달 사실이며 OS 설정의 독립 관측·변경 실적이 아니다. 서버·테스트의 WSL 표준은 유지한다. 출처와 과거 On 관찰은 [조사 관찰과 미실행](#조사-관찰과-미실행)에 구분한다.
- **확정된 비용 선호:** 서명은 최대한 비용 없이 진행하기를 원한다. 무료 공개신뢰 서명이 확보되었다는 의미는 아니다.
- **미결정:** 코드서명 방식/가입 가능 여부. 사용자는 개인 개발자이며 법적 소재지는 별도 확인하지 않았다. Electron 개발 실행 결과는 해당 목표에 기록하고 배포 EXE/설치프로그램의 SAC 실행과 구분한다.
- **목표별 완료조건:** [초기화 목표](goals/2026-09-30-foundation/goal.md#관찰-가능한-완료조건)는 strict TS·로컬 화면 기반, [데스크톱 창 목표](goals/2026-09-30-desktop-shell/goal.md)는 기존 화면의 Electron 개발 실행 가능성 확인에 한정한다. 실제 관리백엔드 연동은 후속 목표다.

## R-04

- **확정:** 관리창을 닫아도 서버 운영·자동복구·예약 동작이 지속되고, 다시 열면 상태와 이력을 볼 수 있어야 한다. 창 X 닫기는 트레이에 남아 장애 알림을 유지하는 방향을 선택했다. 조치가 필요한 실패는 Windows 알림을 원한다.
- **제안:** 화면과 별도 수명을 가진 운영 담당 프로세스, 로그인 시 관리백엔드 자동시작.
- **미결정:** 도구 완전종료 후 알림 필요 여부, 백엔드 자동시작 시점/방식. 이번 데스크톱 셸은 X=숨김/트레이 유지, 메뉴 열기=복원, 명시 종료=이 앱만 종료로 한정하고 실제 장애/OS 알림은 백엔드 연결 뒤 구현한다.
- **향후 완료조건:** 창 닫기/재열기 동안 예약·복구가 보존되고 이력이 이어진다. 알림 대상 실패와 전달 경로를 검증한다.

## R-05

- **확정:** 운영 중 비정상 종료는 제한된 자동재시작으로 복구한다. 반복 실패 시 재시작을 중단하고 표시한다. 수동/점검 종료는 장애로 오인해 재시작하지 않는다. PC 재부팅 뒤 라이브 서버는 사용자가 수동 시작한다.
- **제안:** PC 재부팅 전에 만든 예약을 재부팅 후 '확인 필요'로 처리한다.
- **미결정:** 재시작 횟수·간격, 프로세스 생존 중 응답없음 감지/자동복구, 재부팅 후 예약 처리의 최종 정책.
- **향후 완료조건:** 정상·수동·점검·비정상 종료가 구분되고 한도 초과 시 중단/실패 이력이 남는다. PC 재부팅으로 라이브가 자동 시작되지 않는다.

## R-06

- **확정:** 예정 종료를 안내하고 신규 접속을 차단한다. 정해진 시각에 플레이/상태 변경을 중단한 뒤 모든 유저의 미저장 변동사항 저장완료를 기다려 셧다운한다. 저장미완료/실패가 남으면 자동 강제종료하지 않는다. 재시작 예약은 정상 종료완료 뒤 실행한다.
- **공학 조건:** 게임 틱은 DB I/O 완료를 기다리지 않는다. 종료조정자가 비동기 저장완료/실패 신호를 기다리는 경계를 마련해야 한다.
- **선행 의존성:** GameServer 영속저장은 아직 미구현이다. DB schema/접속 확인은 게임 상태 저장 연동 완료를 뜻하지 않는다.
- **미결정:** 안내 시점/내용, 저장 실패 후 조치·재시도·운영자 확인, 정지 중 유저에게 보일 상태.
- **향후 완료조건:** 미저장 변경이 모두 저장된 근거가 있어야 종료된다. 저장 실패를 주입하면 자동 강제종료/예약 재시작이 실행되지 않고 실패를 표시한다.

## R-07

- **확정:** 개발 빌드와 라이브 배포 버전을 분리한다. 사용자 명시 적용 또는 예약으로 업데이트하며 장애복구는 현재 운영 버전을 사용한다.
- **미결정:** 새 버전 실패 시 rollback, 저장 데이터/프로토콜 호환 정책, 배포 검증과 버전 보존 방식.
- **향후 완료조건:** 개발 빌드만으로 라이브 버전이 바뀌지 않는다. 운영 버전과 배포/예약 이력, 장애복구에 쓰인 버전을 확인한다.

## R-08

- **확정:** 유저 GM/관리자 권한 부여·회수와 서버 운영제어가 모두 필요하다. 관리툴과 GM 계정의 게임 직접 접속·순간이동·관찰·운영명령을 원한다.
- **제안:** 게임 GM 권한과 관리도구 운영자 권한을 분리한다.
- **미결정:** 개별 명령, 권한 단계, 비노출 관전, 재화/아이템 변경, 제재 기능, 계정 인증과 권한 변경 감사 정책.
- **공학 조건:** 서버가 명령·대상·현재 상태·소유권·권한 검증과 게임 상태 판정을 소유한다.
- **향후 완료조건:** 권한 부여/회수 후 허용·거부가 서버에서 일관되게 적용되고 수행자·대상·결과 근거를 확인한다. 명령별 완료조건은 목록 합의 후 정한다.

## R-09

- **확정:** 이상행동 대응은 이벤트와 증거를 남길 기반부터 마련한다.
- **미결정:** 실제 탐지 규칙, 자동제재, 수집 이벤트 범위, 보존기간·용량과 열람 권한.
- **향후 완료조건:** 사건의 발생 시점·대상·근거 이벤트를 추적할 수 있다. 탐지/제재 기능은 별도 합의 전 완료 기능으로 취급하지 않는다.

## R-10

- **확정:** 사람과 에이전트가 개발 상태와 근거를 공유한다. Management 상세 맥락은 `05_Management`에 두고 기존 Game Dev 메인과 의논한다.
- **제안:** 개발 목표·PR·CI·실행 결과의 원본 링크와 관찰 시점을 화면에서 연결한다.
- **2026-10-06 변경:** 기록의 원본은 프로젝트 문서 하나이며 `records/catalog.json`은 원문 링크와 색인으로 바뀐다([R-19](#r-19)). 아래 「후속 확정」과 「재개 범위」의 catalog 공동 원본 서술은 이 변경 전의 기준이다.
- **후속 확정(2026-10-06 변경 전):** 기존 `records/catalog.json` 파일을 공동 원본으로 유지하고 로컬 stdio MCP와 공통 조회 모듈부터 구현한다. 앱 종료와 독립적으로 사람과 에이전트가 같은 버전·시점의 자료를 읽으며 첫 범위는 읽기 전용이다. 다음 단계는 서버 등록·로그 조회다. [공동 조회 완료조건](goals/2026-09-30-system-records/shared-read-agreements.md#공동-조회-완료조건)을 따른다. 실제 진행 순서는 [R-01](#r-01)에 정정했다.
- **로그 후속 확정:** 기본 조회는 현재 운영 서버 최근 10분이며 일반 로그는 서버당 최대 7일·1GB 중 먼저 도달하는 한도로 정리한다. 별도 조사 근거는 일반 자동 정리에서 제외한다. 이는 R-09의 이상행동 이벤트 수집·보존 정책 전체를 확정한 것이 아니다. [서버 등록·로그 합의](goals/2026-09-30-system-records/shared-read-agreements.md#서버-등록로그-합의)에 경계가 있다.
- **재개 범위(2026-10-06 변경 전):** 2026-10-01 메인을 통해 전달된 사용자 결정에 따라 로컬 읽기 전용 MCP와 공통 조회 모듈의 착수 보류를 해제했다. 정본은 management-active 작업 트리의 `records/catalog.json`이며 미병합 편집도 같은 hash/revision 기준으로 조회한다. 승인·실행·검증 상태는 [공동 조회 goal](goals/2026-10-01-shared-read-mcp/goal.md)에 둔다. 실제 개발 세션 연결 설정은 별도 결정이며 서버 등록·로그 조회와 쓰기·실행 제어로 범위를 넓히지 않는다. 2026-10-06 사용자 결정으로 실제 개발 세션 연결은 이번 목표에서 하지 않고 다음 계획에서 정한다([R-19](#r-19)).
- **미결정:** 자동 수집·갱신 주기, 후속 쓰기·실행 제어와 에이전트 권한, 로그 등록/회전 세부 계약은 [남은 결정](goals/2026-09-30-system-records/shared-read-agreements.md#다음-결정)을 따른다. 라이브 조작권한을 에이전트에게 자동 부여하지 않는다.
- **향후 완료조건:** 같은 근거를 탐색할 수 있고, 검증된 범위와 미실행 범위를 구분한다. 전체 대화·일일 장부·중복 진행률을 새 원본으로 만들지 않는다.

## R-11

- **제안:** 테스트 서버는 독립 작업자가 화면 없이 자기 실행본만 관리하는 공통 기반에 연결한다. 현재 확정된 구현 범위는 아니다.
- **미결정:** 실행 공간·프로세스·포트 소유권, 테스트/라이브 분리와 에이전트 인증·권한.
- **향후 완료조건:** 채택할 경우 자기 실행본만 조작 가능하고 다른 작업자/라이브 실행본 접근은 거부되어야 한다.

## R-12

- **확정:** 시각 방향은 상점 장부 앱과 퀘스트 게시판 카드의 혼합안이다. 앱 전체는 밝은 장부 면과 호두나무 사이드바·상태 표시줄을 쓰고, 개발 현황의 상위/하위 시스템 카드는 코르크 게시판의 종이 의뢰서로 표시한다. 구현 문서·검색·기록·편집·운영 화면의 데이터 면은 평평하게 읽히도록 둔다. 상태는 색뿐 아니라 도장 모양과 글자로 구분한다.
- **보존 요구:** 영역 우선순위와 메뉴의 의미, 미연결 안내, 비활성 제어를 유지한다. 상태/로그 영역은 미연결을 표시하고 운영 수치·로그·성공 결과를 만들어 채우지 않는다.
- **설계 선택:** 승인된 PNG 14종과 Galmuri11 Bold를 로컬 파일로 번들한다. Galmuri는 제목 12/24 CSS px에 한정하고 본문은 Segoe UI·맑은 고딕을 쓴다. 실제 게임 아트·UI·폰트를 복사하지 않는다. 전환/반응은 `prefers-reduced-motion`에서 끈다. 출처·라이선스는 [D-09](decisions.md#d-09)와 [자산 명세](goals/2026-10-02-system-cards/asset-spec.md), 도식 라이브러리·격리/CSP는 R-14·D-11을 따른다. 제품 자산은 `font-src 'self'`·`assetsInlineLimit: 0`으로 파일 번들하고 `img-src 'self'`를 유지한다.
- **향후 완료조건:** 일반 자료를 CSS 내용 영역 1280×720에서 볼 때 상위 7장을 스크롤 없이 표시한다. 긴 글·작은 창에는 반응형과 스크롤을 허용하고 내용 접근을 보존한다. 실제 Electron 125%에서 64/32px 그림·글꼴·키보드·동작 감소·좁은 창·미연결/비활성 제어를 독립 검증한다. 외곽 창 크기와 CSS 내용 크기를 혼동하지 않는다.

## R-13

- **확정:** 작업 기록의 제목·요약·본문은 무엇을 했는지 풀어 쓴다. D1·D2·M-2 같은 프로젝트 코드로 작업 이름을 대신하지 않는다. 코드는 추적에 필요할 때만 이름 뒤에 보조 정보로 둔다. 예: D1b → 캐릭터 저장소와 격리 SQL 시험, M-2 → 개발 현황 시스템 카드. 요약도 짧은 완성된 한국어 문장으로 쓰며 단어 나열·임의 생략·마일스톤 코드만으로 작업을 대신하지 않는다. 제목·요약·본문 범위는 2026-10-02 메인 `msg_a107d44368a7`이 전한 결정이며, 완성 문장 구체화의 후속 승인 근거는 R-15 승인 문안이다.

- **향후 완료조건:** 검토자가 제목·요약·본문에서 코드만으로 작업을 식별해야 하는 경우가 없어야 한다. 독립 검증은 새로 쓰거나 바꾼 제목·요약·본문에 코드만 남은 작업 이름이 있는지 대조한다.

## R-14

- **확정:** 구현 설명에서 호출 순서·패킷 흐름·상태 전이를 설명하는 절은 텍스트 원천과 다이어그램을 함께 갖는다. 제한된 diagram 블록을 `system-guide.json` section에 저장해 diff와 읽기 MCP가 같은 원천을 보게 한다. Mermaid 12.0.0은 로컬 번들하며 외부 네트워크 없이 별도 sandbox 문서 안에서 렌더/표시한다. 장부 테마, 제목·한국어 대체 설명, 원천 펼쳐 보기/복사를 제공한다. 렌더 실패는 해당 블록의 상태·원천·대체 설명으로 드러내고 나머지 본문은 보존한다. 미구현 흐름을 실제 동작처럼 그리지 않는다.
- **경계:** 메인 style 제한은 유지하고 고정 로컬 renderer의 최초 frame 진입만 예외로 한다. 결과 검사→부모 승인 ACK→자식 표시 완료 ACK 순서를 사용하며 로드부터 부모가 표시 완료 ACK를 받을 때까지 5초다. 문서 자체 로드 실패는 같은 세대 나머지 블록도 즉시 실패로 표시한다. 소유자·정리·입력 한도·금지 구문은 goal의 승인 계약과 [명세](goals/2026-10-02-system-cards/design-spec.md)를 따른다.
- **로컬 자산 제공:** 2026-10-03 메인 `msg_b67b1860b10c`가 전달한 사용자 승인으로 도식 전용 `dh-diagram://renderer/`에 HTML·자체 IIFE·CSS 정확한 3파일 GET만 매핑한다. 후속 `msg_f9952b4413ea`의 사용자 승인에 따라 Chromium 정규화 뒤 handler가 실제 받은 URL이 고정 주소 3개와 문자열로 정확히 같을 때만 허용한다. 원래 port·userinfo·dot-segment·host 대소문자 표기의 전면 거부는 보장하지 않는다. 응답 파일은 고정 표에서만 고르며 URL 경로·쿼리로 파일 경로를 만들지 않는다. 비GET은 405, 고정 주소 외는 404이고 MIME/nosniff와 파일 읽기 실패를 명시한다. 부모 index/IPC·이동 단계 차단은 유지한다. standard/secure만 등록하고 추가 scheme 특권은 주지 않는다. 부모 frame-src와 자식 script/style의 외부 자원 주소는 이 고정 로컬 제공 범위에 한정한다. 기존 자식 도식 style 허용과 격리·메시지·ACK 수명은 보존하고 실제 통합/거부 경로는 신규 독립 검증으로 확인한다.
- **공개 저장소 조건:** Mermaid ESM core 원천을 Vite로 빌드해 Git 제외 dist에 자체 IIFE를 만들고 제3자 번들을 추적 경로로 복사하지 않는다. elkjs는 설치만 허용하고 alias로 EPL 코드를 산출물에서 배제한다. `overrides`의 lodash-es 4.18.1이 실제 번들되는지 확인한다. 최초 지정 4.18.0의 deprecated 빌드 결함 때문에 메인 `msg_a7ffb3ccb82e`가 4.18.1로 조정했다. import graph·산출물·audit·3종 렌더와 고지 파일을 검증한다. Unlicense 추가 허용, DOMPurify Apache-2.0 선택, khroma 동봉 MIT 채택은 후속 메인 결정이며 상세는 명세 8.3절을 따른다.
- **시각 복잡도 관문:** 실제 guide 내용의 호출·패킷·상태 대표 3종을 먼저 만든다. 신규 Opus가 125% Electron 캡처에서 글 설명보다 관계를 한눈에 읽는 데 도움이 되는지 비평하고, 메인이 사용자 확인을 받은 뒤에만 전체 도식을 작성한다. 복잡도가 오르면 구조화 데이터→자체 SVG/CSS, 도식별 손 CSS, GPT-Image를 비교해 메인에 올린다. 사실 흐름의 생성 이미지는 라벨·수정·diff 한계를 검토하며 승인 없이 정본으로 대체하지 않는다.
- **향후 완료조건:** 실제 흐름 설명 절의 도식 존재와 실제 작성된 모든 diagram의 Electron 정상 렌더를 전수 확인하고 소스 근거와 대조한다. 이와 별도로 세 종류 fixture, 실패/금지 구문/초과 입력, 로드 실패·무응답·늦은 응답·후속 블록, 오프라인/CSP/긴 한국어/키보드/대체 설명을 독립 검증한다. 원천과 MCP는 같은 snapshot/hash를 쓰고 2 MiB guide·16 KiB 응답 상한을 유지하며 조용히 자르지 않는다. MCP 쓰기는 후속 목표다.

## R-15

- **확정된 구체화:** 첫 장의 설명은 간략히 하고 본문에서 추가 설명을 보려는 사용자 요구를 개발 기록 탭의 시스템/개발 기록 양쪽 목록과 상세에 적용한다. 목록은 제목·기존 유형/분야·상태 원문·짧은 소개를 보여 주고 자세한 책임·동작·이유·검증 한계·연결은 상세에서 읽는다.
- **필드/저장:** 양쪽 `summary`는 1~2문장·공백 포함 160 Unicode code point다. 시스템의 responsibility/behavior, 개발 기록의 reason/details[]/limitations[]/nextSteps[]를 보존하며 새 body를 중복 생성하지 않는다. 새 항목 또는 summary를 바꾼 항목은 UI와 저장 경계에서 길이/빈 값 검사를 한다. 기존의 바뀌지 않은 긴 요약은 읽기/다른 필드 저장을 막지 않고 정비 안내와 상세 원문을 제공한다. 한국어 완성 문장은 내용 검토로 확인한다.
- **호환:** schemaVersion 1, 원문·ID·기존 MCP DTO/5도구·저장/초안/충돌/백업을 보존한다. MCP preview는 기존 UTF-16 code unit 기준 160과 truncatedFields를 유지하고 UI 소개를 그 잘린 preview로 만들지 않는다. 시스템 목록은 area·implementationStatus, 기록 목록은 type·status 원문을 쓰며 임의 분류/말줄임을 하지 않는다. 시스템 나머지 상태와 기록 연결 시스템은 상세에서 보존한다.
- **향후 완료조건:** 첫 화면의 설명 분량과 상세 원문 접근, 새/수정 요약 검증·기존 긴 요약 호환, 검색·복귀·focus·초안·저장·MCP를 독립 검증한다. 디자인 재비평 N-01(기록 실패·초안 없음의 마지막 기록 안내)도 해결한다. 타임라인·MCP 쓰기·기존 기록 일괄 재작성은 후속이다.
- **2026-10-06 변경:** 목록과 전체 페이지 상세의 분리는 [개발 기록 탐색 goal](goals/2026-10-05-development-record-navigation/goal.md)(PR189)로 구현됐다. [R-19](#r-19)의 색인 전환으로 `summary`와 상세 서술 필드가 빠지므로 160 code point 검사와 기존 긴 요약 호환 요구는 대상이 사라진다. 기록 편집·초안·저장도 없어진다. N-01의 처리 근거는 확인하지 못했으며 색인 전환 화면에서 다시 본다.

## R-16

- **확정:** 첫 창 내용 영역은 1600×900 DIP(`useContentSize: true`), 콘텐츠 배율은 125%다. Windows 100%에서는 CSS 1280×720이다. 사용자가 바꾼 정상 외곽 bounds·최대화·배율을 checkout별 userData에 복원하고 화면 밖이면 주 모니터, 겹치면 가장 많이 겹치는 작업 영역 안에 보정한다. 작은 영역에서는 반응형/스크롤을 허용한다.
- **조작/저장:** 배율 75·100·125·150·175·200%, Ctrl +/- 및 Ctrl 0=125%다. 잘못된 설정/단계 밖 배율은 기본값을 쓴다. main이 500ms debounce와 직렬 쓰기를 소유한다. 숨김은 저장을 기다리지 않고, 명시 종료는 마지막 대기값 저장을 즉시 시작해 최대 500ms 기회를 준다. 실패는 마지막 정상 파일을 보호하고 이유를 기록한다. 살아 있는 창에는 즉시 비차단 안내를 연속 실패 중 한 번만 보이며 저장 성공 때 초기화한다. 종료 시 실패나 500ms 초과는 다음 실행에 한 번 안내하고 기록을 지운다. 메인 `msg_f85b875114b7`의 Q-01 해석 정정이며 전역 표시/설정과 기존 트레이 수명은 바꾸지 않는다.
- **향후 완료조건:** 최초/재실행·연속 변경·저장 실패·저장 중 숨김/종료·깨진 설정·모니터 분리/작업 영역 축소·배율 양끝/초기화·125% 그림/폰트 캡처를 독립 검증한다. 실제 보조 모니터 배치는 가능할 때만 실행하고 미실행을 구분한다. 기존 외곽 1280×720 테스트는 새 계약으로 교체한다.

## R-17

- **확정:** 상세 문서의 매핑 코드 이름을 클릭해 앱 안에서 읽기 전용 원문을 본다. 파일은 직접, 디렉터리는 목록을 거쳐 연다. 줄 번호·고정폭 텍스트·가로 스크롤·복귀/focus를 제공한다. 편집·실행·외부 편집기·MCP 코드 조회 도구·심볼 이동은 포함하지 않는다.
- **버전:** 원문은 codeReference.commitSha의 Git blob이다. 비교는 앱 checkout(현재 management-active)의 요청 시 고정한 HEAD blob이며 전체 비교 SHA를 표시한다. 같음/다름/파일 없음/비교 실패를 구분하고 다름을 신구 판정으로 해석하지 않는다. 미커밋 작업 트리는 비교하지 않음을 표시한다.
- **권한/한도:** main이 guide hash·cardId·mappingIndex를 검증하고 매핑의 정확한 file 또는 경계 prefix 안 directory에서만 Git 일반 blob을 읽는다. 임의 SHA/절대·상위·역슬래시·URL·glob 경로, symlink/gitlink는 거부한다. 파일은 256 KiB UTF-8, 디렉터리는 100개씩 표시하며 총 2,000개/원시 1 MiB 상한이다. Git은 고정 cwd/실행파일·execFile 인자·환경 제한·자동 fetch/필터 금지·5초 제한으로 실행한다. 동시 2개는 요청 단위이며 초과는 busy로 거부한다. 전환/취소/종료 시 정리하고 늦은 응답은 폐기한다.
- **향후 완료조건:** 정상 파일/디렉터리와 경로/버전/종류/byte/인코딩/출력/timeout/busy/취소 경계를 독립 시험한다. 원문 IPC와 200줄 화면 분할, 비교 상태, 키보드/복귀를 실제 Electron에서 확인한다. 오류를 빈 화면이나 잘린 전체 원문으로 숨기지 않는다. Git 읽기·매핑 권한·표시의 책임을 분리한다.

- **확정:** 운영툴의 개발 현황 영역은 완성된 작업의 기준과 이후 작업을 정리한다. 실시간 작업 현황은 저장소 밖 개인 도구인 CLI 현황판이 맡는다. 운영툴 「작업 현황」 화면 후보는 폐기했다. 사용자 원문 「…운영관리툴에는 완성된 작업 기준과 이후 작업 어떻게 해야할지로 정리하는 방향으로 가는게 더 좋겠다, 실시간성은 클로드 모드가 훨씬 좋다」(2026-10-04, 메인 `msg_3485e21d8942`)와 「운영툴 「작업 현황」 화면 후보를 폐기할지 → A 폐기」(2026-10-05, 메인 `msg_b101768ef103`)가 출처다. 전문은 [시스템 카드 goal의 역할 방향 절](goals/2026-10-02-system-cards/goal.md#운영툴과-실시간-현황판의-역할-방향--2026-10-04-메인-전달)에 있다.
- **범위:** 이 방향은 개발 현황 영역에 대한 것이다. [R-01](#r-01)의 라이브 서버 운영·유저/GM 관리 우선순위를 바꾸지 않는다.
- **향후 완료조건:** 개발 기록은 완성된 작업을 원문 색인으로 보여 준다([R-19](#r-19)). 이후 작업은 `00_Document/operations/BACKLOG.md`를 읽기 전용으로 보여 주는 백로그 메뉴가 맡는다. 운영툴은 실시간 세션·진행 상태를 만들어 표시하지 않는다.

## R-19

- **확정:** 문서와 운영툴 기록의 원본은 프로젝트 문서 하나다. 사용자 원문은 「대시보드 결정 응답: … 4) 문서와 운영툴 기록의 이중 원본 - 9-30 링크 합의를 확정할지 → A 9-30 링크 합의로 확정 …」(2026-10-06, 메인 `msg_1f81ec8d4d15` 전달)이다. 9-30에 열어 둔 「항목별 서술 소유권 전환」은 닫는다. 운영툴 기록의 요약·상태 사본은 원문 링크(경로·구간과 필요한 commit)와 색인으로 바꾼다.
- **구체화(2026-10-06 사용자 답, 메인 `msg_dbff8df03e07`):** 화면의 기록 편집·JSON 불러오기·저장을 없애고 색인 수정은 Git PR로만 한다. 화면과 MCP는 실행 중인 checkout의 파일을 읽고 그 checkout의 branch·HEAD를 표시한다. 조회 MCP의 실제 개발 세션 연결은 이번 목표에서 하지 않는다.
- **유지:** `records/system-guide.json`의 구현 설명 문서와 카드 소개는 다른 문서의 사본이 아닌 유일한 원문이므로 Management 소유 원문으로 둔다. MCP는 이 자료도 같은 원천으로 제공한다([R-14](#r-14)).
- **향후 완료조건:** catalog에 서술·상태 필드가 없고 모든 원문 링크가 저장소 경로·구간을 가리킨다. 없는 파일·구간이나 낡은 색인은 끊긴 링크로 보이며 현재 사실처럼 보이지 않는다. 색인에 등록된 저장소 안 문서만 읽는다. 구체 완료조건과 상태는 [기록 원본 일원화 goal](goals/2026-10-06-record-source-unification/goal.md#관찰-가능한-완료조건)을 따른다.
