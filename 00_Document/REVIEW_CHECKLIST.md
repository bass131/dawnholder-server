# 변경 검토

완료조건과 실제 diff에 해당하는 항목을 고른다. 작업 방식·권한은 [AGENTS](../AGENTS.md), 코드 규칙은 [CODE_CONVENTION](conventions/CODE_CONVENTION.md)을 따른다. 결과에는 수행한 검사·실패·미실행 항목과 근거 경로를 적는다.

| 대상 | 확인할 내용 |
|---|---|
| 입력 경계 | 길이·범위·현재 상태·소유권·호출 빈도 검증, 잘못된 입력의 거부 경로 |
| 서버 권위 | HP·보상·쿨다운·위치·판정의 최종 결정이 서버에 있는지, 예측 결과와 권위 상태를 구분하는지 |
| 패킷 | ID 재사용·재정렬 여부, PDL/생성 코드/버전 일치, 양쪽 읽기·쓰기와 핸드셰이크·봇 호환성 |
| 실행 순서 | 맵 큐와 틱의 소유권, Party→Quest 순서, 종료·연결·맵 이동 중 요청 처리 |
| 공유 코드 | .NET Standard 2.1 호환성, 서버와 Unity 사용처, DLL 갱신 부작용 |
| Unity | `.meta`·GUID·직렬화 값·Resources 경로, 메인 스레드 적용, 씬과 네트워크 수명주기 |
| 구조 | 데이터 소유자와 변경 이유가 분명한지, 구현 없는 추상화·같은 이유의 중복·거대한 책임 묶음이 있는지 |
| 테스트 | 정상 경로와 의미 있는 거부·경계·회귀 사례, 테스트가 목표 분기를 실제로 거치는지 |
| 보고 | 현재 코드·계획·과거 관찰 구분, 주장과 로그·파일 근거 일치, 검증하지 않은 영역 명시 |

문제는 파일·조건·관찰 결과·영향으로 설명한다. 실행 결함은 구현자에게 수정 요청하고 영향 범위를 다시 검증한다. 설계·범위 선택은 메인이 사용자와 결정한다. 코드 변경이 없는 문서 정비에는 링크·내용·원문 보존·렌더 검사가 우선이다.

PR 작성은 허용되지만 각 PR의 병합 직전 사용자 명시 승인이 필요하다. 검토 통과나 CI 성공을 병합 승인으로 대신하지 않는다.
