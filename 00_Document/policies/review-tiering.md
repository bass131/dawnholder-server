# Review Tiering — 3-Tier 리뷰 구조 + Tier 2 자동 호출

> **헌법 참조**: 본 정책은 헌법 "Agent Routing" 섹션에서 링크됩니다.
> 충돌 시 헌법이 이깁니다.
>
> **⚠️ 명세 신선도 주의**: ADR-019(2026-05-15)에 막 박힌 시스템. 본 정책 작성 시점에 *실측 발동 0건*. **현재 명세는 추측 기반**. 합류(2026-06-말) 후 첫 발동 1~2회 관찰 → false positive·누락·트리거 조건 재조정 예정. 명세 변경 시 본 문서 갱신.

본 문서는 코드 변경 후 리뷰 단계를 3개 Tier로 나누고, 그 중 **Tier 2 자동 호출**의 트리거·약속·결과 처리를 정의합니다.

---

## 1. 3-Tier 리뷰 구조

| Tier | 누가 | 언제 | 무엇을 | 도입 상태 |
|---|---|---|---|---|
| **Tier 1** 도메인 셀프리뷰 | 도메인 에이전트 자기 자신 | 코드 변경 직후, work-envelope 작성 전 | 자기 영역의 헌법 위반 자체 점검 | **합류 후 도입 예정** (미구현) |
| **Tier 2** 자동 통합 리뷰 | `reviewer` 서브에이전트 | 메인 세션이 트리거 조건 충족 시 자동 호출 | [`REVIEW_CHECKLIST.md`](../REVIEW_CHECKLIST.md) 기준 5축 점검 | **2026-05-15 박힘** (실측 0건) |
| **Tier 3** 수동 깊은 리뷰 | `/work:review` 슬래시 커맨드 | 사용자가 명시 호출 | Phase 단위 상세 보고 | 기존 운영 중 |

## 2. Tier 2 트리거 조건 (메인 세션 책임)

도메인 에이전트가 코드 변경 후 메인 세션으로 복귀하면, 메인 세션은 다음을 *순서대로* 평가:

### 2-1. 무조건 호출 (조건 무시)
- `98_Shared/` 변경 포함 → 호출
- 새 핸들러/패킷/공식 추가 → 호출
- 사용자가 *"리뷰 돌려줘"* 명시 요청 → 호출

### 2-2. 조건부 호출
- 실질 코드 변경 ≥ 10줄 → 호출
- 실질 코드 변경 < 10줄 → 스킵

### 2-3. 무조건 스킵
- 테스트 파일만 변경 → 스킵 (회귀 안전망 강화는 리뷰 우선순위 낮음)
- 주석/오타/rename만 → 스킵
- 사용자가 *"리뷰 스킵해줘 — <사유>"* 명시 + 사유 첨부 → 스킵, work-envelope에 사유 기록

---

## 3. 입력 약속 (메인 세션 → reviewer)

reviewer 호출 시 다음 3개 전달 ([`reviewer.md`](../../.claude/agents/reviewer.md) 입력 약속 섹션 참조):

| 키 | 내용 |
|---|---|
| `range` | 변경 범위 식별자 (Phase slug 또는 ad-hoc id, work-envelope의 WORK-ID와 동일) |
| `files` | 변경된 파일 절대 경로 목록 |
| `diff_summary` | 메인 세션이 작성한 자연어 diff 요약 (몇 줄) |

**3개 중 하나라도 누락 시** reviewer가 *추측 없이 즉시 종료*하므로, 메인 세션은 호출 전 3개 다 준비.

---

## 4. 결과 처리 (메인 세션 책임)

reviewer가 반환한 리뷰 결과를 *그대로 사용자에게 노출* + 다음 액션:

| 결과 | 다음 액션 |
|---|---|
| 🔴 **위반 있음** | 사용자에게 "고칠까요?" 확인 → *재* 도메인 에이전트에 위임. 사용자가 *"패스"*하면 work-envelope에 `리뷰 패스 사유: <한 줄>` 기록. |
| 🟡 **개선 제안만** | 그대로 보여주고 통과. work-envelope엔 별도 기록 X. |
| 🟢 **위반 0개** | 통과. 메인 세션이 work-envelope 마무리 후 사용자에게 최종 제시. |

---

## 5. 우회 메커니즘 (S-1: 사유 명시 후 허용)

사용자가 *"리뷰 스킵해줘"* 명시 시 메인 세션은 *사유*를 요청 (예: "임시 디버깅용", "다음 커밋에 별도 리뷰"). 사유 받으면:

1. reviewer 호출 스킵
2. work-envelope에 다음 줄 추가:

```
리뷰 스킵 사유: <사용자가 제공한 한 줄>
```

이 흔적은 `grep "리뷰 스킵 사유"`로 한 방에 회수 — 우회 *습관화* 감지 가능.

---

## 6. 범위 (Scope)

| | 대상 | 비고 |
|---|---|---|
| ✅ **점검** | 헌법 / ADR / ARCHITECTURE / 테스트 커버리지 / 도메인 패턴 | 5축 매핑은 [`REVIEW_CHECKLIST.md`](../REVIEW_CHECKLIST.md) |
| ❌ **점검 X** | 코드 스타일 (네이밍/들여쓰기/포매팅 등) | 미래 Roslyn analyzer로 도입 예정 (ADR-019 후속 후보) |

**왜 코드 스타일 제외인가**: 합의 없는 1+1명 단계에서 *스타일 일관성*은 도구(analyzer + .editorconfig)에 위임이 옳음. 시니어 피드백 *"코드 컨벤션 깔쌈하게"*를 우리 현실(합의 없는 단계)에 맞게 재해석한 길 D (CONTEXT.md 학습 일지 후보 ★★ 참조).

## 7. 실측 후 재조정 예정 항목

본 정책은 *추측 기반*. 합류 후 첫 1주 안에 다음 관찰 → 명세 갱신:

- [ ] **트리거 false positive 빈도** — "10줄 미만이지만 호출됐어야 했던" 케이스
- [ ] **트리거 누락 빈도** — "10줄 이상이지만 트리비얼해서 스킵 권장" 케이스
- [ ] **결과 처리 마찰** — 🔴 위반 시 *재 도메인 위임*이 자연스러운가, 아니면 메인 세션이 직접 고치는 게 빠른가
- [ ] **우회 습관화** — `grep "리뷰 스킵 사유"` 주간 카운트. 3회 초과 시 트리거 조건 재설계 신호
- [ ] **Tier 1 도메인 셀프리뷰 도입 시점** — Tier 2 안정화 후 1주 더 관찰 후 판단

재조정 결과는 ADR-019 후속 또는 본 정책 직접 수정 (변경 폭에 따라 결정).
