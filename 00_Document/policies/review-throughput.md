# Review Throughput — 리뷰 처리량 모델 (병목 해소)

> **근거**: [`../ADR/harness/ADR-032-loop-driven-operation.md`](../ADR/harness/ADR-032-loop-driven-operation.md) §E. [ADR-019](../ADR/harness/ADR-019-reviewer-agent.md) 정적 트리거 매트릭스를 *예외 기반·신뢰 졸업*으로 **supersede**. 헌법 링크는 P02 — 충돌 시 **헌법이 이깁니다.**
>
> **이 문서의 역할**: 사람이 *모든* 산출물을 리뷰하지 않고 어디에 시선을 쓸지 정하는 정책. 판정자는 [`work-judge.md`](work-judge.md), 엔진은 [`loop-driver.md`](loop-driver.md). 리뷰 *트리거*의 구버전(무조건/조건부/스킵)은 [`review-tiering.md`](review-tiering.md).

본 문서는 **throughput(처리량) 병목**을 해소합니다. AI 산출 속도를 사람의 *전수 리뷰*가 못 따라가면 (PR 100개가 쌓이면 사람 시간으로 다 못 봄) 직렬 병목이 됩니다. 사람을 *모든 산출물*에서 빼고 *고위험·고학습가치*에만 시선을 집중시킵니다.

---

## 1. 네 가지 기제

1. **예외 기반**: 고위험·신규·flagged + *샘플*만 사람이 봄. 나머지는 기계 게이트 + AI 리뷰가 통과. 일부 산출물은 **의식적으로** 완전 리뷰를 포기 = *잔여 위험 수용*.
2. **통합 고도**: PR 100개를 보는 게 아니라 **통합 이야기 하나**를 봄. 루프는 coherent 단위로 묶고, 사람 이해를 돕는 *작업 정리 문서*(`-DONE.md` + HTML)로 요약 (영호: *"작업물을 정리하는 문서로 사람의 이해를 돕고, 목표를 최대한 구체적으로"*).
3. **신뢰 졸업**: 안전이 증명된 카테고리는 개별 정독 없이 배치 GO (§3).
4. **시선 배분 = `max(위험, 학습가치)`**: 보일러플레이트는 빠르게, 새 아키텍처·까다로운 네트워킹은 깊게.

---

## 2. 항상 사람 시선 (졸업 불가)

다음은 신뢰 졸업 대상이 **아닙니다** (영구 사람 게이트 — [`work-judge.md`](work-judge.md) 버킷 (c)):

- `trust-boundary` / `irreversible` (push·PR·머지·`Protocol.Version`·DB 마이그)
- 신규 아키텍처 / 프로토콜 / 공식
- 헌법 절대 원칙(§1~5) 인접 변경

---

## 3. 신뢰 졸업 N — 초안 (#6, 영호 확정 대기)

어떤 산출물 유형이 N회 무위반이면 샘플링으로 강등되는가:

| 산출물 유형 | 예시 | 졸업 처리 |
|---|---|---|
| **보일러플레이트·기계 생성** | PDL 생성 코드, 데이터 테이블 1행 추가 | 즉시 샘플링 (정독 면제) |
| **패턴 반복** | 새 몬스터 데이터, 기존 핸들러 패턴 복제 | 연속 **N회** 무위반 후 샘플링 강등 |
| **신규 구조·trust-boundary** | 새 시스템·네트워킹·보안 경계 | **졸업 불가** (항상 사람) |

**초안값**:

- **N = 3** (Rule of Three — 우리 하네스가 이미 쓰는 임계와 정합)
- 강등 = "매번 정독" → **1/3 무작위 샘플링**
- **위반 1회 = 졸업 취소** (원위치 + N 카운트 재시작)
- `trust-boundary`/`irreversible`는 영구 제외 (§2)

> ⚠️ 이건 **초안**입니다. 실제 N·샘플링 비율·유형 경계는 루프 운영 *실측 후* 영호가 확정 (미결 #6). 너무 빨리 졸업시키면 잔여 위험 ↑, 너무 늦으면 throughput 이득 ↓ — trade-off의 균형점은 실측이 알려줌.

## 4. AI가 통과시키는 것의 안전망

- `reviewer` 🔴 0 + 회귀 게이트 = 기계 + AI 통과. 그 위의 잔여 위험은 *의식적 수용* (전수 리뷰의 세밀함을 포기한 대가).
- **큰 PR 머지 전** = `/cross-review` 권유 (외부 시각).
- **자기평가 편향 주의**: 무인 진단은 자기 코드를 후하게 봄 → 외부 cross-check 게이트 (refactor-sweep 첫 dry-run에서 Codex가 self-assessment bias 적발한 전례).
