📌 한눈 결론 (TL;DR)

헌법 절대원칙 위반은 SN-02(치트 게이트) 단 1건이고, 나머지는 보안 구멍이 아니라 "리팩토링이 중간에 멈춰 책임이 엉뚱한 계층에 흘러들어 굳은 자국"입니다. 5대 원칙(서버 권위 / 프로토콜 / 신뢰경계 / 공유규율 / 틱루프 블로킹)은 production 경로에서 대체로 잘 지켜지고 있어요.

M8(DB 영속화) 진입 전 가장 중요한 정리는 QuestRegistry 분리입니다 — 영속화될 핵심 상태(킬카운트·보스해금·솔로진행도)가 지금 PartyRegistry(파티 도메인) 안에 살아서, 그대로 M8을 하면 "파티 클래스가 솔로 플레이어 퀘스트를 영속화"하는 개념 역전이 DB 스키마에 박힙니다. 영속화 경계를 긋기 전에 도메인 경계부터 바로잡아야 깨끗한 스키마가 나옵니다.

🔁 반복 테마 (결함 패턴 6)

① System 추출의 절반-완료 비대칭

같은 도메인의 같은 작업이 한쪽은 전용 System/Migration으로 빠지고(MeleeAction+DeferredDamageSystem, MapMigration, HandleEnemyDeath) 한쪽은 State·GameSession·PartyRegistry에 인라인 잔류. 리팩토링이 도중에 멈춰 책임 배치가 비대칭.

② 진실 공급원 이중화 + 암묵 동기화

같은 개념을 두 곳에 저장하고 동기화를 '각 진입점이 잊지 말고 세팅'하는 컴파일러가 못 잡는 계약에 의존. AI 상태(EnemyState vs Fsm), 사망 신호, 매직넘버, 매핑 테이블.

③ false-promise 문서/주석

코드/문서가 '이건 X에 쓰인다 / 참조 불가하다 / 클라도 공유한다'고 능동 약속하나 실재와 어긋남 → 다음 개발자를 오도. (JobQueue 'actor 큐로 사용 중', DashSpeed '서버 전용' 등)

④ 보일러플레이트 fan-out

동일 plumbing이 8~18곳 복제(Rule of Three 초과). 핸들러 게이트(8), 봇 라이프사이클(17), 이펙트 스폰(4). 계약 1곳 변경 시 다중 파일 동시 수정 + 누락 시 부분 침묵 실패.

⑤ 네임스페이스 ≠ 폴더 ≠ 책임

디렉토리·namespace·헤더 주석이 표방하는 책임과 실제 내용이 어긋남. GameSession(폴더 Network/namespace Sessions), PartyRegistry가 퀘스트 소유, ActionKind가 서버 전용인데 98_Shared.

⑥ endianness 계약 위생

wire는 LittleEndian 단일 진실인데 frame/list count 읽기 일부가 host-endian BitConverter로 새어 자기 계약 위반. 현 LE 타깃에서 우연히 동작하는 latent 결함.

🔴 M8 전에 꼭 정리할 2건 (preM8)

1. QuestRegistry 분리 preM8 recommend

왜 — 영속화될 핵심 상태(킬카운트·보스해금 latch·_soloProgress)가 PartyRegistry에 살아서, DB 스키마를 그대로 설계하면 '파티가 솔로 퀘스트를 영속화'하는 개념 역전이 DB 계층에 박힘. _soloProgress(파티 없는 플레이어)가 파티 클래스에 있는 게 정반대.
범위 — PartyRegistry에서 퀘스트 상태/로직 제거 → 신설 Quest/QuestRegistry.cs(actor 패턴 동일). GameWorld가 둘 각각 소유, QuestRegistry는 파티 멤버 조회만 PartyRegistry에 질의(한 방향, 순환 없음). QuestConstants는 이미 Quest/에 있어 상태/로직만 합류.
위험 — 낮음. actor 경계 복제로 race 낮음. PartyState.KillCount(파티 공유)는 PartyState에 남기되 QuestRegistry가 읽기/쓰기. 테스트 분리 필요.

2. 치트 게이트를 빌드 구성에 종속 preM8 헌법 #1·#3 recommend

왜 — untrusted C_CheatCommand(F8)가 기본 ON 런타임 플래그(주석+수동토글이 유일 안전장치)만 통과하면 보스 포탈을 권위적으로 해금. 영속화 후엔 치트로 조작된 상태가 DB에 굳어 더 위험.
범위 — HandlerRegistry에서 #if DEBUG로 CheatCommandHandler 등록을 감쌈. Release는 C_CheatCommand가 unknown PacketID로 drop. const 방식은 CS0162 경고 재도입이라 등록 게이트가 더 나음.
위험 — 낮음·가역. DEBUG(데모) 빌드는 F8 그대로 유지(영호 시연 보존).

🟡 검증 통과 발견 — 심각도별

SN-02high헌법 #1·#3계층위반
02_Server/GameServer/Debug/DebugConfig.cs:13 + Handlers/Debug/CheatCommandHandler.cs

DebugConfig.AllowCheats=true가 const도 #if DEBUG 가드도 아닌 런타임 static readonly 기본 ON. CheatCommandHandler가 모든 빌드에서 무조건 등록 → untrusted C_CheatCommand가 퀘스트 킬카운트 게이트를 우회해 보스 포탈을 권위 해금. 안전장치가 '주석+수동 토글'뿐.

XD-2medpreM8 핵심위치오류
02_Server/GameServer/Party/PartyRegistry.cs

PartyRegistry가 퀘스트 도메인 상태/로직을 통째 소유(_soloProgress/_bossUnlocked/OnKill/GetKillCount 등). 특히 _soloProgress는 '파티 없는' 플레이어 진행도라 파티 개념과 정반대. Quest/ 네임스페이스엔 상수만 있고 상태/로직은 PartyRegistry에 — 상수만 옳은 곳에 있는 비대칭.

SG-2med위치오류
02_Server/GameServer/.../States/EnemyStates.cs:59-67

적→플레이어 근접 데미지·HP감소·사망판정·풀피 부활(Revive)이 States 폴더에 인라인. 플레이어→적은 이미 MeleeAction+DeferredDamageSystem+HandleEnemyDeath로 추출됐는데 적→플레이어만 State에 남은 비대칭. '죽으면 풀피 부활' 핵심 규칙이 State에 묻혀 발견성 낮음. HandlePlayerDeath 대칭 진입점 부재.

SN-01 / XD-3med위치오류
02_Server/GameServer/Network/GameSession.cs:381-527

파티 비즈니스 규칙(거절 4종 검증/위장검증/CreateParty race/Disband 시퀀스)이 GameSession의 EnqueueJob 람다에 인라인. 같은 도메인의 포탈 이동은 MapMigration으로 추출됐는데 파티만 세션에 잔류. PartyRegistry는 저수준 primitive만 노출.

SN-03medSOLID·false-promise
02_Server/Network/JobQueue.cs · PriorityQueue.cs

JobQueue/IJobQueue + PriorityQueue가 production wiring 0건 dead code(게임은 ConcurrentQueue 직접 사용). 문서/convention refs는 'JobQueue가 맵 actor 큐로 사용 중'이라 약속하나 실재 0. 게다가 PriorityQueue.Pop() sift-down에 실제 버그(line 59가 _heap[right] 대신 _heap[left] 비교).

SN-05med개념종속·DRY
02_Server/GameServer/Handlers/ (8개 핸들러)

전제조건 게이트가 3층 분산 — handshake(OnRecvPacket 인라인) + HasSelectedClass(8개 핸들러가 각자 첫 줄 복붙) + dispatch. 새 게임플레이 핸들러에서 가드 누락 시 class 선택 전 입력이 새는데 컴파일러가 못 잡음(잠재 #3 구멍).

C2medSOLID·응집
03_Client SkillCastHandler · HitResultHandler · PlayerAttackHandler

SkillCastHandler가 스킬 분기·Resources 경로·스폰/부모링/flip/앵커 정책·텔레포트 보간까지 떠안은 God-handler성. Load+Instantiate+flip+EffectLifetime 패턴이 3곳에 4중 복제 — 정작 BossAttackEffectSpawner·ProjectileSpawner 추출 패턴이 이미 존재하는데 이 3개만 인라인(채택 컨벤션과 불일치).
