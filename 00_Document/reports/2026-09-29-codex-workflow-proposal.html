위임할 때 · 짧은 작업 계약

목표, 필요한 파일·결정, 소유 파일 범위, 완료 조건, 검증 기준을 전달합니다. 작업자가 같은 파일을 동시에 수정하지 않도록 메인이 범위를 나눕니다.

돌아올 때 · 핵심 정보 네 가지

변경 요약 / 검증 근거 위치 / 리스크 / 결정 요청. 구현 세부 기록과 원본 로그는 파일에 남기고, 메인은 필요할 때 해당 근거를 확인합니다.

검증 결과 · 수정 또는 논의

구현 결함은 작업자에게 수정 요청합니다. 설계·범위 변경은 메인으로 올려 사용자와 논의합니다. 필수 검증이 남아 있으면 완료로 보고하지 않습니다.

이번 범위는 운영 규약입니다. 요청과 보고의 범위를 관리하는 방식이며 기술적 강제나 컨텍스트 오염의 완전한 차단을 보장하지 않습니다. AgentDeck으로 구상했던 결정론적 프로그램 통제 시스템은 이번에 개발하지 않습니다.

검증 범위와 완료 기준
  • 문서·지침: 새로 바뀐 링크, 현행 지침의 충돌, 최신 상태 진입점을 확인합니다.
  • 스크립트·검사: 성공할 입력과 실패해야 할 입력을 모두 확인합니다. 스크립트 존재만으로 작동을 보장하지 않습니다.
  • 게임 경로 변경이 포함될 때: 깨끗한 출력에서 빌드·관련 테스트·맵 배포·실서버 시작·Unity DLL 및 자산 로드를 확인합니다.
  • 기존 실패와 이번 변경으로 생긴 실패를 구분합니다. 필수 검증이 실행되지 않았으면 확인 대기로 남깁니다.
  • 검증된 변경만 커밋하고, 원격 반영과 병합은 합의한 범위에 맞춰 진행합니다.
보존·정리의 경계

로컬 변경 4건은 따로 확인해 보존합니다. 보관할 설정·코드를 명시적으로 선택해 합의한 변경만 포함하며, 관련 없는 로컬 변경을 자동 커밋하지 않습니다. 브랜치를 만드는 것만으로 로컬 변경이 저장되지는 않습니다. 무시된 로컬 설정·로그·인증 정보는 일괄 원격 업로드하지 않습니다.

게임 ADR·중요 구현 기록은 유지합니다. Claude 전용 역할·명령·학습 장부·중복 운영 정책은 보관 후 활성 안내에서 제외하고, 호출·링크 의존성을 끊은 범위만 정리합니다. 빈 Unity Directory.Build.props는 의도된 격리 파일이므로 유지합니다.
