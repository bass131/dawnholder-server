01 — 이게 뭔가요

Dawnholder는 .NET 10 + Unity 6 LTS 기반 2D MMORPG 프로토타입. 본 레포의 진짜 자산은 게임 코드가 아니라 AI를 어떻게 운영하고 통제하고 견제했는가입니다.

본인이 합류한 이유

본인은 학부생 백지 수준에서 시작합니다. 그게 정상이에요. 본 프로젝트는 *AI에게 코드 시키는 법*이 아니라 *AI를 운영하는 법*을 같이 배우는 학습 마라톤입니다.

본인이 얻어갈 것

  • 실전 백엔드/네트워킹 — raw TCP, 권위 서버, 동시성, 영속화
  • 면접 무기로 누적되는 협업 기록 — Claude와 협업한 모든 결정·트러블슈팅이 본인 명의로 박힘 (노션 자유 양식)
  • 본인 노션 포트폴리오 — 6개월 뒤에 본인 자기소개서 쓸 때 베이스 자료

Daily Workflow

03 — 매일 작업 흐름

셋업 끝났으면 본 흐름이 일상. 처음엔 어색해도 한 주만 지나면 손에 박힙니다.

아침: /session:start # git 안전 점검 + work-pin + CHANGELOG → (게이트 통과 시) git pull origin main → 게이트가 STOP 띄우면 안내대로 처리 후 /session:start 다시 작업 중: git checkout -b feature/{slug}-{작업명} → Phase 진행 → 막히면 Claude한테 자연어로 질문 (예: "이거 왜 이래?") → 큰 작업이면 /work:plan {목표} (plan-auditor 자동 호출) → 코드 변경 후 Tier 2 reviewer SubAgent 자동 호출 + 새 hooks 자동 검사 Phase 끝 (등급별): 단순/보통 = work-pin + commit message 복잡 = -DONE.md 박제 (AI가 사실 박음) 대규모 = + 5단계 보고 MD/HTML (캡스톤 평가 자산) → (선택) 학습 회고: 본인 노션 자유 양식 → /session:end # commit + PR + (선택)노션 + work-pin 갱신

핵심 3개 슬래시

/session:start
아침에 첫 입력. git 안전 점검 게이트 + work-pin 좌표 인지 + 팀장 변경(CHANGELOG) 자동 확인. 위험 상태(main 브랜치·미커밋 변경)면 STOP 띄우고 안내.
/work:plan
큰 목표를 1~3시간짜리 Phase로 쪼개기. Phase 분해 받기.
/session:end
Phase 끝났을 때 마감 절차. commit + PR + 노션 박제까지 한 흐름.
⚠ Git 충돌·실수 — 안전 매뉴얼 (2026-05-15 보강)

작업물 유실의 단 하나의 원인은 잘못된 복구 명령입니다. git pull 자체는 unstaged 변경을 덮어쓰지 않아요. 충돌이 나면 git이 멈춰서 물어볼 뿐.

해도 되는 것: git status · git stash push -m "{요약}" · git commit -m "wip: {요약}" · git checkout -- {특정파일}

절대 금지 (이거 치면 작업물 증발): git reset --hard · git checkout . · git clean -fd

충돌·복구 상황은 무조건 팀장(유영호) 슬랙. 부끄러운 일 아닙니다. 위 3개 명령은 한 번 치면 되돌릴 수 없어요.

💡 갑자기 STOP 떴어요? — 하네스 변경 후 첫 세션

본인이 마지막 작업한 이후 팀장(또는 본인)이 .claude/ 안의 슬래시 커맨드·헌법·하네스를 갱신했을 수 있어요. 그런 변경은 .claude/CHANGELOG.md 최상단에 한 줄씩 박힙니다 (위험도 [L] / [M] / [H] 표시).

/session:start의 게이트나 다른 슬래시 커맨드 동작이 어제와 다르게 보이면 그건 버그가 아니라 변경 인지의 신호예요. 안전 장치가 박힌 거지 갑자기 동작이 바뀐 게 아닙니다.

첫 STOP 만났을 때 3단계:

  1. CHANGELOG 최상단 한 줄 읽기 (오늘 또는 가까운 날짜의 변경)
  2. 게이트가 띄운 STOP 메시지 안내대로 처리 (브랜치 이동 · stash · wip commit 등)
  3. 그래도 헷갈리면 팀장(유영호) 슬랙. 부끄러운 일 아닙니다 — 하네스 전환 시점에 한 번씩 다 겪어요.

[H] 변경이면 슬랙에도 별도 안내가 갔을 거예요 — 그것도 같이 보면 컨텍스트가 더 빨리 잡힙니다.

05 — 협업 룰

짧고 명확한 4개 룰. 어겨도 큰일 안 나지만, 따라야 서로 덜 부딪힙니다.

  1. main 브랜치 직접 push 금지

    팀원은 PR로만 머지. 팀장은 bypass 권한 있음. 작업은 feature/{slug}-{작업명} 브랜치에서 → PR 만들기 → 팀장 승인 → main에 머지.

  2. 본인 영역만 만지기

    .github/CODEOWNERS 참조. 백엔드는 팀장 단독, 클라는 인규·유현 공유, 학습 일지는 각자.

  3. 하네스 변경 인지

    팀장이 헌법/ADR/하네스 갱신하면 .claude/CHANGELOG.md에 박힘. /session:start가 매일 자동 확인.

  4. 개인 자산은 git 무시

    current-pin.txt(작업 좌표, 세션 간 단일 핸드오프 — ADR-025)는 각자 보유(.gitignore). learning-journal/{본인}/은 2026-05-16부터 기본 공개(PR #12) — 비공개 원하면 본인이 자기 슬러그를 .gitignore에 추가(영역 자율).

06 — AI 운영 시스템

본 레포의 핵심 자산. 4계층 구조로 Claude를 통제·견제합니다. 본인이 직접 만질 일은 거의 없지만, 어떻게 돌아가는지는 알면 좋아요.

계층자산역할
L1 — 규칙 CLAUDE.md (헌법, 239줄) AI가 위반 시도 시 거부하도록 박힌 절대 원칙 5개 + 라우팅 + 4등급 + SubAgent 풀 9 + Knowledge 시스템
L2 — 역할 .claude/agents/ 서브에이전트 9개 = Worker 4 (server / shared / client / qa) + Reviewer 2 (reviewer / plan-auditor) + Specialist 3 (unity-bridge / coordinator / knowledge-gc)
L3 — 단축키 .claude/commands/ 슬래시 커맨드 10개 (작업 4 / 세션 3 / 점검 2 / 셋업 1). 옛 학습 5 + 일지 3 슬래시는 M3.5에서 제거 (ADR-022), 학습 트랙 B는 ADR-025로 은퇴
L4 — 검증 .claude/hooks/ 자동 검증 훅 7개 (dangerous-cmd-guard / tdd-guard / circuit-breaker / risk-detector / shared-discipline-guard / pin-injector / phase-gate-validator)
L5 — 캐시 .claude/knowledge/ SubAgent 도메인별 학습 캐시 5 (cross-cutting / server / shared / client / qa) + GC Collector (신설)

헌법 5대 절대 원칙

이거 어기면 보안 구멍, 동기화 버그, 핵 취약점. 본인이 어겨달라 요청해도 Claude는 거부합니다.

  1. Server Authority — 서버 권위

    클라이언트는 단순 렌더러 + 입력 전달자. HP/XP/인벤토리는 서버 전용. 데미지/히트 판정/루팅은 서버가 결정.

  2. Protocol is Sacred — 프로토콜은 신성함

    패킷 ID는 영원. 은퇴 ID 재사용 절대 금지. 필드 추가는 끝에만.

  3. Trust Boundary — 신뢰 경계

    클라이언트 소켓에서 오는 모든 것은 untrusted. 범위 검증·소유권 확인·rate-limit 항상.

  4. Shared Code Discipline — 공유 코드 규율

    98_Shared/ 변경 시 양쪽 빌드 확인. 복사-붙여넣기 금지.

  5. No Blocking in Tick Loop — 틱 루프 블로킹 금지

    50ms마다 도는 틱 안에서 await Task.Delay·동기 DB·Thread.Sleep 절대 금지.

★ 정책 외부화 (2026-05-15 시작 + 2026-05-21 ADR-022 갱신)

헌법은 "무엇을 절대 어기지 않는가"만 담고, 양식·운영 가이드는 00_Document/policies/로 외부화됨. 8개 파일: reporting-format.md · pin-and-done.md · doc-thresholds.md · review-tiering.md + 새 3개 (grade-and-risk.md · subagent-routing.md · knowledge-system.md).

07 — 학습 회고 (자율)

본인 면접 무기. 디테일이 잊히기 전에 박아두면 좋음. AI는 인터뷰만, 답은 본인이 채움. 옛 학습 추적 트랙 B(자동 권유 + ★★ 후보 누적)는 ADR-025로 은퇴 — 이제 회고는 강제 아닌 자율. 아래 양식은 박고 싶을 때 쓰는 도구일 뿐.

두 가지 박제 — 역할 분담

산출물작성자내용
-DONE.md AI 사실·결정·증상·키워드 박제. 잊히기 전에 자동 작성.
노션 자유 양식 또는 잔존 learning-journal/{본인}/ 본인 회고·교훈·면접 답변 (자율). AI는 질문만 던짐. 트랙 B 은퇴(ADR-025)로 자동 권유는 없음.

본인이 학습 일지 쓸 때 -DONE.md를 사실 베이스로 활용. AI가 박은 사실 위에 본인 회고를 얹는 구조.

3종 회고 양식 (자율 — AI 인터뷰 도움 가능)

옛 /journal:* 슬래시는 M3.5에서 제거 (ADR-022), 학습 추적 트랙 B 자체도 ADR-025로 은퇴. 다만 같은 3종 양식은 박고 싶을 때 그대로 활용 가능 — 본인 노션에 자유 양식으로 박고, AI 인터뷰 도움 필요하면 Claude에게 자연어로 요청.

  1. Phase 통째 회고

    Phase 하나 끝났을 때. 7개 질문 (한 줄 요약 / 새로 배운 것 / 막혔던 지점 / 결정 포인트 / 다시 한다면 / 아직 모르는 것 / 면접 시뮬레이션). 15~20분. Claude에게: "Phase 회고 인터뷰 도와줘".

  2. 개념 깊이 학습 <키워드>

    9개 질문 (한 줄 정의 / 처음 만난 맥락 / 비유 / 단계별 설명 / 흔한 오해 / 우리 코드 사용 / 면접 시뮬레이션 / 이해도 자가평가). 자가평가 솔직하게. Claude에게: "이 개념 학습 일지 인터뷰 도와줘".

  3. 트러블슈팅 서사 (버그 회고)

    막혔다가 풀린 사건. 10개 질문 (증상 / 재현 / 기대 / 가설들 / 진짜 원인 / 왜 헷갈렸나 / 해결 / 재발 방지 / 한 줄 학습 정수 / 면접 90초 답변). Claude에게: "이 버그 트러블슈팅 일지 인터뷰 도와줘".

✓ "잘 모르겠어요"도 학습

면접 시뮬레이션에서 답이 잘 안 나오면 솔직히 적기. 그게 다음 학습 큐가 됩니다. AI가 채워주는 답은 가짜 학습 — 본인 머리로 통과한 것만 면접에서 답할 수 있어요.

노션 박제도 따로 (선택)

본인 노션 "Dawnholder 협업 히스토리" 페이지에 STAR 형식 박제. 로컬 회고가 *디테일*이라면 노션은 *간결한 결정 박제*. 둘이 상호 보완. /session:log로 박음 (선택 — 자동 강제 X).

★ 본인 자산

노션 페이지는 각자 자기 노션. 팀 공유 X. 본인 포트폴리오·자기소개서 베이스로 활용.

08 — 막혔을 때

막히는 게 정상. 학습은 시간이 걸리는 거고 멍청한 질문 같은 건 없어요.

상황어디로
셋업 막힘/setup 다시 호출 또는 Claude한테 직접 물어보기
작업 중 개념 모름Claude한테 자연어로 — 예: "이 코드 한 줄씩 설명해줘" / "이 개념 학부 수준으로 풀어줘"
Claude 답이 어려움"더 쉽게 다시 설명해줘" 한 줄로 OK
지금 어디까지 왔는지 모름/session:start 다시 호출 (work-pin 자동 출력) 또는 "지금까지 진행 + 다음 할 일 정리해줘"
/session:start가 "work-pin drift" STOP을 띄움옛 work-pin 박힌 진행 단계(commit/push/PR 생성/PR 머지)가 실제 git/gh 상태와 어긋남 — work-pin(.claude/state/current-pin.txt)의 "현재 작업 / 다음 액션"을 본인이 갱신 후 재호출 (자동 갱신 안 함, ADR-023+025). 사용자가 명시적으로 "drift 봉합해줘"라 요청하면 Claude가 갱신 박음 OK
Git/PR 막힘 (일반)팀장(유영호)에게 슬랙
Git 충돌·복구 (pull 충돌, 작업물 사라진 듯, 잘못 commit)팀장 슬랙 우선. git reset --hard · git checkout . · git clean -fd 절대 금지 (되돌릴 수 없음)
Unity 켰더니 ProjectSettings.asset 변경 떴음cloud 라인만이면 자동 정리됨 (각자 Cloud 정책, B+). /session:start 게이트가 처리. cloud 외 변경(예: scriptingDefineSymbols)도 같이 떴으면 STOP 떠요 — 본인이 의도적으로 만진 게 아니면 팀장에게 물어보기
Unity 켰더니 ProjectVersion.txt 변경 떴음 (M)Unity 빌드 hash가 main과 다름. main의 03_Client/ProjectSettings/ProjectVersion.txt 두 번째 줄과 본인 머신 출력 비교 → 다르면 팀장이 안내한 딥링크(unityhub://6000.4.7f1/...)로 재설치. .gitignore로 가리지 마세요 — 신규 팀원이 다른 버전으로 프로젝트 열어도 막아주는 안전망이 깨짐
Image 컴포넌트 Inspector 띄운 채 코드 변경 → 콘솔에 NREUnity 알려진 이슈 (UUM-139557, 6000.4.7f1에도 잔존). 빌드/런타임 영향 없음 — 짜증만 남. 회피: 코드 변경 전 Inspector에서 Image 안 띄우고 다른 GameObject 클릭해두기
빌드 에러에러 메시지 그대로 Claude한테 보여주기
헌법/ADR 결정 이유 궁금Claude한테 자연어로 ("ADR-022 왜 박혔어?") 또는 00_Document/ADR/INDEX.md 참조
회고 박고 싶음 (Phase 끝 / 버그 풀린 후 / 개념 학습 후)본인 노션에 자유 양식 (자율 — 트랙 B 은퇴, ADR-025). AI 인터뷰 도움 필요하면 Claude에게 자연어로 요청. 잔존 learning-journal/{본인}/ 디렉토리도 그대로 사용 OK

Claude의 응답 톤 — 기대해도 됨

본인 헌법에 박혀있는 약속:

  • 친절·인내심 — 같은 질문 두 번 OK. 멍청한 질문 같은 거 없음.
  • 전문 용어는 첫 사용 시 풀어쓰기 — "직렬화(객체를 바이트로)..." 식.
  • 결정엔 항상 trade-off — "A를 골랐다"가 아니라 "A vs B 중 A, 이유는…, 단점은…".
  • 5단계 보고 — *대규모 등급 Phase 완료 시만* 🎯 무엇 / 🤔 왜 / 🛠️ 어떻게 / 🧪 테스트 / ➡️ 다음 (MD + HTML 이중 박음 = 캡스톤 평가 자산). 단순/보통/복잡은 work-pin + commit message로 충분 (ADR-022 양식 다이어트).

09 — 자주 묻는 것

Q. 본인 컴퓨터에 Codex CLI가 없는데 노션 박제 되나요?

됩니다. /session:log가 Codex 분기 / Claude 단독 분기를 자동으로 묻고 처리. 본인은 본인 노션 페이지 URL 또는 DB ID만 준비하면 됨.

Q. 헌법(CLAUDE.md) 읽어야 하나요?

한 번 정독 권장. 길지만 본인이 따라야 할 약속이 박혀있어서 안 읽고 시작하면 충돌 발생. 셋업 끝나고 첫 작업 시작 전에.

Q. ADR 문서들 다 읽어야 하나요?

아니요. 직접 읽지 않아도 OK. 일하다 "이건 왜 이렇게 돼있지?" 싶으면 Claude한테 자연어로 물어보면 관련 ADR 근거로 학부생 톤으로 알려줍니다.

Q. Phase가 너무 커요. 어떻게 쪼개죠?

한 Phase = 1~3시간 작업이 기준. 더 크면 /work:plan 다시 호출해서 재분해. 의심되면 더 작게 쪼개기.

Q. 작업하다 새 패킷 추가가 필요해요.

/work:new-packet <C2S|S2C> <PacketName> 호출. shared+server SubAgent가 양쪽 wiring까지 한 번에 처리 + shared-discipline-guard Hook이 PDL 의무 3종(PacketGenerator 재생성 + Shared.dll commit + Protocol.Version bump) 자동 점검. 본인이 직접 패킷 정의 만지지 마세요 — 그건 팀장 영역.

Q. 한국어로 답하는데 면접은 영어로 봐야 하는데요.

일단 한국어로 학습 일지 누적. 본인 영어 면접 준비 시점에 그 일지를 영어로 옮기는 게 효율적. 한국어로 일단 *생각이 박혀야* 영어로도 답할 수 있음.

Q. 본인이 잘못 박은 게 있으면 어떻게 정정하나요?

commit 안 했으면 그냥 파일 수정. commit 했으면 새 commit으로 정정 + 이유 commit 메시지에. CHANGELOG에 박혀야 할 수준이면 팀장에게 알리기. 부끄러워하지 말고 솔직히.

Q. Phase 06부터 진입하라고 했는데 그게 뭐예요?

M2-first-connection 마일스톤의 6번째 Phase. 01_Phases/youngho/M2-first-connection/06-input-replay-reconcile.md에 정의됨 (팀장 영역). /session:start 호출하면 현재 위치 자동 안내. 본인이 새 phase 만들면 01_Phases/<본인 네임스페이스>/M{N}-{slug}/에 — 팀원과 겹침 차단.
