⚠ 헌법 1번 — Server Authority
클라이언트는 단순 렌더러 + 입력 전달자. 데미지 계산 / HP 변경 / 아이템 생성 같은 권위 있는 상태 변경은 절대 클라에서 하지 않음. 클라가 prediction(미리 그림)은 OK, 단 서버랑 어긋나면 reconcile.

4 본인 트랙 — Dumb Client 보조 (핵심)

학습 목표

  • 백엔드/네트워킹을 보조하는 클라이언트 프로그래밍 — 서버가 권위, 클라는 그 결과를 멋지게 표시.
  • Unity UI · 입력 시스템 · 스프라이트/애니메이션 · 컨텐츠 표시 흐름 익히기.
  • 서버 패킷 → 클라 상태 → 화면 매핑하는 일반 패턴 학습.

팀장 권장 시작 흐름

1단계 → UI 세팅 (캔버스 / 메인 메뉴 / HUD 골격)
2단계 → 캐릭터 스프라이트 + 애니메이션 (idle / walk / jump / attack)
3단계 → 컨텐츠 작업 (몬스터 스프라이트 / 맵 타일 / 아이템 아이콘 등)

위 순서는 강제 X, 권장. 본인 의견 있으면 팀장과 의논 후 조정 가능.

해도 되는 것 vs 안 되는 것

✅ 본인이 하는 것
  • UI 캔버스 배치, 버튼/메뉴 핸들러
  • Unity Input System으로 입력 받아 *서버에 보낼 인텐트*만 만듦
  • 스프라이트/애니메이터 셋업
  • 서버에서 받은 위치/HP/인벤토리를 화면에 표시
  • 이펙트, 사운드, 카메라, 트랜지션
🚫 본인이 안 하는 것
  • 데미지 계산 (서버 권위)
  • HP / 인벤토리 / 골드 직접 변경
  • 아이템 생성 / 드랍 굴림
  • 패킷 정의 변경 (98_Shared/ 손대지 않음)
  • 서버 코드 (02_Server/, CODEOWNERS로 보호됨)

5 MVP 6개 중 본인이 닿는 부분

MVP 6개 다 되면 데모 영상을 찍을 수 있음. 본인은 클라 표시 레이어로 거의 모든 항목에 손댐 — 단, 권위 로직은 팀장.

1.계정+캐릭터 (서버: 인증·영속화)
2.이동+점프 ★ (클라: 입력·렌더링)
3.사냥+전투 ★ (클라: 이펙트·HP UI)
4.인벤토리+창고 ★ (클라: 슬롯 UI·드래그)
5.길드+거점 ★ (클라: 시설 배치 UI)
6.마을+사냥터 (클라: 맵 타일·portal UI)
본인 손대는 부분
팀장 단독 (백엔드)

6 절대 어기면 안 되는 5가지 (헌법)

이건 보안·동기화·핵 취약점 직결. 본인이 위반 요청해도 Claude가 거부함.

  1. Server Authority — 권위 상태는 서버. 클라는 표시·prediction만. 본인 가장 중요
  2. Protocol is Sacred — 패킷 ID 재사용 X, 호환성 깨는 변경 금지. 팀장 단독
  3. Trust Boundary — 서버는 클라 입력 다 검증. 팀장 단독
  4. Shared Code Discipline — 98_Shared/ 변경 시 양쪽 컴파일 확인. 팀장 단독
  5. No Blocking in Game Loop — 서버 틱(50ms)에 await·sleep 금지. 팀장 단독
