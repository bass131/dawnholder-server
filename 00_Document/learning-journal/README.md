# 📚 Learning Journal — 학습 일지 시스템

> **이 디렉토리의 역할**: 프로젝트를 진행하며 배운 것을 영구적으로 기록.
> 면접 어필용 + 본인의 진짜 학습 누적용.

---

## 왜 학습 일지가 필요한가

포트폴리오 프로젝트에서 **결과물의 절반은 학습의 흔적**입니다. 면접관이
보는 건:

- "결과물이 동작하나?" (코드)
- **"이 사람이 이 과정에서 무엇을 배웠나?"** (학습 일지)

두 번째가 없으면 "AI한테 시킨 거 아니야?" 의심을 받아요. 학습 일지는
**본인의 사고 과정과 성장 흔적**을 보여주는 가장 강력한 증거입니다.

추가로, 일지를 쓰는 행위 자체가 학습을 깊게 만들어요. 머리로만 이해한
것은 글로 쓸 때 갭이 드러나거든요.

---

## ⚠️ 이 시스템의 핵심 원칙

### 본인이 쓰는 게 핵심. AI는 도구일 뿐.

AI가 자동으로 채워준 학습 일지는 면접에서 들통나요. "이 부분 더 설명해
보세요"에서 본인이 못 답하면 신뢰가 무너져요.

그래서 이 시스템의 슬래시 커맨드들은 **"AI가 다 써주는" 방식이 아니라**:

1. AI가 **틀(구조)을 잡고**
2. AI가 **빈칸 채울 질문을 던지고**
3. **본인이 답한 것을 AI가 다듬어 문서화**

이 패턴을 따라요. 답을 모르면 모른다고 솔직히 적으세요. "이 부분은
다음에 더 공부해야 함" 같은 표시도 학습의 흔적이에요.

### 면접 답변 가능 여부가 검증 기준

각 일지를 다 쓰고 한 번 자문하세요:
**"이 일지에 적힌 내용을, 한 달 뒤에 면접관 앞에서 5분 동안 설명할 수 있는가?"**

못 한다면 그 일지는 아직 부족한 거예요. 본인 말로 옮겨 적거나, 더
공부한 후 갱신하세요.

## 3가지 문서 종류

각 종류마다 다른 면접 질문에 대응합니다.

### 1. Phase 정리 (`<milestone>/<phase>.md`)
**대응 질문**: "이 마일스톤/Phase에서 뭐 했어요?"

Phase 하나 끝날 때마다 작성. 무엇을 만들었고, 어떤 결정을 했고,
어디서 막혔고, 다시 한다면 어떻게 할지를 정리.

**커맨드**: `/journal:phase`

### 2. 개념 정리 (`<milestone>/concepts/<keyword>.md`)
**대응 질문**: "X 개념 설명해보세요" / "Y는 왜 그렇게 동작해요?"

`/learn:concept`나 `/learn:explain`으로 깊이 판 개념 중 **본인이 진짜 이해한 것**을
본인 말로 정리. 나중에 블로그 포스트로 발전시킬 시드.

**커맨드**: `/journal:concept <키워드>`

### 3. 트러블슈팅 (`<milestone>/troubleshoots/<date>-<slug>.md`)
**대응 질문**: "기억나는 어려웠던 버그 있어요?" / "디버깅 어떻게 해요?"

진짜 막혔다가 풀린 사건 기록. 증상 → 가설 → 시도 → 발견 → 해결의
서사. **면접 단골 질문에 즉시 답할 무기**.

**커맨드**: `/journal:bug`

## 워크플로우

### Phase 진행 중
- 막혔다가 풀리면 → 즉시 `/journal:bug`
- 새 개념 깊이 학습했다 싶으면 → 즉시 `/journal:concept <키워드>`

### Phase 끝날 때
- AI가 Phase 완료 보고 후 "일지 작성하시겠어요?" 자동 권유
- "응" → `/journal:phase` 자동 발동
- 본인이 답할 시간 없으면 "나중에" → 일단 Phase 클로즈, 나중에 일지

### 마일스톤 끝날 때
- `/learn:recap`으로 전체 흐름 점검
- 학습 일지가 빠진 게 있나 확인
- 마일스톤 단위 회고 추가 작성 (선택)

## 면접 활용 팁

학습 일지는 그냥 쌓아두면 안 돼요. **면접 전에 한 번 씩 정리**해서
"이 프로젝트에서 가장 자랑하고 싶은 5가지" 같은 형태로 추출하세요.

- README.md에 "개발 일지 하이라이트" 섹션을 두고 베스트 트러블슈팅
  3개의 링크.
- 블로그가 있으면 개념 정리 1~2개를 글로 발전시켜 게시. URL을
  포트폴리오에 박기.
- "어려웠던 버그 사례" 같은 코너로 트러블슈팅 정리를 모아두면 면접관이
  시간 5분 더 봐줘요.

## 일지를 안 쓰면 어떻게 되나

코드는 동작해도, 면접에서 다음 질문에 답을 못 해요:
- "왜 raw TCP를 골랐어요?" (ADR에 있지만 본인이 외워야 답)
- "Lag compensation 어떻게 구현했어요?" (코드는 있지만 설명 못 함)
- "이 프로젝트에서 가장 어려웠던 게 뭐였어요?" (기억 안 남)

이 답들이 안 나오면 **"이 친구가 진짜 만든 게 맞나?"** 의심을 받아요.
일지가 그걸 막아주는 보험이에요.
