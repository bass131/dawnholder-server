# ADR-034: 하네스 원칙과 목표 종료 점검 채택

**결정일:** 2026-10-03 · **기록일:** 2026-10-04 · **상태:** 사용자 결정 채택, 구현·검증 상태는 [goal](../../../01_Phases/goals/2026-10-03-harness-principles/goal.md)에서 확인한다.

## 배경과 결정 근거

SQL 가독성과 과거 급히 만든 코드의 유지보수성을 개선하려면 지침뿐 아니라 실제 확인 수단이 필요하다는 사용자 판단에서 시작했다. DB 저장소·연동 완성을 게임 콘텐츠의 선행 경로로 두고, 다른 품질 작업은 그 소유와 순서를 막지 않도록 조율한다. 외부 글은 선택의 참고이며 프로젝트 권한의 원천이 아니다.

결정은 메인이 전달했다. 원칙·DB 우선·Gardener는 `msg_c9bc79f8ec43`, 첫 범위 보정은 `msg_c1412c982ac5`, 현재 범위 원칙은 `msg_238982aa5d26`, 이관·점검은 `msg_168d9aa35710`, 중간 점검 후 운영 PR 착수는 `msg_063d3c6e4829`다. 사용자 직접 입력과 메인 전달을 구분하고 [goal의 원문 매핑](../../../01_Phases/goals/2026-10-03-harness-principles/goal.md#정본-반영-전-적용-중인-사용자-결정)으로 추적한다.

## 채택한 원칙

1. 반복 규칙 중 판정 가능한 부분을 검사로 만들고, 실패 진단에 고치는 방법을 적는다.
2. 정본 helper·생성기·구조를 쓰는 경로가 가장 쉽게 발견되고 사용되도록 한다.
3. 수기 경로 목록에는 실제 존재를 확인하는 드리프트 검사를 연결한다.
4. 새 검사는 warning 파일럿의 실측 뒤 error 승격을 판단한다. 비용이 가치보다 크면 강등을 검토하며, 실행 불가와 규칙 위반은 다른 상태로 기록한다.
5. 구조 변경과 동작 변경을 다른 커밋으로 나누고 보존 동작의 근거를 남긴다.

진행 중 단계는 마치고 각 파트의 다음 작업 계약부터 승인 범위 안에서 적용한다. 주석 정책은 유지한다. 규칙 문서와 스킬만으로 행동의 기술적 강제나 미래 세션의 준수가 보장된다고 하지 않는다. 기존 PS 진단의 CI 실패 동작을 이 결정으로 자동 완화하지 않으며, 현재 설정과 파일럿 도입 원칙을 구분한다.

원칙의 코드 기준은 [CODE_CONVENTION](../../conventions/CODE_CONVENTION.md), 목표·검증·점검은 [goal-loop](../../../.agents/skills/dawnholder-goal-loop/SKILL.md), 역할·권한은 [AGENTS](../../../AGENTS.md)가 소유한다. 외부 원문·반론과 미확인 범위는 [참고 색인](../../conventions/refs/agent-engineering/_index.md)으로 분리한다.

## 검토한 대안과 비용

아래는 goal에 보존한 기존 결정 이유를 기록한 것이다. 새로운 도입 승인이나 이번 구현 성과를 뜻하지 않는다.

| 대안 | 당시 판단과 현재 경계 |
|---|---|
| 검사를 모두 별도 목표로 미룬다 | 그동안 새 코드가 검사 없이 쌓일 수 있다. 승인된 변경의 검출 가능한 경계부터 연결하고 무관한 전면 정리는 제외한다 |
| 뷰어를 먼저 보강해 구조 우려를 해결한다 | 경계 검사가 유지보수성 문제에 직접 대응하고 기존 구조 스냅샷을 재사용할 수 있다는 판단이었다. 이 ADR 자체가 뷰어나 경계 검사 구현 완료를 뜻하지 않는다 |
| Gardener를 주간 예약으로 실행한다 | 전체 goal 종료를 자연 점검 지점으로 선택했다. 신규 읽기 전용 Opus·보고 하나·최대 두 후보의 네 주 시범이며 사용자 채택을 거친다 |
| 메인이나 리드가 구현을 직접 대신한다 | 작성과 독립 검증의 분리를 유지한다. 지정 작업자의 한정 capacity 예외는 운영 정본을 따르며 리드 직접 구현으로 확대하지 않는다 |
| legacy 전체를 일괄 archive로 옮긴다 | 앞선 안에서는 지정 통합으로 경로/manifest 비용을 줄이려 했다. **최신 범위 결정은 통합·삭제·보관 자체를 다음 계획으로 이관했다.** 이 ADR로 과거 승인을 다시 실행하지 않는다 |

추가 검사에는 구현·실행·유지 비용과 오탐 위험이 있고, 독립 세션에는 시간과 비용이 든다. 반대로 미검증 변경을 빨리 쌓으면 근거와 책임 경계를 복원하기 어렵다. 현재 사용자는 속도보다 완성도를 우선했다. 가독성·테스트 품질·실제 통합은 검사 건수나 단일 점수로 대체하지 않는다.

## 보류와 적용 범위

- 검증 강도 차등·작은 작업 예외·규칙 문서 가지치기·사람용 코드 따라읽기는 별도 사용자 결정이다.
- 세 파트 PS 정리 이후의 All 비교·정책 승격·근거 인용/집계 helper는 [BACKLOG](../../operations/BACKLOG.md)의 별도 후보다. 현재 goal 종료조건으로 합치지 않는다.
- ADR-035의 영속성 사실 정리는 GameDev 첫 SQL 구조 PR 병합 뒤다. 환경/경로 검사와 PowerShell 출력 순서는 같은 goal의 별도 PR 단위다.
- Gardener 세부 권한과 평가 시점은 [선택 근거](../../conventions/refs/agent-engineering/gardener.md)와 운영 정본을 따른다. 자동 병합·승인 없는 예약 작업은 채택하지 않는다.

이 ADR은 ADR-028의 코드 규칙·참고자료 분리를 유지하면서 에이전트의 작업 환경과 피드백에 대한 선택 이유를 더한다. 실제 커밋·독립 판정·CI·병합·미실행 범위는 goal 한 곳에서 확인한다.
