### ADR-023: work-pin/CONTEXT 동기화 결함 — 진행 단계 stale hole 봉합

**날짜**: 2026-05-22
**상태**: 채택됨 (발효 = M3.7 Phase 02 commit)

**결정**: M3.5 Phase 05에서 박힌 옵션 C 게이트 (`work-pin → CONTEXT.md` 단방향 동기, `/session:end` 단일 게이트)는 **유지**. 옵션 C 게이트가 *세션 마감 시점*만 잡고 *세션 도중 진행 단계*(commit / push / PR 생성 / PR 머지)는 못 잡아 work-pin이 stale로 박히는 결함을 발견 게이트로 **보강**. 새 발견 게이트 = `/session:start` 0-부수 단계 (M3.7 Phase 01 산출물) — 세션 시작 시점에 `git log -3` + `gh pr list --head $(branch)` + `git status -sb` 자동 호출 → work-pin "현재 작업 / 다음 액션" 키워드 vs 실제 상태 대략 매칭 → 차이 발견 시 STOP + 본인 수동 갱신 안내. **자동 갱신 박지 않음** (헌법 정신 = `pin-and-done.md` §1 "갱신은 본인 수동" / Hook is for alert, not action). 사용자 명시 위임("drift 봉합해줘") 시 예외 허용.

**이유**: 옵션 C 게이트(ADR-022 새 하네스 v1 + M3.5 Phase 05 박힘) 5번 실측 결과 — (1) M3.6 Phase 06 자기 work-pin "외부 리뷰 4건 흡수 약속" 가짜화 (5번째 false-promise 사례). (2) M3.7 진입 시점 (본 ADR 박힘 시점) work-pin "commit + push + PR 게이트 4-D/4-E/4-F 대기"라 박혔지만 실제 4단계 모두 박힘 (PR #44 MERGED 2026-05-22 03:58 UTC). (3) M3.5 → M3.6 진입 시 work-pin "M3.5 마감 직후" 잔재가 다음 세션 첫 응답까지 stale. (4) M3 Phase 마감 commit 직후 work-pin "commit 박을 예정" 잔재 ~수십분 stale. (5) Phase 06 PR 머지 후 work-pin "PR 머지 게이트 대기" 잔재. **5번 누적 = Rule of Three 통과** (옛 운영 학습 패턴 = M3.5 `cross-review-rule-of-three` 정합) → 본질 봉합 트리거 ON. 옛 운영 *발견은 본인 수동 PR 리스트 체크 의존*이라 빈도 ↓ → 본 ADR이 자동 발견 박음 + 본인 인지 게이트 보호 (학부생 호흡 유지 정신). 갱신을 Hook 자동화로 박지 않은 이유 = (a) 학부생 인지 게이트 우회 위험 (자동 박힌 work-pin은 사용자가 의도 모르고 stale 이어받음), (b) Hook 복잡도 ↑ (post-commit/post-push/gh-pr-create 시점 매처 다중), (c) work-pin 잦은 rewrite 노이즈 (작업 중간 work-pin이 자동 변하면 *다음 턴 컨텍스트 상단*이 흔들림 = 자동 주입 의도 위반).

**트레이드오프**: 본 ADR은 *발견*만 자동 + *갱신은 본인 수동*이라 사용자가 `/session:start` *호출 안 한* 세션은 여전히 stale로 출발 (예: 본 ADR 박힘 후에도 사용자가 매 세션 시작 시 `/session:start` 호출 의무화는 X — 본인 호흡 의존). **모니터링** = 다음 마일스톤(M4) 마감에서 stale hole 0건이면 본 ADR 성공. 1건+ 발견 시 후속 봉합 (옵션 A Hook 자동 갱신 재논의 또는 옵션 B work-pin 양식 다이어트 재논의). 본 게이트 자체 false positive 위험 = work-pin "현재 작업" 자유 양식이라 키워드 대략 매칭이 *없는데 STOP 띄움* 또는 *있는데 못 잡음* 가능 — 본인 인지 게이트가 최종 판단 (STOP 띄워도 본인이 "정합이에요" 판단하면 무시 OK, `/session:start` 재호출 시 다시 발견). `gh` CLI 의존성 = 본 게이트는 `gh` 박힌 환경 전제, 미박힘 환경(인규 합류 시점) `setup-steps/`에 박혀있는지 별 시점 점검 의무. 본 ADR 묶음 = ADR-024 (false-promise 주기적 감사 cadence)와 같은 M3.7 마일스톤에서 동시 박음, 두 ADR이 *같은 가짜 약속 시리즈*의 두 시각 봉합 (ADR-023 = 진행 단계 stale, ADR-024 = 약속 누적 가짜).
