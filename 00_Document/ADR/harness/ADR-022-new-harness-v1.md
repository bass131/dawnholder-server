### ADR-022: 새 하네스 v1 (M3.5 — 5/20 의논 결과 + NDREAM 패턴 흡수 + 작업 KPI 전환)
**날짜**: 2026-05-21
**상태**: 채택됨 (발효 = M3.5 Phase 06 전환 commit)
**결정**: M3 First Multiplayer & Demo Stage 마감 (2026-05-20, PR #41 main `ac2d302`) 후 5/20 면담 의논에서 박힌 *새 하네스 v1 모델*을 별도 마일스톤 M3.5(`youngho/harness-v1` 브랜치, Phase 01~06 = 6 Phase 분해)로 박고 격리 폴더 `01_Phases/youngho/M3.5-harness-v1/New_Harness/`에 누적한 산출물 풀세트를 Phase 06 전환 commit으로 일괄 mv하여 *옛 운영 100% 작동 유지 → 새 운영 100% 발효* 게이트 통과. 6 핵심 변경: (1) **KPI 전환** — "학습 박제 중심" → "Planning → 구현 → 보고" (학습은 트랙 B로 분리). (2) **정량 4등급 + 위험 깃발 자동 상향** — 단순/보통/복잡/대규모 (정량) + trust-boundary/irreversible/unity-asset (위험 깃발 → 등급 자동 상향, `risk-detector.sh` Hook 강제). 양식 부담 + 동원 패턴이 등급에 *조건부*. (3) **SubAgent 풀 9 (옛 7 → 새 9)** — Worker 4 (server/shared/client/qa, 옛 6 도메인 통합) + Reviewer 2 (reviewer/plan-auditor, Codex γ *내부 흡수*) + Specialist 3 (unity-bridge—Phase 08 BackGround prefab 사고 학습 정합 / coordinator—NDREAM 패턴 / knowledge-gc). 모델 분담 = Sonnet (Worker + knowledge-gc) / Opus (Coordinator + Reviewer + plan-auditor). (4) **Hook 인프라 풀세트 7 (옛 5 → 새 7)** — rename 3 (`inject-current-pin → pin-injector`, `validate-phase-gate → phase-gate-validator` 강화, `validate-shared-changes → shared-discipline-guard` 경고→차단) + 삭제 2 (`check-server-authority` Reviewer 흡수, `check-work-envelope` 양식 죽임) + 신설 4 (`dangerous-cmd-guard`, `tdd-guard`, `circuit-breaker`, `risk-detector`). (5) **Knowledge 시스템 신설** — `.claude/knowledge/<domain>/_index.md` 5 도메인 (cross-cutting/server/shared/client/qa) + `_usage.md` + `knowledge-gc.md` SubAgent (수동 트리거만, AI 자율 박제 X = `seed-with-restraint-pattern` 정신). 트랙 A (AI 캐시, 구조화 패턴) vs 트랙 B (본인 회고, learning-journal/ + 노션) *분리* — 같은 사건 양쪽 박힐 수 있으나 시각 다름 (가짜 학습 방지). (6) **슬래시 다이어트 17 → 10 + 신규 2** — 작업 4 (옛 4 유지 + 옛 `/work:review` → `/harness-review` rename·강화) + 세션 3 (유지) + 점검 2 신설 (`/harness-review` 하네스 자체 점검 + `/cross-review` 외부 시각, Rule of Three 통과 후 슬래시화) + 셋업 1. 옛 학습 5 + 일지 3 = *트랙 B Notion 이관* (잔존 `learning-journal/{본인}/` 디렉토리는 옛 자산 보존 정신으로 *그대로 유지*). (7) **양식 다이어트** — work-envelope 절 통째 *죽임* (옛 매 코드 응답 양식 봉투 → 새 = 등급별 분기). 5단계 보고 = *대규모 등급 Phase 완료 시만* 박음 + MD+HTML 이중 박음 (캡스톤 평가 자산). work-pin 압축 (옛 60~70줄 → 새 30~40줄 목표). (8) **work-pin ↔ CONTEXT 정합 게이트 (옵션 C)** — `/session:end` 단일 게이트에서 단방향 동기 (work-pin → CONTEXT의 "⏸️ 현재 멈춤 지점"). 등급 무관 항상 동기 = Claude 혼선 방지가 양식 부담 ↓보다 우선. (9) **Phase 폴더 namespace** — `01_Phases/<owner>/M{N}-{slug}/` + frontmatter `owner: youngho|yuhyeon|inkyu` 필수 + `grade:` `risk:` 박음. (10) **헌법 부분 갱신** — 절대 원칙 5개(서버 권위/프로토콜 신성/신뢰 경계/공유 코드 규율/틱 블로킹) *글자 그대로 100% 보존* (`constitution-partial-update-trap` 학습 정합). 헌법 본체에 등급 4 + SubAgent 9 + Knowledge 시스템 + 위험 깃발 절 신규 박음 → 옛 200줄 → 새 239줄 (+39줄, *증가 정당* — 본체 다이어트 X, 운영 양식 절은 다이어트).
**이유**: 5/20 교수 중간 면담 통과 + M3 마감 직후 *바이브 도메인 시대 인식*과 *팀 합류 흡수* 흐름에서 옛 하네스(개인 학부생 1인 운영용)가 *팀 협업 + AI 자동화 본격화* 단계와 어긋남이 4 곳에서 표면화: (a) SubAgent 옛 6개 (netcode/gameplay/client/content/persistence/qa-sim) 도메인 모호 (98_Shared/ 누가? Unity asset 누가? 메인 세션 분해 부담은?) → 새 9개 카테고리화 (Worker/Reviewer/Specialist) + 3축 정의(도메인+권한+모델) 강제. (b) Codex γ 외부 의존 (3~7회차 누적 실측) → `plan-auditor` SubAgent로 내부 자산화. (c) 옛 헌법 #2 ProtocolVersion handshake + #4 Shared Code Discipline + Handlers/ 폴더 "주석으로 박힌 약속이 가짜다" 3회 봉합 시리즈 (M3 Phase 02+03 + 정유현 5/17 사고) — 정책이 *물리적 강제*되지 않으면 가짜화 → 새 7 Hook으로 정책의 물리적 강제. (d) 옛 학습 5 + 일지 3 슬래시 = *학습 토큰 절약 슬래시* 본질이지만 KPI 전환(Planning→구현→보고)과 어긋남 → 트랙 B로 이관 (옛 자산 보존, 새 트랙 추가, 옛 슬래시만 제거 = `track-b-migration-without-asset-loss`). NDREAM 하네스 PDF 패턴 참조 = *직접 카피 X*, 정신 흡수 (Coordinator 패턴 / Knowledge 시스템 / 등급별 처리 / 모델 분담). 팀 합류 흡수 = 영호(server/shared) + 유현(client) + 인규(client + ComfyUI 자산) 영역 분리 + Phase 폴더 owner namespace + Unity asset 위험 깃발 자동 상향. KPI 전환의 *현실적 정당화* = M3까지 18+ ★★★ 학습 누적 (Phase 06~08 + γ 6~7회차 + 5/20 의논 + M3.5 Phase 01~05 신규 ★★★ 18건) — 충분히 박힌 학습 자산을 *과제 진척 정체로 만들지 않게* 박는 본질에서 KPI 자체를 전환. M3.5 Phase 01~05 풀세트 (commits 223729d → 78f7394) 격리 폴더 안에 본체 박은 후 Phase 06 전환 commit으로 *옛 100% → 새 100% atomic 발효* = `isolation-folder-migration-pattern` (DB dual-write phase 정신). 면접 자산화 = *바이브 도메인 시대 인식 + 투트랙 분리 + Zero-based 재구성 + 팀 합류 흡수*의 *방향성 결정 + 리팩터링 의사결정* 어필 결정타 (한국 게임 회사 백엔드 면접 단골).
**트레이드오프**: 본 결정 자체가 *큰 마이그*라 전환 commit 시점이 폭발 위험점 — 한 시점에 옛 자산 67개 삭제 + 17개 갱신 + 24개 신규 = 108 파일 변경. 검증 = dotnet build green + dotnet test 170+ PASS + 새 슬래시/SubAgent/Hook 최소 1회 실측 (Phase 06 마감 조건). 옛 운영 깨뜨림 위험은 격리 폴더 패턴 + Phase 01~05 누적 박음 + 본 전환 commit *atomic*으로 완화. 새 hooks 7개 명세는 M3.5 박힘 시점 *실측 0건* — false positive 빈도 (특히 risk-detector 등급 상향 마찰 / circuit-breaker 정당 반복 알림) M4 진입 후 첫 1주 안 관찰 → 명세 재조정 필요. SubAgent 9 풀세트 명세도 *실측 0건* — 합류 후 1~2회 발동 관찰 → 트리거 조건 재조정 (ADR-019의 추측 기반 명세 학습 정합). knowledge 시스템 신설은 *유기적 누적 정신* (`seed-with-restraint-pattern`) — 처음부터 풀세트 X, 시드 8건만 박고 작업하며 누적. AI 자율 박제 차단 (`ai-self-reinforcement-bias-prevention`) = 사용자 확인 게이트 3 트리거. 양식 다이어트(work-envelope 죽임 / 5단계 보고 조건부)는 *양식 가치 vs 노이즈 평가 학습* (`format-cost-evaluation`) — 모든 양식 죽일 수 있다는 정신 박힘. 슬래시 학습 5 + 일지 3 트랙 B 이관 = 옛 학습자(인규/유현 합류 직전) 학습 흐름 일시 변화 (자연어 질문 + 노션 자유 양식 + AI 인터뷰 도움 = 본인 회고 흐름 그대로). 옛 모든 팀원 영향 = CHANGELOG [H] entry + 슬랙/디스코드 동반 안내 의무. 본인 단독 통제 (영호) = 헌법/SubAgent/Hook/`/harness-review` 모두 영호만 통제 (M3.5 마감 후 별 시점 협의 가능). M4 진입 후 새 하네스 *진짜 4맵 + 정밀 전투* 첫 실측 = 새 모델 *효과 증명 1회차*. 옛 *학습 박제 중심* 모델이 캡스톤 평가 자산 누적엔 효과적이었으므로 새 KPI가 *학습 박제 효과 ↓* 위험은 있음 — 트랙 B(노션 + learning-journal/) 분리로 학습 박제 자체는 *지속*하되 *작업 흐름 KPI에서 제외*만 분리. 외부 리뷰 mini-Phase 4건 (`Dawnholder-harness-review-2026-05-19.md`)은 M3.5 후속 별 처리 (M4 backlog와 분리).
