### ADR-024: false-promise 주기적 감사 cadence

**날짜**: 2026-05-22
**상태**: 채택됨 (발효 = M3.7 Phase 02 commit)

**결정**: false-promise 패턴(*주석 / 문서 / work-pin / -DONE.md에 약속 박혀있는데 코드 / Hook / 실재 자산에는 없음*) 발견 시 **즉시 봉합**(옛 운영 그대로) + **주기적 감사 cadence 박음**(본 ADR 신규). cadence 2 트리거: (1) **마일스톤 마감마다 자체 감사** — 본인 + (옵션) plan-auditor SubAgent 자동 호출. 검사 = "약속 박힌 .md 파일 × 실재 코드/자산 grep". 결과 박음 = 마일스톤 마감 `-DONE.md` 안 "false-promise 점검 결과" 섹션 의무(0건도 박음). (2) **ad-hoc X건 누적 트리거** — false-promise 발견 누적이 직전 점검 후 +5건 이상이면 ad-hoc 점검 마일스톤(M3.6 같은 형태) 신설 트리거. **자동화 도구는 본 ADR 박지 않음** (별 시점 작업) — 옵션 = plan-auditor SubAgent에 false-promise 감사 책임 추가 (M5+) 또는 별도 슬래시 `/audit:false-promise` 신설 (M5+).

**이유**: false-promise 발견 시리즈 누적 12건+ 박힘 — M3 Phase 02 (헌법 #2 ProtocolVersion handshake 봉합) / Phase 03 (헌법 #4 Shared Code Discipline 봉합 + 정유현 5/17 Shared.dll .gitignore 사고) / Phase 04 (Handlers/ 폴더 가짜 약속 봉합) + M3.6 Phase 02 (헌법 #4 한계 = `02_Server/*/Handlers/*` 매처 stale 봉합) / Phase 04 (forward 3 + 역방향 2 + 시기상조 1 = 6변종) / Phase 05 (4번째 변종 = 문서 자기 불일치) / Phase 06 (5번째 사례 = 자기 work-pin 약속 가짜화). **Rule of Three 통과 3회** (3 변종 + 4 변종 + 5번째 사례) + **4번째 변종 발견** + **5번째 사례 누적** = 누적 트리거. 옛 운영 *발견 시 즉시 봉합*만 박혀있고 *주기적 감사* 정책 X → 발견이 본인 ad-hoc 시점(점검 마일스톤 또는 우연)에 의존 → 12건+ 누적이 그 의존성의 비용 증거. 본 ADR이 cadence 정책 박음 = (a) 마일스톤 마감 = 자연스러운 점검 시점 + 양식 부담 ↓ (이미 -DONE.md 박는 의례 안 통합), (b) ad-hoc X건 누적 = 자기 강화 안전망 (점검 자체가 점검 미발화로 누적되는 함정 차단). 점검 마일스톤 M3.6 자체가 *cadence 정합 시범*이었음 (별 시점 backlog 4건 흡수 + false-promise 7건 발본) = `audit-milestone-purpose-validation` 학습 정합. 본 ADR이 그 정신을 정책 영구화.

**트레이드오프**: cadence 정책만 박음 + 자동화 도구 박지 않음 = 본 ADR 자체가 false-promise 위험 (cadence 약속 박혔는데 점검 안 하면 본 ADR이 가짜 약속 = 자기 참조 함정). 봉합 = -DONE.md "false-promise 점검 결과" 섹션 **의무**(0건도 박음) → 점검 누락 시 `phase-gate-validator.sh` 후속 보강으로 차단 가능 (별 시점 작업, 본 ADR 박음 X). **모니터링** = 다음 마일스톤(M4) 마감 -DONE.md에 점검 결과 섹션 박힘 + 누적 그래프 (M3 5건 → M3.6 7건 → M4 ?건) 확인. M4 마감 시 false-promise 누적 = 12건+ + N건 추세로 cadence 효과 정량. ad-hoc 트리거 +5건 누적 임계는 *추측 정책* — M4~M5 실측 후 재조정 가능. 본 ADR 신설 = 별 시점 액션 #5 (work-pin 박힌 약속) 봉합 = 그 자체가 *별 시점 약속 → 본 시점 봉합* 1건 사례 (메타 false-promise 발본). plan-auditor SubAgent로 자동화 위임은 매력적이나 plan-auditor의 현재 책임은 *Phase 정의 `.md` 사전 검증*이라 false-promise 감사 흡수가 책임 비대 위험 → 별 SubAgent 또는 별 슬래시가 정합 (M5+ 결정).
