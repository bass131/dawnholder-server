### ADR-021: 클라이언트 UI는 별도 Additive Scene으로 분리
**날짜**: 2026-05-17
**상태**: 채택됨
**결정**: 클라이언트의 게임 내 UI(HUD, 추후 PauseMenu / Settings / Inventory 등)는 별도 **`Assets/Scenes/UI.unity`** 전용 씬에 박고, 게임플레이 씬에서 `LoadSceneMode.Additive`로 런타임 자동 로드. 트리거는 `Scripts/Bootstrap/SceneBootstrap` MonoBehaviour가 게임플레이 씬에 부착되어 `Awake()`에서 `SceneManager.LoadSceneAsync("UI", LoadSceneMode.Additive)` 호출. 멀티 씬 편집 중 중복 로드 회피용 `GetSceneByName(...).IsValid() && isLoaded` 가드 박힘. Phase 03에서 Gameplay 씬에 박았던 HUD Canvas + 4 자식(HpSlider/HpText/GoldText/MinimapPlaceholder) + HudController + EventSystem을 UI 씬으로 이사. `Scripts/Bootstrap/` 폴더 신설(`03_Client/CLAUDE.md` Layout 표 갱신은 팀장 영역이라 PR 시점에 동반 갱신 권유). CODEOWNERS에 `/03_Client/Assets/Scenes/UI.unity`, `/03_Client/Assets/Scripts/Bootstrap/`, `/03_Client/Assets/Scripts/UI/` 3 경로를 `@yuhyeon` 단독 영역으로 박아 팀장(@bass131)·@ingyu도 PR로 못 만짐. `Assets/Scenes/Gameplay.unity` / `MainMenu.unity`는 캐릭터·맵·게임 로직이 들어오므로 *공유 영역 유지*. 본 결정은 정유현 본인 작업 중 Phase 03 마감 직후 *영역 분리* 가치 자각 → 팀장 합의 완료(2026-05-17, 슬랙) 후 ad-hoc 작업(`ad-hoc-20260517-ui-scene-split`)으로 박음. CHANGELOG는 팀장 영역이라 본 ADR 박힌 후 팀장이 [M] 한 줄 추가 권유.
**이유**: Unity의 `.unity` 씬 파일은 YAML 텍스트라 git merge가 *일단 시도는* 하지만 fileID 충돌 / 컴포넌트 직렬화 순서 어긋남 / 자식 GameObject 추가 순서 차이 등으로 *자동 머지 실패율 높음* → 같은 씬을 두 명이 동시 수정하면 충돌 마커가 박힌 .unity 파일이 Unity Editor에서 *깨진 씬*으로 열림. M1 진행 중 정유현(클라 UI/입력)과 팀장(서버 코어 + 가끔 클라 캐릭터/맵) 양쪽이 Gameplay.unity를 *동시*로 수정할 비제로 가능성(예: 팀장이 플레이어 발판 추가 + 정유현이 HUD 수정) → 영역 분리로 *물리적 차단*하는 게 한국 게임 회사 정석 패턴(씬 하나당 한 명). DontDestroyOnLoad 전역 UI 대안(옵션 C) 대비 *씬마다 다른 UI*(보스전 전용 UI 등) 가능성 열어둠 + Phase 04~05의 PauseMenu / 씬 전환 페이드 모두 같은 UI 씬에 누적 가능. UI Prefab 분리 대안(옵션 B) 대비 *씬 자체에 prefab 참조 한 줄*도 없애서 충돌 영역 0. Phase 03 HUD 박은 후 *즉시* 분리한 이유는 헌법 "scope 늘면 새 Phase" 원칙 — Phase 03을 갈아엎지 않고 ad-hoc로 분리해서 *결정 흐름 깔끔*(Phase 03 마감 박제 + ad-hoc 분리 박제 두 사건이 분리됨). 정유현 본인이 *왜 분리가 필요한지* 떠올린 사건 자체가 협업 감각 자라는 학습 신호로 박힘.
**트레이드오프**: 씬 2개 동시 관리 복잡도 ↑ — Editor 멀티 씬 편집 패턴 학습 필요(학부생 학습 가치로 상쇄, 면접에서 *왜 분리했나* 설명 자산). `SceneBootstrap.Awake()` → `LoadSceneAsync` 비동기 호출로 *HUD가 게임플레이 시작 후 한 프레임 정도 늦게* 그려짐(체감 미미, 페이드 인 시점에 가려짐). UI 씬과 게임플레이 씬 간 GameObject 참조 시 `FindObjectOfType` / `SceneManager.GetSceneByName(...).GetRootGameObjects()` 등 *씬 간 통신 패턴* 필요 — 다음 마일스톤에서 서버 데이터 → HudController.UpdateHP 호출 시점에 *어떻게 HudController를 찾을지* 결정 필요(현재 미해결, M2+ 진입 시 본인 결정). MainMenu→Gameplay 전환 시 `LoadSceneMode.Single`이 기존 씬 unload → UI 씬도 unload → SceneBootstrap.Awake가 다시 UI 씬 로드 → *씬 전환마다 UI 씬 재로드* 비용(작은 씬이라 미미, M2+에서 UI 씬 커지면 재검토). Editor 멀티 씬 편집 중 Play 누르면 *이미 UI 씬 열려있어서* 가드가 동작 → 빌드 런타임과 다른 경로 → *Editor 검증과 빌드 동작이 미세하게 다름*(가드 자체 검증을 Editor에서 한 번, 빌드에서 한 번 권장). `Scripts/Bootstrap/` 폴더 신설로 `03_Client/CLAUDE.md` Layout 표가 *살짝 일탈* 상태 — 팀장 영역이라 본 ad-hoc 범위 밖, PR에서 동반 갱신 안내. `Assets/Scenes/UI.unity`를 `@yuhyeon` 단독 영역으로 박아 *팀장도 PR로 못 만짐* → 팀장이 UI에 디버깅 도구 박을 일 생기면 본인 PR 통과 필요(M1 단계에선 발생 거의 X). 영역 분리는 *학습 단계*에서 명확하지만 *프로젝트 후기* 합류자가 많아지면 단독 영역 패턴이 PR bottleneck 위험 — M3+ 시점에 *영역 정의 재검토* 후보.
