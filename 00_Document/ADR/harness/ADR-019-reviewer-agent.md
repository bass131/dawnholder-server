### ADR-019: Reviewer 에이전트 도입 (Tier 2 자동 리뷰)
**날짜**: 2026-05-15
**상태**: 채택됨 (단, M3.5 Phase 06 / ADR-022로 *부분 갱신*: work-envelope 양식 죽임으로 본 ADR 본문의 "work-envelope에 리뷰 스킵 사유 기록" 우회 메커니즘이 죽음 → 새 운영에서는 **work-pin 또는 commit message로 사유 박음**. **Tier 2-A reviewer + Tier 2-B plan-auditor 자동 호출 5축 골격 자체는 유지** + 본 ADR이 박은 *Codex 코드 컨벤션 검증은 Roslyn analyzer 별 도입* 결정도 유지. 새 운영에서 plan-auditor가 사전 검증, reviewer가 사후 검증으로 분리 강화. **M3.6 Phase 03-B 4-5 박힘**: Hard hook 신설 (`.claude/hooks/reviewer-auto-trigger.sh`) — 옛 Soft (메인 세션 판단)만 박혀있던 자동 호출이 *까먹기 위험*이라 PostToolUse Edit/Write 시 무조건 호출 트리거 (98_Shared/ + 02_Server/Handlers/ + Protocol + GameSession.cs) *알림 + 누적*까지 Hook 강제. SubAgent 직접 호출 권한은 메인 세션 유지 (Hook 권한 한계). 정유현 5/16 합류 → 5/22 = "합류 후 첫 주 안정화 후 추가" 약속 봉합.) — *정적 트리거 매트릭스 부분 superseded ([ADR-032](ADR-032-loop-driven-operation.md), 2026-06-18): 무조건/조건부/스킵 → 예외기반·신뢰졸업 throughput 모델. reviewer 5축 본체·R-only는 보존*
**결정**: 시니어 피드백("검증 부실 — 리뷰어로 1차 검증")에 대응해 **3-Tier 리뷰 구조**를 도입. (1) **Tier 1 도메인 셀프리뷰**: 도메인 에이전트가 코드 변경 직후 자기 영역의 헌법 위반 자체 점검 (합류 후 도입). (2) **Tier 2 자동 통합 리뷰**: 신규 `reviewer` 서브에이전트(`.claude/agents/reviewer.md`)가 격리 컨텍스트에서 [`00_Document/REVIEW_CHECKLIST.md`](../../REVIEW_CHECKLIST.md) 기반 5축 점검(헌법/ADR/구조/테스트/패턴). 메인 세션이 *조건부로* 자동 호출: 무조건 호출(`98_Shared/` 변경, 새 핸들러/패킷/공식, 사용자 명시 요청) / 조건부(≥10줄 변경) / 무조건 스킵(테스트 파일만, 주석/오타/rename, 사용자 우회). 사용자 우회(S-1)는 *사유 명시 후* 허용 — `work-envelope`에 `리뷰 스킵 사유: <한 줄>` 기록, `grep "리뷰 스킵 사유"`로 우회 습관화 감지. (3) **Tier 3 수동 깊은 리뷰**: 기존 `/work:review` 슬래시 커맨드 유지 — Phase 단위 상세 보고. 입력 약속 `range / files / diff_summary` 3종 — reviewer는 추측 없이 즉시 종료 가능. 읽기 전용 권한(Read/Glob/Grep/Bash) — 코드 직접 수정 X. 자동 호출 트리거는 *Soft만* 우선 도입 (CLAUDE.md 라우팅 규칙 — 합류 직전). Hard 강제 훅(`.claude/hooks/`) + Tier 1 도메인 셀프리뷰는 합류 후 첫 주 안정화 후 추가.
**이유**: 시니어 진단 그대로 — 현재 본인이 매번 `/work:review` 슬래시 커맨드를 *수동 호출*해야만 검증이 일어나는 구조라 *까먹으면 검증 0*. 자동화 빠진 게 핵심. 단순히 "항상 자동" 호출은 비용(메시지 한도 체감 절반 ↓) 부담 + 리뷰 피로 위험 → 스마트 트리거로 30~50% 호출로 절감. *코드 컨벤션*(네이밍/포매팅) 영역은 의도적으로 *Scope 밖*: 학부생 1인 + 합류 직전 1명 현실에서 *합의된 코드 스타일이 없음* → 룰북 먼저 쓰면 premature abstraction(Rule of three 위반의 자기 모순). 미래 Roslyn analyzer + .editorconfig로 *도구가 강제*하는 방향으로 도입 예정 (ADR-019 후속 후보 — Phase 30+ 또는 팀원 2명 안정화 시점 트리거). REVIEW_CHECKLIST.md는 헌법·ADR의 *복제*가 아닌 *매핑 인덱스* — stale 위험 관리는 *동기화 절차*(ADR 추가 5단계에 체크리스트 갱신 명시) + *향후 안전망 훅*(합류 후) 2단계. 시니어 멘트의 "코드 컨벤션 깔쌈하게"를 우리 현실에 맞게 *재해석*: 회사처럼 기존 합의된 룰을 적용하는 게 아니라, *합의가 없는 단계*에서는 아키텍처 검증부터 자동화하고 코드 스타일은 도구에 위임하는 길(길 D).
**트레이드오프**: 매 코드 응답마다 트리거 조건 평가 → 메인 세션 인지 부담 약간 증가(허용 비용). 트리거 조건 충족 시 모델 호출 2회(도메인 에이전트 + reviewer) → 메시지 한도 체감 65~80%로 감소(절반은 아님). 컨텍스트 윈도우는 reviewer가 격리돼 *덜* 차오름 → 긴 Phase 세션 수명은 오히려 이득. REVIEW_CHECKLIST.md ↔ 원본(헌법/ADR/layer CLAUDE.md) 동기화 부담 — 옵션 4(절차에 박기)로 1차 해소, 옵션 2(훅 강제)는 합류 후. 코드 스타일 미검증 → 팀원 합류 직후 *변수명/포매팅 충돌* 가능성 (감수, 도구 도입 시점까지). reviewer false positive 위험 — Hard rule 6("확실하지 않으면 짚지 마")로 완화하되, 합류 첫 주 운영 보고 trigger 조건 조정 필요 가능성. 헌법(`CLAUDE.md`) 350줄 임계 *경계선상* 도달(약 350줄) → 다음 큰 추가(예: Tier 1 도메인 셀프리뷰 가이드)는 *외부화* 필수. 시니어 피드백 100% 충족 아님 — "코드 컨벤션 깔쌈하게" 부분이 의도적 미해결(80% 충족), analyzer 도입 ADR로 미룸으로써 *상황 판단한 후퇴*가 학부생 의사결정 학습에 가치.
