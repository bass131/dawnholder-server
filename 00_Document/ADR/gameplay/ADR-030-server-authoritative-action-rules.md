### ADR-030: 행동 상태 규칙은 서버 권위 — 클라 Animator Exit Time은 시각 거울

**날짜**: 2026-06-08 (세션24)
**상태**: 채택됨
**결정**: 캐릭터·몬스터·보스의 *행동 상태가 만드는 게임플레이 규칙*(공격 중 이동 잠금 = commit window, telegraph 예고 타이밍, 회복 윈도우 등)은 **서버 State에서 강제**한다. 클라이언트 Animator의 전환 조건 / Exit Time은 그 규칙을 *따라가는 시각 거울*일 뿐 권위가 아니다. 규칙의 수치(잠금 지속 틱 등)는 **98_Shared 단일 상수**로 둬, 클라 예측이 같은 값으로 게이트하게 한다(reconcile rubber-band 방지).

**이유**: 헌법 #1(서버 권위)의 *행동·애니메이션 영역 구체 적용*. 규칙을 클라 Animator Exit Time에만 두면 조작된 클라가 "공격 중 이동" 같은 규칙을 우회 = 핵 취약점. 같은 원칙이 반복 등장(M4.5 보스 telegraph 상수, M4.6 commit window) → 일회성이 아닌 아키텍처 원칙으로 박제. 수치를 서버·클라 양쪽에 따로 하드코딩하면 drift → 공격 시 위치 튕김(reconcile 불일치)이라 98_Shared 단일 출처가 전제.

**트레이드오프**: 매끄러움을 위해 클라가 같은 규칙을 예측으로 *중복 구현*(서버 진실 + 클라 거울 2벌)해야 함 — 단순 "서버만 계산"보다 코드량 ↑. 단 이는 prediction+reconciliation의 본질 비용이고 단일 상수로 drift는 차단된다. 순수 시각 전용 효과(파티클/사운드/카메라 흔들림)는 본 원칙 밖 — 클라 자유.

---

*관련*: 헌법 #1(서버 권위) / M4.6 ActionState FSM(`01_Phases/youngho/M4.6-action-state-fsm/`) commit window 구현이 본 원칙의 첫 정식 적용. M4.5 보스 telegraph 상수가 선례.
