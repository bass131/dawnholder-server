# 01-intro — 자기소개 + 역할 분기

> 이 파일은 `/setup` 진입점에서 첫 단계로 호출됨.
> 종료 시 변수: `name_kr`, `slug`, `role`.

---

## 1. 첫 인사

다음 메시지를 사용자에게 그대로 보냅니다:

```
Dawnholder 협업 셋업에 오신 걸 환영합니다.

저는 본인 옆에서 셋업을 하나씩 안내할 거예요.
환경 검증 → 역할별 도구 → 본인 작업 공간 초기화까지 차근차근 갑니다.
막히면 그 자리에서 멈추고 도움 안내할 테니 안심하세요.

먼저 본인 한글 이름(성+이름)을 알려주세요. (예: 김인규)
```

응답 대기.

---

## 2. 이름 → slug + role 변환

사용자가 한글 이름 답하면 다음 사전을 적용:

| 한글 이름 | slug | role |
|---|---|---|
| 유영호 | `youngho` | `backend` |
| 김인규 | `ingyu` | `unity-client` |
| 정유현 | `yuhyun` | `unity-client` |

### 사전 매칭 시

다음 메시지로 확인:

```
{name_kr}님 맞나요? 본인 정보로 셋업 진행할게요:
- 영문 식별자: {slug}
- 담당 영역: {role}
- 본인의 학습 일지 폴더: 00_Document/learning-journal/{slug}/

맞으면 "맞아요" 답해주세요. 다른 사람이면 한글 이름 다시 알려주세요.
```

사용자 "맞아요" 또는 동의 응답 → 다음 단계로.

### 사전에 없는 이름이면 (즉석 변환 + 사후 보고)

국립국어원 로마자 표기법으로 이름(성 제외)을 영문 변환. 변환 후 다음과 같이 안내:

```
{name_kr}님은 제 사전에 없는 분이네요. 다음으로 임시 변환했어요:
- 영문 식별자: {추정 slug}
- 담당 영역: ??? (백엔드 / Unity 클라 / 그 외)

영문 식별자 이걸로 OK인가요? 그리고 담당 영역도 알려주세요.

⚠️ 알림: 변환된 정보는 셋업 끝난 후 팀장(유영호)에게 보고됩니다.
   팀장이 사전을 정식 업데이트할 거예요.
```

사용자가 영문 slug 확인 + 역할 응답하면 변수 박고 진행. role 값은 `backend` 또는 `unity-client` 중 하나로 정규화. 그 외 역할이면 사용자에게 어느 셋업 흐름 따를지 직접 물어 결정.

**사후 보고용 메모 보관**: 단계 04-finalize에서 사용자에게 "팀장에게 보고 드리세요: '{name_kr} → {slug} / {role} 사전 추가 필요'" 안내.

---

## 3. 다음 단계 안내

변환 확정 후 사용자에게 다음 메시지:

```
좋아요. {name_kr}님 ({slug} / {role}) 셋업 시작합니다.

다음 단계: 공통 환경 검증 (8 단계, 약 10~20분).
한글 경로 → Git → .NET → MSSQL → VS Code → Git 사용자 → 빌드 확인 순서.

준비됐어요?
```

사용자 "준비됐어요" 또는 동의 → `.claude/setup-steps/02-common.md` 읽고 진행.

---

## 변수 박힘 상태 (이후 모든 단계에서 참조)

- `name_kr` — 사용자 한글 이름
- `slug` — 영문 식별자 (폴더명, Git author 등에 사용)
- `role` — `backend` 또는 `unity-client`
- `is_new_member` — 사전 매칭 실패해서 즉석 변환된 경우 true (단계 04 사후 보고용)
