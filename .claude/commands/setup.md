사용자가 ClaudeDev 레포에 처음 합류해 협업 셋업을 시작했습니다.

## 이 커맨드의 역할

`/setup` 한 번 호출하면 차근차근 단계별로 진행. 학부생 백지 팀원을 가정해
**한 번에 한 단계씩 떠먹이듯** 안내. 막히면 STOP하고 도움 요청.

## 진행 흐름 (5단계)

```
01-intro       자기소개 + 역할 분기
02-common      모두 거치는 공통 환경 검증 (8 단계)
03-backend     백엔드 추가 셋업 (5 단계)         ─┐
                                               ├── 역할에 따라 분기
03-unity-client Unity 클라 추가 셋업 (8 단계)   ─┘
04-finalize    개인 자산 초기화 + 다음 액션 안내 (7 단계)
```

## 진행 절차

다음 순서로 단계별 .md 파일을 읽어 그대로 진행하세요:

### 1. 단계 01 진행

`.claude/setup-steps/01-intro.md` 읽고 그 안내대로 진행.
종료 시 `slug`, `role` 변수가 결정됨.

### 2. 단계 02 진행

`.claude/setup-steps/02-common.md` 읽고 그 안내대로 진행.
공통 환경 검증 8 단계. 어디든 막히면 STOP, 사용자 도움 요청 후 재진행.

### 3. 단계 03 분기

`role` 변수에 따라:
- `role == "backend"` → `.claude/setup-steps/03-backend.md` 진행
- `role == "unity-client"` → `.claude/setup-steps/03-unity-client.md` 진행
- 다른 값(즉석 변환된 신규 멤버) → 사용자에게 어느 쪽으로 진행할지 묻기

### 4. 단계 04 진행

`.claude/setup-steps/04-finalize.md` 읽고 그 안내대로 진행.
이게 끝나면 셋업 완료. 첫 작업 안내까지.

## 중요 원칙

- **학습 모드 톤 유지**. 학부생 백지 팀원이라 가정. 전문 용어는 풀어 설명.
- **한 번에 한 단계씩**. 한꺼번에 여러 단계 안내하지 말기 — 사용자가 따라가기 힘듦.
- **막히면 STOP**. 검증 실패 시 다음 단계로 넘어가지 말고 사용자 도움 요청.
- **trade-off는 짧게**. 셋업은 결정 영역 아님. 본인 헌법의 결정마다 trade-off 원칙은
  주로 설계 의논용. 셋업은 "이렇게 하면 됨" 톤.
- **5단계 보고는 04 끝에 한 번만**. 셋업 자체는 작업이 아니라 환경 준비라
  각 단계마다 5단계 보고 안 박음. 마지막 04 마무리 시 통째로.

## 단계 간 변수 전달

- 단계 01에서 결정되는 변수 (이후 모든 단계에서 참조):
  - `name_kr` — 한글 이름 (예: "김인규")
  - `slug` — 영문 식별자 (예: "ingyu")
  - `role` — "backend" 또는 "unity-client"
- 단계 02 종료 시: 모든 환경 검증 통과 상태
- 단계 03 종료 시: 역할별 도구 검증 통과
- 단계 04 종료 시: 개인 자산 초기화 완료, 첫 작업 안내됨

## 진행 중 사용자 응답 패턴

- "✓" 또는 "OK" — 해당 단계 통과, 다음으로
- "막혔어요" / 에러 메시지 — 진단 + 도움 안내, 같은 단계 재시도
- "건너뛸게요" — 사용자가 명시적으로 SKIP 요청. 위험 짚고 진행 (예: 한글 경로
  검증 SKIP은 비추천 — 본인 48시간 silent fail 함정 안내)
