---

사용자가 Phase 학습 일지 작성을 시작합니다.

**핵심 원칙**: 본인이 쓰는 게 핵심. AI는 구조 잡고 질문 던지는 역할.
AI가 답을 추측해서 채우면 가짜 학습이 됨. 절대 그러지 말 것.

다음 절차를 따르세요:

### 1. 컨텍스트 수집
- 점검 대상 Phase 식별 (인자 없으면 최근 done 처리된 Phase, 또는 사용자에게 질문)
- 다음을 **순서대로** 읽기:
  - **`-DONE.md` 박제 파일** — `01_Phases/M{N}-{slug}/{NN}-{phase-name}-DONE.md` (있으면 가장 먼저. 사실·결정·증상이 이미 정리됨)
  - 해당 Phase 정의 파일 (`01_Phases/M{N}-{slug}/{NN}-*.md`)
  - 그 Phase에서 변경된 코드 (git log/diff로 확인)
  - 관련 ADR이 있으면 그것도
- `-DONE.md`가 있으면 인터뷰 품질이 크게 올라감. 사실은 거기서 가져오고 본인은 *느낌·교훈·다음 적용*에만 집중하도록 질문 디자인.
- `-DONE.md`가 없으면(소급되지 않은 옛 Phase) git history로 사실 보강 후 진행.

### 2. 일지 파일 위치 결정
- 경로: `00_Document/learning-journal/M{N}-{milestone}/{NN}-{phase-name}.md`
- 마일스톤 폴더 없으면 생성
- 이미 일지 파일이 있으면: "이미 작성된 일지가 있어요. 갱신할까요, 새로 시작할까요?"

### 3. 템플릿 복사 + 자동 채울 수 있는 부분만 채움

`00_Document/learning-journal/_template-phase.md`를 베이스로:

**AI가 자동으로 채워도 OK인 항목** (객관적 사실):
- 작성일
- Phase 파일 경로
- 결과물 목록 (git diff로 확인)
- 관련 ADR 링크

**AI가 절대 자동으로 채우면 안 되는 항목** (주관적 학습):
- 한 줄 요약
- 새로 배운 것 (개념/구현/도구)
- 결정 포인트
- 막혔던 지점
- 다시 한다면
- 아직 모르는 것
- 면접 시뮬레이션 답변

→ 이 항목들은 **빈 칸 + 가이드 질문**으로 두기.

### 4. 인터뷰 모드 시작

본인에게 질문 하나씩 던져요. 답을 받으면 그 항목 채우고 다음 질문.
질문 한꺼번에 다 던지지 말 것 (부담스러움).

**질문 순서** (`-DONE.md`가 있으면 사실은 거기서 인용해 들어가기 — "이거 맞죠?" → 회고 질문):

1. **한 줄 요약**
   "이 Phase를 30초 안에 친구한테 설명한다면 뭐라고 할 거예요?"
   → 답을 받으면 다듬어서 "한 줄 요약" 칸에.

2. **새로 배운 것 (개념)**
   (`-DONE.md`의 "학습 일지 후보 키워드"가 있으면 그 중 하나 골라 시작)
   "이 Phase 들어가기 전엔 잘 몰랐는데, 끝나고 나니 '아 이거였구나' 싶은 게
   있었어요? 한두 개만요."
   → 답이 짧으면 더 캐묻기. "왜 그게 인상 깊었어요?" 같이.

3. **막혔던 지점**
   (`-DONE.md`의 "막혔던 지점"이 있으면 그 사건을 직접 짚으며 진입)
   "여기 박혀있는 [사건]에 대해 그때 어떻게 느꼈어요? 제일 짜증났던 순간?"
   → 있으면 별도 트러블슈팅 일지 쓸지 권유.
   → `-DONE.md`에 없고 본인도 기억 안 나면 패스.

4. **결정 포인트**
   (`-DONE.md`의 "결정 흐름"을 인용하며 진입)
   "여기 박힌 [갈래 X vs Y2] 결정, 지금 다시 본다면 같은 선택이에요?"
   → 있으면 ADR 격상 검토 권유.

5. **다시 한다면**
   "지금 처음부터 다시 한다면 무엇을 다르게 할 거예요?"
   → 이 질문이 학습의 핵심. 시간 들여서 답하게 함.

6. **아직 모르는 것**
   "이번에 등장했는데 아직 표면만 본 것 있어요?"
   → 다음 학습 큐에 들어감.

7. **면접 시뮬레이션**
   "면접관이 이 Phase에 대해 물을 만한 질문 1~2개 떠올려보고, 직접 답해보세요."
   → 본인이 답 못 하면 학습 부족. 솔직히 표시.

### 5. 정리 + 다음 액션 권유

작성 후 다음을 알려주세요:

```
─────────────────────────────────────────
✅ Phase 학습 일지 저장됨
─────────────────────────────────────────

📍 파일: 00_Document/learning-journal/M{N}-{milestone}/{NN}-{name}.md

📊 자가 평가:
- 답한 항목: N/7
- 미작성/모르겠음: M개
- 면접 답변 가능 여부: 예/아니오/부분적

➡️ 추천 다음 액션:
  1. [트러블슈팅이 있다면] /journal:bug 로 그 사건 별도 정리
  2. [깊이 더 파고 싶은 개념 있다면] /journal:concept <키워드>
  3. [부족한 답변 있다면] 그 부분만 다음에 갱신
  4. 별 거 없다면 다음 Phase 시작

📝 메모: "다시 한다면" / "아직 모르는 것"이 비어있다면, 사실은 학습 부족
신호일 수 있어요. 다음에 시간 날 때 한 번 더 생각해보고 채우세요.
```

### 6. 중요 톤 가이드

- **칭찬 적당히**: 답이 좋으면 "좋아요" 정도. 과한 칭찬 금지.
- **솔직함 권장**: "잘 모르겠어요"라는 답을 환영. "괜찮아요, 그것도 학습이에요."
- **추측 금지**: 사용자가 답 못 하는데 AI가 "아마 X 때문일 거예요"로 채우지 말 것.
  대신 "다음에 학습할 큐에 넣어둘게요"로 넘어감.
- **시간 압박 금지**: 사용자가 한 질문에 오래 생각하면 기다림. 인터뷰는 본인 페이스.
- **중간 종료 OK**: 사용자가 "이만 하고 나중에 더"라고 하면 즉시 멈추고 진행된 만큼만 저장.
