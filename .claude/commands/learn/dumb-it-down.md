---
description: 직전 답변을 더 쉬운 말로 다시 설명
argument-hint: [헷갈리는 부분 명시 - 선택]
---

사용자가 직전 답변이 어려웠다고 합니다. 추가 단서: **$ARGUMENTS**

다음 원칙으로 다시 설명하세요:

### 1. 사과 금지, 부끄럽게 만들지 않기
"제가 너무 빨리 갔네요" 정도는 OK. "어려우셨군요?" 같은 느낌 NO.
어려운 게 정상이라는 톤으로.

### 2. 한 단계 더 내려가기
- 전문 용어를 한국어로 풀어쓰기
- 비유를 추가하거나 더 일상적인 비유로 교체
- 한 번에 다루는 개념 수를 줄이기 (5개 → 2개)
- 코드 예시는 더 작고 단순한 버전으로

### 3. "근본적으로 헷갈렸을 만한 곳" 추측
사용자가 어디서 막혔는지 명시 안 했어도, 직전 답변에서 가장
허들이 높았을 부분을 짚어 다시 풀이.

### 4. 확인 질문 던지기
재설명 끝에 "이 부분은 이제 감이 오시나요?" 같은 질문.
사용자가 "예"라고 해도 한 번 더 점검하는 작은 질문 1개:
"그럼 X 상황에서는 어떻게 될까요?" 식.

### 5. 그래도 어렵다면 한 단계 더
사용자가 두 번째 시도 후에도 어렵다고 하면, 거기서 멈추고
다른 접근을 제안:
- "이 개념 잠깐 미루고 다른 걸 먼저 해볼까요?"
- "직접 코드 한 번 돌려보고 결과를 같이 볼까요?"
- "이 개념의 더 작은 버전부터 시작할까요?"

---

**중요**: "이건 어려운 개념이에요"라고 인정해도 OK. 모든 걸 5초 만에
이해시키려 하지 말 것. 학습은 시간이 걸리는 거고, 그게 정상.
