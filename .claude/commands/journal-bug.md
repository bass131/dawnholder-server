사용자가 트러블슈팅 일지 작성을 요청했습니다.
한 줄 요약 (있으면): **$ARGUMENTS**

**왜 이게 중요한가**: 면접 단골 질문 "기억나는 어려웠던 버그?"에
즉시 답할 무기. 매 막힘이 자산. 풀린 직후 작성해야 디테일 안 잊음.

### 1. 적합성 체크

먼저 사용자에게 확인:
- 정말 막혔다가 풀렸나? (Phase 진행 중 일반적 시행착오는 굳이 트러블슈팅
  까지 안 만들어도 됨. Phase 일지의 "막혔던 지점"으로 충분.)
- 30분 이상 막혔거나, 원인 찾는 데 가설 2개 이상 거쳤다면 트러블슈팅 가치 있음.

판단 어려우면: "이 사건이 면접에서 '어려웠던 버그'로 얘기할 만한 가요? 아니면
가벼운 시행착오 수준?" 물어보고 결정.

### 2. 일지 위치
- 경로: `docs/learning-journal/M{N}-{milestone}/troubleshoots/{YYYY-MM-DD}-{slug}.md`
- 마일스톤 폴더 + troubleshoots 폴더 없으면 생성

### 3. 인터뷰 — 시간순 재구성

이 일지는 **서사**가 핵심. 시간순으로 재구성하는 게 면접 답변 연습이 됨.

`_template-troubleshoot.md` 베이스.

**자동 채워도 OK**: 작성일, 발생 Phase

**인터뷰로 채움**: 모든 본문

### 4. 질문 순서

1. **증상 (사실만)**
   "무엇이 잘못 보였어요? 원인 추측 빼고 사실만요."
   → 사용자가 원인을 말하려 하면 "그건 이따 적을게요. 우선 본 것만"으로 컷.

2. **재현 절차**
   "어떻게 하면 이 버그가 재현됐어요? 1단계, 2단계 식으로."

3. **기대했던 것**
   "원래는 어떻게 동작해야 했어요?"

4. **가설들 (시간순)**
   "막혔을 때 머릿속에 떠오른 원인 후보들 시간순으로 알려주세요.
   '아 이거겠지'에서 '그건 아니네'로 가는 흐름까지 다 적는 게 좋아요."
   → 답변 받으면 가설별로 정리.

5. **진짜 원인**
   "최종적으로 진짜 원인은 뭐였어요? 메커니즘까지 설명해주세요."
   → 메커니즘이 약하면 더 캐묻기. "그래서 정확히 어떻게 그게 그 증상을
     만들었어요?"

6. **왜 헷갈렸나 (자기 분석)**
   "왜 이게 헷갈리는 버그였어요? 본인의 어떤 가정이 틀렸어요?"
   → 이 답이 면접에서 가장 강한 무기.

7. **해결**
   "어떻게 고쳤어요? 코드 변경 위주로."

8. **재발 방지 (마구 고치기)**
   "같은 실수 다시 안 하려면 어떤 가드레일을 추가할 수 있을까요?"
   → 후보들:
     - 헌법(`CLAUDE.md`)에 명시
     - 코드 주석으로 경고
     - 단위/통합 테스트로 회귀 방어
     - Hook 추가 (가능하면)
   → 사용자가 떠올린 것 + AI가 1~2개 더 제안. 실제로 추가까지 도와줌.

9. **한 줄 학습 정수**
   "이 사건에서 한 줄로 가져갈 교훈이 있다면?"

10. **면접 답변 90초 버전**
    "이걸 면접관에게 90초 동안 답한다고 생각하고 적어보세요. 본인 말로."
    → **이게 가장 중요.** 일지의 정수.

### 5. 재발 방지 실행 도움

8번 단계에서 "헌법에 명시" 같은 게 결정되면, 실제로 그 변경까지
도와주세요. 예:

- "헌법에 추가" → 사용자에게 어느 CLAUDE.md(루트/server/client/shared)에
  넣을지 묻고, 추가 문구 제안.
- "테스트 추가" → 어떤 시나리오를 단위 테스트로 만들지 코드 제안.

이게 진짜 "마구 고치기"의 실현.

### 6. 마무리

```
─────────────────────────────────────────
✅ 트러블슈팅 일지 저장됨
─────────────────────────────────────────

📍 파일: docs/learning-journal/M{N}/troubleshoots/{date}-{slug}.md

🎤 면접 답변 길이: ~N초
   → 90초 적정. 너무 짧으면 디테일 부족, 너무 길면 압축 필요.

🛡️ 재발 방지 추가됨:
- [ ] 헌법 갱신: ✓ / ✗
- [ ] 코드 주석: ✓ / ✗
- [ ] 테스트 추가: ✓ / ✗
- [ ] 기타: ___

➡️ 다음:
- README의 "개발 일지 하이라이트"에 이 트러블슈팅 후보로 메모
- 관련 개념이 깊다면 /journal-concept 로 별도 정리
```

### 7. 톤

- **재구성 도움 적극**: 사용자가 시간순으로 정리 못 하면 도와주기.
  "막힌 직후 처음 한 시도가 뭐였어요?" 식으로.
- **메커니즘 캐묻기**: "그래서 그게 왜?"를 두세 번 물어서 진짜 이해
  깊이 확인.
- **면접 답변 연습 강조**: 마지막 90초 답변은 시간 들여서 다듬게.
  본인 말투 유지하되 군더더기 빼기.
