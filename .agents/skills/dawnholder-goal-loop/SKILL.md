# Dawnholder 목표 루프

메인 세션은 목표·완료조건·주요 결정과 사용자 대화를 유지하고, 구현·검증·테스트는 서브에이전트를 최대한 활용한다. 이 스킬은 운영 지침이며 기술적 강제 장치가 아니다.

## 적용과 권한

- 이 프로젝트의 다단계 실제 작업에 사용한다. 프로젝트 밖이나 사용자 전역에 이 절차를 설치하지 않는다.
- 기존 사용자 합의와 승인 범위를 먼저 확인한다. 범위 안의 수정·검증은 계속하며 중복 승인 요청을 하지 않는다.
- 스킬 호출은 범위 확대, 원격 쓰기, 외부 서비스 변경의 새 권한을 주지 않는다.
- 목표 정의·스킬 설정 요청만으로 지속 목표를 활성화하지 않는다. 별도 native goal 도구는 사용자가 실제 지속 목표 시작을 명시 요청한 경우에만 사용한다.
- 학습 질문·학습 장부·고정 모델 배정·HTML 보고는 기본 요구사항이 아니다.

## 메인이 유지할 최소 상태

- 사용자 합의로 목표, 허용 범위, 완료조건, 산출물과 검증 범위를 정한다. 이미 정한 내용을 다시 묻지 않는다.
- 합의된 목표 폴더의 `goal.md` 한 곳에 위 기준과 현재 상태, 주요 결정, 검증 결과·근거 경로, 미해결 사항을 기록한다.
- `00_Document/operations/CURRENT.md`에는 활성 `goal.md` 링크만 둔다. 별도 원장에 같은 상태를 중복 관리하지 않는다.
- 재개할 때 해당 `goal.md`, 현재 Git 상태와 필요한 근거만 읽고 남은 작업을 이어간다.
- 전체 대화·소스·원문 로그를 메인 문맥이나 `goal.md`에 복제하지 않는다.

## 작업 분할과 위임

- 메인이 의존 관계와 파일 소유권을 나눈다. 서로 독립적이며 파일이 겹치지 않는 작업은 병렬로 맡긴다.
- 실제 구현자와 독립 검증자는 다른 작업자로 둔다. 일반 작업자는 자신에게 할당된 일만 하며 이 스킬 재귀 호출·추가 위임을 하지 않는다.
- 메인이 명시 지정한 Orca 목표 담당자에게만 단일 목표·작업 공간·권한 안의 좁은 구현·검증 작업자 분할을 한 단계 허용한다. 해당 작업자는 추가 위임하지 않는다. 새 독립 목표·추가 Orca 세션·범위 변경은 메인에 올린다.
- Orca 다중 세션으로 큰 독립 작업을 감독할 때만 [Orca 위임 지침](references/orca-work.md)을 추가로 읽는다. 일반 작업에 Orca를 강제하지 않는다.
- 위임 입력에는 목표, 허용 파일/쓰기 소유권, 필요한 최소 맥락, 완료조건, 검증 범위, 실행 권한을 포함한다.
- 필요한 코드·문서는 경로와 관련 부분으로 전달한다. 프로젝트 전체나 대화 전체를 입력할 필요는 없다.
- 리뷰어에게는 요구사항·변경 대상·검증 범위와 원시 근거를 준다. 예상 답, 의심 결함이나 이전 평가를 먼저 알려 결론을 유도하지 않는다.
- 원문 로그는 TEMP 또는 목표별 산출물 경로에 저장한다. 보고는 짧은 결과와 해당 경로로 받는다.
- 같은 파일을 둘이 수정하지 않는다. 소유권 이전은 기존 작업 종료 확인 후 메인이 명시한다.
- 메인이 통합·발행 여부와 권한을 결정한다. 브랜치 전환·커밋·푸시의 기계 작업은 메인이 명시한 범위에서 담당자에게 위임할 수 있다. 작업자는 임의로 Git 변경·PR·병합을 하지 않는다.

## 구현과 검증의 반복

- 작업자는 할당 범위의 구현과 적절한 자체 점검을 수행하고 변경·검증 근거를 전달한다.
- 독립 검증자는 완료조건과 실제 결과를 확인한다. 수행한 검사, 실패, 미실행 항목을 구분한다.
- 구현 결함은 담당 작업자에게 반환하여 수정하고, 영향을 받는 검증을 다시 수행한다.
- 설계 분기나 목표 범위 변경이 필요하면 메인이 선택지·영향·추천을 정리해 사용자와 결정한다.
- 승인 범위 안에서는 첫 오류나 작은 결함에서 멈추지 않는다. 무의미한 반복 실패는 원인·남은 선택지를 명시한다.
- 도구 부재·접근 불가·외부 의존 등 막힘을 숨기지 않는다. 영향을 받지 않는 일은 이어가되 메인이 몰래 구현 전체를 대신하지 않는다.

## 브랜치와 통합

- 매 목표는 최신 `main`에서 별도 작업 브랜치를 만들고 구현·독립 검증 후 PR을 통해 `main`에 병합한다.
- 기존 변경은 보존하고, 안전한 최신화가 불가능하면 원인을 해결한 뒤 진행한다.
- 이번 초기 정비는 `chore/codex-project-setup`에서 마무리한다. 영구 Codex 개발 계열로 사용하지 않는다.
- `archive/claude-setup-2026-09-29`는 고정 보관으로 유지한다.
- 메인은 결과와 필요한 diff·근거를 선택 확인하여 통합한다. 원격 쓰기·PR·병합은 실제 승인 범위에 따르며 문서만으로 허용되었다고 추정하지 않는다.
- 병합 권한이나 외부 조건이 충족되지 않으면 검증 완료와 병합 대기를 구분해 기록한다.

## 복귀 보고와 종료

- 작업자 보고: 만든 것 / 구현 방법 / 변경 파일 / 실제 검증 결과와 근거 경로 / 남은 문제 / 메인 결정 요청.
- 메인 종합 보고도 같은 핵심을 사용자 눈높이로 설명하되 작업자의 전체 로그나 대화를 붙이지 않는다.
- 완료조건을 실제로 충족한 뒤 `goal.md`에 결과를 갱신한다. 미검증·남은 작업이 있으면 완료로 표시하지 않는다.
- 루프 정의나 문서 정비만으로 새 세션 자동 선택, 게임 실행, 배포나 DB 연결까지 검증되었다고 말하지 않는다.
