# 구현자 모델 라우팅 시범

일반·위험 신호 구현자는 `gpt-6.1-sol` max가 기본이다. 리드는 위임 계약에 아래 현재 배정과 실제 근거를 적는다. 셸·보안·입력 경계, 시간·순서·동시성·수명, 런타임·언어 경계라는 이유만으로 Astra를 고르지 않는다. 「설계 판단이 남은 새 다파일 기능」과 「애매하면 Astra」도 배정 기준으로 쓰지 않는다.

현재 기준은 [10-19 결정과 이번 정본 정렬의 승인 원천](../../../../01_Phases/goals/2026-10-25-implementer-routing-canon/goal.md#적용-중인-사용자-결정)에 둔다. 리드 Sol xhigh는 유지한다. 사용자 결정에 따른 런타임 전환은 정본 병합을 기다리지 않으며, 문서 반영과 실제 런타임 관측은 구분한다.

## 현재 배정과 집계

| 조건 | 다음 신규 구현자 | 기록 근거 |
|---|---|---|
| 일반·위험 신호 구현, 같은 계약 Sol 구현의 독립 불합격 0~1회 | `gpt-6.1-sol` max | 작업 경계와 해당 회차·독립 판정 원문 |
| 같은 계약에서 Sol 구현의 독립 `NOT PASS`가 두 번째로 확정됨 | `gpt-6-astra` xhigh | 결함 번호와 무관하게 두 판정 원문을 연결하고 다음 신규 수정 시도에 적용 |
| Sol max 작업자의 capacity 장기 실패 | [capacity 예외](../../../../00_Document/operations/ORCA.md#capacity-retry)의 신규 `gpt-6-astra` xhigh 작업자 | 같은 세션 재시도·누적 30분·정산/종료 등 기존 조건과 관측 근거 |

두 번째 독립 불합격 집계에서 heartbeat·check 이탈 같은 절차 실패와 계약·명세 귀속 결함을 뺀다. **같은 계약·같은 결함 번호의 확정 실패 3회**와 네 번째 시도의 Advisor는 별도 [확정 실패 정본](../../../../00_Document/operations/ORCA.md#confirmed-failures)을 따른다. 두 집계를 합치거나 같은 산출물을 이중 집계하지 않는다. 구현자·검증자는 작업 하나 뒤 정산·종료하고 수정·재검증은 신규 세션으로 수행한다.

위험 신호는 구현자 승격 근거에서 제외되지만 독립 검증의 배정 근거로 남는다. 위험 신호 구현과 DB·영속 데이터·프로토콜·공유 DLL·보안 경계 검증, 그 밖의 검증 및 기존 예외는 [검증자 모델 시범](../SKILL.md#검증자-모델-시범2026-10-31까지)을 따른다.

## 과거 조사 근거

이전 난이도 배정의 사용자 원문·메인 적용 판단은 [10-09 당시 goal](../../../../01_Phases/goals/2026-10-09-plan-boundary-and-junction/goal.md#요구사항-원천과-적용-결정), 이후 Sol xhigh 전환은 [10-14 당시 결정](../../../../01_Phases/goals/2026-10-14-sol-xhigh-routing-hotfix/goal.md#적용-중인-사용자-결정)에 보존한다. 아래 표는 당시 신호와 조사 근거이며 현재 배정표가 아니다. 사례 번호는 10-09 goal이 가리키는 `E/routing-evidence.md`의 조사 표를 따른다. 조사는 읽기 전용 내부 에이전트가 했고 리드가 원문 일부를 표본 대조했다. 외부 실행이나 독립 검증이 아니다.

| 번호 | 당시 Astra 배정 신호(역사 근거) | 기록 근거 |
|---|---|---|
| 1 | 열린·적대적 입력을 해석한다. 셸·명령줄 해석, 보안 그물, 입력 경계 검증이 해당한다. | 조사 사례 10·11: 셸 문법 해석 결함 |
| 2 | 시간·순서·동시성·수명을 다룬다. 같은 틱 경합, 프로세스·서비스 수명, timeout·재시도가 해당한다. | 조사 사례 6·1~4: 같은 틱 경합과 DB·PowerShell 수명 도구 |
| 3 | 런타임·언어 경계를 넘는 상호 운용을 다룬다. PS5.1↔.NET과 서버↔클라이언트 프로토콜이 해당한다. | 조사 사례 2~3·6: 런타임 경계와 프로토콜 |
| 4 | 설계 판단이 남은 새 다파일 기능·검사기·화면이다. | 조사 사례 7·8: Unity 실화면과 새 검사기 |
| 5 | 같은 계약에서 Sol 구현의 독립 NOT PASS가 두 번째다. 결함 번호와 무관하게 다음 수정 시도를 Astra에 맡긴다. | 조사에서 같은 번호 재실패가 0건이라 확정 실패 3회 규칙이 발동하지 않았다. |

## 계약과 시범 기록

위임 계약에 지정 모델·effort·정확한 실행 명령과 현재 배정 근거(Sol max 기본 / 같은 계약 두 번째 독립 불합격 / 별도 capacity 예외)를 적는다. 파일·줄 수·영역·판정/관측 원시 경로를 연결한다. 요청·첫 화면·rollout 설정과 backend 실제 모델을 구분하고, 실제 모델을 확인할 수 없으면 `unknown`으로 적는다. 첫 기동 화면에 `max`가 없으면 대체하지 않고 리드를 통해 메인에 보고한다. 메인은 [R-2](../../../../00_Document/operations/ORCA.md#r2-source-check) 표본 대조에 배정 근거를 포함한다.

계약마다 배정 모델·회차·독립 결함 수·절차 실패 여부를 goal에 남긴다. Astra 구현 표본은 과거 조사 시점에 0이었으며 당시 조사는 Astra가 더 낫다는 근거가 아니었다. 이번 문서 정렬은 새 성능·비용 측정이나 절감 효과의 입증이 아니다. 2026-10-31 Gardener 평가에서 사용자가 유지·조정·되돌리기를 정한다.

기동은 [R-5](../../../../00_Document/operations/ORCA.md#r5-worker-launch)를 따른다. capacity는 [재시도 정본](../../../../00_Document/operations/ORCA.md#capacity-retry)을 따른다. 독립 검증자는 [검증자 모델 시범](../SKILL.md#검증자-모델-시범2026-10-31까지)을 따른다. 태그와 역할은 [AGENTS](../../../../AGENTS.md#메시지와-보고)를 따른다.
