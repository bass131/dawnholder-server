# 구현자 난이도 라우팅 시범

구현자는 `gpt-6.1-sol` max 또는 `gpt-6-astra` xhigh다. 리드가 위임 계약을 쓸 때 고른다. 아래 신호가 하나라도 해당하면 Astra로 배정한다. 애매하면 Astra로 배정한다. 신호가 없으면 Sol max로 배정한다.

사용자 원문과 메인 적용 판단은 [goal의 적용 결정](../../../../01_Phases/goals/2026-10-09-plan-boundary-and-junction/goal.md#요구사항-원천과-적용-결정)에 있다. 정본 PR 병합 뒤 발행하는 계약부터 적용한다.

## 난이도 신호와 근거

사례 번호는 [goal의 라우팅 근거](../../../../01_Phases/goals/2026-10-09-plan-boundary-and-junction/goal.md#요구사항-원천과-적용-결정)가 가리키는 `E/routing-evidence.md`의 조사 표를 따른다. 조사는 읽기 전용 내부 에이전트가 했다. 리드는 원문 일부를 표본 대조했다. 이 조사는 외부 실행이나 독립 검증이 아니다.

| 번호 | Astra 배정 신호 | 기록 근거 |
|---|---|---|
| 1 | 열린·적대적 입력을 해석한다. 셸·명령줄 해석, 보안 그물, 입력 경계 검증이 해당한다. | 조사 사례 10·11: 셸 문법 해석 결함 |
| 2 | 시간·순서·동시성·수명을 다룬다. 같은 틱 경합, 프로세스·서비스 수명, timeout·재시도가 해당한다. | 조사 사례 6·1~4: 같은 틱 경합과 DB·PowerShell 수명 도구 |
| 3 | 런타임·언어 경계를 넘는 상호 운용을 다룬다. PS5.1↔.NET과 서버↔클라이언트 프로토콜이 해당한다. | 조사 사례 2~3·6: 런타임 경계와 프로토콜 |
| 4 | 설계 판단이 남은 새 다파일 기능·검사기·화면이다. | 조사 사례 7·8: Unity 실화면과 새 검사기 |
| 5 | 같은 계약에서 Sol 구현의 독립 NOT PASS가 두 번째다. 결함 번호와 무관하게 다음 수정 시도를 Astra에 맡긴다. | 조사에서 같은 번호 재실패가 0건이라 확정 실패 3회 규칙이 발동하지 않았다. |

신호 5의 집계에서 heartbeat·check 이탈 같은 절차 실패를 뺀다. 계약·명세 귀속 결함도 뺀다. [확정 실패 집계](../../../../00_Document/operations/ORCA.md#confirmed-failures)는 그 정본을 따른다.

신호가 없을 때 Sol max로 둘 일은 명세가 고정된 1~2파일 수정, 기계적 변경·lint 정리, 문서, 측정·조사, 선행 시험이 요구를 다 고정한 좁은 구현이다.

## 계약과 시범 기록

위임 계약에 배정 모델을 적는다. 신호 번호 또는 「해당 없음」을 적는다. 파일·줄 수·영역과 원시 근거 경로를 적는다. 메인은 [R-2](../../../../00_Document/operations/ORCA.md#r2-source-check) 표본 대조에 배정 근거를 포함한다.

계약마다 배정 모델·회차·독립 결함 수·절차 실패 여부를 goal에 남긴다. Astra 구현 표본은 조사 시점에 0이다. Astra가 더 낫다는 근거는 아직 없다. 2026-10-31 Gardener 평가에서 사용자가 유지·조정·되돌리기를 정한다.

기동은 [R-5](../../../../00_Document/operations/ORCA.md#r5-worker-launch)를 따른다. capacity는 [재시도 정본](../../../../00_Document/operations/ORCA.md#capacity-retry)을 따른다. 독립 검증자는 [검증자 모델 시범](../SKILL.md#검증자-모델-시범2026-10-31까지)을 따른다. 태그와 역할은 [AGENTS](../../../../AGENTS.md#메시지와-보고)를 따른다.
