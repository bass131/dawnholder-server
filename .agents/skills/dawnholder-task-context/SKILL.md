# 작업 맥락과 규칙 준수

작업의 읽기 → 사전 메모 → 규칙 원문 계약 → 실제 준수 위치 → 독립 판정을 연결한다. 권한·모델·파일 소유권은 [AGENTS](../../../AGENTS.md), 목표 운영은 [goal-loop](../dawnholder-goal-loop/SKILL.md)를 따른다. 이 스킬은 새 목표·세션·범위·실행 권한을 만들지 않는다. 질문·설명만이면 필요한 근거를 읽어 답하고 goal이나 쓰기용 메모를 자동 생성하지 않는다.

사람 팀원이 자기 머신에서 쓰는 세션은 [외부 팀원 권한](../../../AGENTS.md#외부-팀원-세션)이 정본이다. 담당 문서의 관련 품질 기준을 적용해도 로컬 goal·작업자/검증자 기동이나 `game-design/` 밖 쓰기를 요구하지 않는다.

## 공통 읽기와 비용 상한

최신 AGENTS와 해당 세션의 Claude 지침 → 현재 goal → 할당 계약 → [기능 지도](../../../00_Document/FEATURE_MAP.md)·[영역별 계약](../../../00_Document/domains/INDEX.md)의 관련 구간 → [CODE_CONVENTION](../../../00_Document/conventions/CODE_CONVENTION.md)의 관련 절 순으로 읽는다. 현재 goal은 할당 계약 또는 [CURRENT](../../../00_Document/operations/CURRENT.md)에서 찾는다. 실행 전에는 [DEVELOPMENT](../../../00_Document/operations/DEVELOPMENT.md)의 해당 환경·부작용을 확인한다.

이미 읽은 동일 버전은 다시 수집하지 않는다. 계약에 지정한 파일·구간과 같은 책임의 주변 예시 **1~2개**를 기본 상한으로 삼는다. 이 예시는 산출물의 책임·배치·명명 관례 탐색용이며 구현 기대답이나 예상 검증 결론과 구분한다. 아래 표는 공통 읽기에 더할 역할별 최소 범위다. 자료가 부족하거나 충돌하면 필요한 이유·추가 경로·구간만 메모에 남기고 좁혀 읽는다. 저장소 전체·전체 과거 대화·전체 로그 수집으로 대체하지 않는다.

| 역할 | 최소 읽기와 기본 상한 | 추가 읽기가 필요한 경우 |
|---|---|---|
| 파트 리드 | 요구사항 원천과 현재 결정·보존 동작, 소유권, 재사용 경계, 적용 규칙과 검증 방법. 할당 경계와 관련 문서 구간, 기존 예시 1~2개 | 요구사항 충돌·경계 간 계약·실행 부작용을 확인할 때 해당 원문/사용처만 추가 |
| 구현 Sol | 바꿀 코드 주변, 같은 책임의 기존 구현 1~2개와 재사용 helper. 이름·들여쓰기·오류 처리·주석·수명 관례 | helper 계약이 불명확하거나 변경 영향이 경계를 넘을 때 관련 호출자/소유자만 추가 |
| 독립 Opus | 요구사항 → 구현 보고 → 실제 diff·실행 원문 → 관련 기존 테스트 패턴 1~2개. 구현자의 결론을 판정으로 재사용하지 않음 | 보고/실제 수행 불일치, 실패·취소·종료 경로 또는 보존 동작의 증거가 부족할 때 해당 원시 근거/테스트만 추가 |
| 디자인·보고서 작성자 | 현재 화면 또는 직전 산출물, 관련 결정·레퍼런스·사용자 피드백(아쉬웠던 지점 포함), 현재 goal 상태. 계약에 지정한 자료와 예시 1~2개 | 결정의 출처·화면 흐름·보고 근거가 부족할 때 해당 자료만 추가. 보고서는 [REPORTING](../../../00_Document/conventions/REPORTING.md) 관련 절도 확인 |

보고서의 조사·설계 해설·본문·HTML·전용 생성 스크립트 작성자는 리드라는 기존 라우팅을 유지한다. 기존 파일은 관례의 출발점이다. 압축 한줄 코드나 미검증 변경을 확정 모범으로 강제하지 않는다. 해당 언어 절이 없으면 부재·임시 적용 기준·출처를 메모에 적고 미승인 기준을 정본으로 만들지 않는다.

## 파일 쓰기 전 메모와 원문 계약

1. 첫 대상 파일 쓰기 전에 [맥락 메모 양식](references/templates.md#맥락-메모)을 할당된 근거 경로에 작성한다. 역할·기준 SHA·읽은 절·기존 예시·helper·영향 파일·위치/이름 근거·적용 규칙·질문을 남긴다. 메모 자체가 첫 기록이며 사후 작성한 메모를 사전 기록으로 소급하지 않는다. 신규 Opus도 자기 테스트/판정 파일을 쓰기 전에 메모를 남긴다.
   기계적 이관·병합 기록도 같은 필수 필드를 짧게 채운다. 기존 양식 안에서 필요한 절·예시·해당 없음의 이유로 축약할 수 있지만 사전 메모/독립 검증 면제나 작은 작업 예외를 만들지 않는다.
2. 새 파일은 [배치와 이름](../../../00_Document/conventions/CODE_CONVENTION.md#파일-위치와-이름)에 따라 같은 책임의 기존 경로를 확인한다. 새 폴더의 필요·주변 명명 관례·재사용/중복 이유를 적는다. 제품·도구의 날짜/마일스톤/작업자 이름 금지를 역사 goal의 날짜 폴더나 외부 계약 이름의 일괄 변경으로 넓히지 않는다.
3. 리드는 [위임 계약 양식](references/templates.md#위임-계약)에 CODE_CONVENTION의 **관련 절 제목·본문 원문 전체**와 출처 경로·기준 commit 또는 미커밋 hash 및 hash 대상을 붙인다. 상태와 책임·주석과 문서·파일 위치와 이름·역할별 적용·변화 평가·해당 언어 절 중 이 작업에 관련된 절만 선택하고, 해당 없는 절은 이유 한 줄로 명시해 제외한다. 관련 없는 절을 무조건 붙이지 않으며, 관련 절 누락·적용 위반·메모/결과 불일치의 차단은 유지한다. 링크만 보내거나 요약으로 원문을 대체하지 않고 출처가 다른 구간을 구분한다. 관련 절이 없으면 그 부재와 임시 기준을 명시한다.
4. 구현·작성 완료 보고에서 메모의 준수 계획을 **실제 파일·심볼 또는 문서 절과 근거 경로**로 갱신한다. 계획 변경의 이유·추가 읽기·열린 질문의 처리도 남긴다. 명령·환경·exit와 미실행을 구분하며 자체점검을 독립 판정으로 표현하지 않는다.

발행 전 리드는 계약 경로를 **실제 작업자 폴더 기준으로 기계 확인**하고 명령·cwd·결과·exit를 근거 파일에 남긴다. 읽을 입력 파일/디렉터리는 실제 존재를, 아직 만들지 않은 출력은 부모 디렉터리 존재와 신규 출력 구분을 확인한다. 경로가 잘못됐으면 계약을 고치며 확인하지 못한 경로를 확인 완료로 적지 않는다. 정본 경로 검사 도구 구현은 후속 범위다. 계약은 예문/예상 결론 대신 요구항목·보존 계약·판정 기준을 담고, 설계 결정이 필요하면 한 줄 대안과 영향을 남긴다.

검증용 harness는 할당된 원시 근거 폴더에 실행 파일로 저장하고 명령·입력·환경·exit·원시 출력을 연결한다. 문자열만 남긴 실행으로 대체하지 않는다. Assert의 판단 변수는 존재·결과·상태 등 의미별로 분리해 무엇이 실패했는지 드러낸다. 보고 수치는 [REPORTING](../../../00_Document/conventions/REPORTING.md#수치와-원시-근거)에 따라 원시 결과 파일에서 읽고 계산 근거·미측정을 구분한다. [R-7 시범](../../../00_Document/operations/ORCA.md#r7-fable-pilot)에 해당하는 작업에서만 불변식 파일과 Sol 보고의 전제 표식을 연결한다.

## 독립 판정과 통과 차단

구현자의 쓰기 종료 뒤 신규 Opus는 [검증 판정 양식](references/templates.md#검증-판정)으로 규칙 → 실제 변경 위치/근거 → 판정 표와 사람 가독성 검토를 남긴다. 메모와 결과가 같은 관례를 따르는지 직접 대조한다. 코드 변경은 [검증 강도 시범](../dawnholder-goal-loop/SKILL.md#검증-강도-4주-시범)의 강/약 필수 항목과 별도 테스트 소유권을 따르고, 문서 변경은 내용·참조·권한의 정적 실사를 수행한다. 독립 세션은 어느 등급에서도 생략하지 않는다. 제품 결함은 번호로 반환하고 제품 파일은 고치지 않는다.

강 등급의 실제 경로와 **설치·실행·I/O 도구는 현재 변경의 실제 진입 경로를 한 번 실행하기 전 PASS하지 않는다.** 허용된 대역(stub) 환경에서도 실제 진입점을 호출하고 입력→분기→출력/실패 경로·사용한 대역·미확인 외부 경계를 기록한다. 대역 환경 자체점검이나 함수 정의만 불러온 점검, 형식검사·대상 0건·기록된 역사 실행은 이 실행을 대신하지 않는다. 실행 권한/환경 제약으로 막히면 **미실행·판정 보류**와 원인을 남기고 승인 밖 실행을 하지 않는다. 대역에서 실행한 결과를 실제 설치·DB·게임 실행으로 확대하지 않는다.

다음은 수정 또는 메인 결정 전 **통과 차단**이다: 맥락 메모 부재, 관련 규칙 원문 누락, 적용 규칙 위반, 메모와 실제 결과 불일치. 메인 결정으로 처리한 항목은 결정 출처와 영향·남은 한계를 판정에 남긴다. 관련 필수 항목의 미검토를 통과로 처리하지 않는다. 범위 밖 과거 위반은 별도로 보고하고 무관한 일괄 수정으로 넓히지 않는다.

기존 CLAUDE의 추가 두 차단사유도 공용 판정에 적용한다. **상수·수기 입력을 실제 측정값처럼 기록**한 경우는 그 값을 만든 명령·원시 로그·계산 코드로 추적되지 않으므로 차단한다. **기대값을 제품과 같은 계산으로 다시 만들어 구조상 항상 통과하는 테스트**도 차단한다. 실제 계측·관측 불가·미실행을 분리하고 실패 전후 값을 고정 성공 상수로 채우지 않는다. 원천은 [이전 맥락 목표의 N1 동기화 안건](../../../01_Phases/goals/2026-10-03-harness-principles/goal.md#운영-규칙참고-근거-정비)이며 Gardener의 같은 번호 관측과 구분한다. [AGENTS](../../../AGENTS.md#작업-진입점)·[CODE_CONVENTION](../../../00_Document/conventions/CODE_CONVENTION.md#역할별-적용)에서 이 절로 연결한다.

기존 테스트가 실패하면 **전 실패를** (a) 옛 구현 세부 단정, (b) fixture/환경 누락, (c) 실제 회귀, (d) 원인 미확정으로 분류한다. (a)는 요구사항 근거와 함께 고치고 (b)는 빠진 입력만 보완하며 (c)는 제품 결함 번호로 반환하고 (d)는 통과로 바꾸지 않는다. 고친 테스트마다 이름·이전 단정·새 단정·요구사항 출처 경로/줄 또는 msg ID를 [판정 표](references/templates.md#검증-판정)에 남긴다. 기대값 일괄 재생성/완화를 금지하며 **같은 명령의 전후 통과·실패 수와 원시 출력**을 보존한다. 이 기준은 사용자 결정과 구분한 메인 결정 `msg_71e41e231d55`와 두 파트 전달 원문에 근거한다. 리드는 새 Opus 계약에 그 원문을 첨부하고 보충 지시의 버전을 고정한다.

사람 검토는 주석이 필요한 코드 가까이에 있는지, 책임·상태 소유·의존성 방향·실패 수명이 드러나는지, 배치와 이름이 책임/관례에 맞는지, 처음 읽는 사람이 진입점과 계약을 찾을 수 있는지, 반복 RPC 뼈대·불필요한 변환·중복 책임의 이유가 있는지 확인한다. 모양만 같고 변경 이유가 다른 코드의 분리를 결함으로 단정하지 않는다.

새 독자가 X의 원천과 변경 주체를 찾는 [30초 가독성 확인](../../../00_Document/conventions/CODE_CONVENTION.md#사람의-탐색과-가독성)을 별도로 판정한다. 지적은 `file:line · 문제 · 대안 · 현재 차단/후속 처리`로 남긴다. 메인은 승인 전에 실패 분류 표/측정·규칙 준수의 원천을 [R-2 표본 대조](../../../00_Document/operations/ORCA.md#r2-source-check)하며 이 표본을 검증자의 전수 분류로 표현하지 않는다.

판정에는 **검토했고 지적 없음 / 결함 번호 / 미검토 / 해당 없음과 이유**를 구분한다. [기계 판독 표](references/templates.md#검증-판정)의 `verifies`는 대상 구현 Task의 실제 ID로 확인하며 결함 번호·심각도·차단 여부·귀속을 명시한다. 해당 없음/미확정을 추정으로 채우지 않는다. 같은 양식의 「설계 관찰(비차단)」은 재사용·책임·가독성 대안과 영향·현재 범위/후속 경계를 남기되 요구사항 위반·차단 결함을 낮추지 않는다. 린터·typecheck 성공은 가독성·책임 분리·주석 품질·배치·설계의 통과 근거가 아니다. 빌드·통합 실행·실제 플레이·DB·CI는 각각 수행 범위와 미실행 범위를 적는다.

## 스킬 자체의 확인

새 명세나 변경된 진입 경로는 신규 Opus가 realistic task에서 역할별 메모·원문 계약·판정 양식을 찾아 실제로 사용할 수 있는지 확인한다. 스킬 작성자의 링크/frontmatter 자체점검과 독립 행동 검증을 구분한다. 자동 선택·미래 세션의 준수 보장을 완료조건으로 삼지 않는다. 문서와 스킬은 운영 지침이며 기술적 강제가 아니다.
