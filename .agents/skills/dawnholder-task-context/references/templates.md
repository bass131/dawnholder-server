# 작업 맥락 양식

현재 할당 작업에 필요한 양식을 골라 실제 값으로 채운다. 경로와 SHA는 예시를 복사하지 않고 관측값을 쓴다. 기록의 시각은 `date -u` 같은 시계 명령 출력을 옮기고 어림하지 않는다. 상세 로그는 할당된 근거 위치에 두고 짧은 메모/보고에는 필요한 경로만 남긴다. 역할별 읽기와 차단 기준은 [SKILL](../SKILL.md)을 따른다.

## 맥락 메모

대상 파일 쓰기 전에 작성하고 완료 때 실제 준수 위치를 갱신한다. 계획이 바뀌면 원래 기록과 변경 이유를 남긴다. 코드·문서·디자인·보고서 작성자와 독립 검증자가 공통으로 사용할 수 있다.

기계적 이관/병합 기록도 아래 필수 필드를 짧게 채운다. 관련 없는 항목은 해당 없음과 이유를 남기며 사전 기록을 면제하거나 사후 작성으로 소급하지 않는다.

```markdown
# 작업 전 맥락

- 역할·자기 태그 / 할당 작업 / 지정 모델·관찰 모델·backend unknown 여부:
- 현재 goal·할당 계약의 경로 / 작업 경로·branch·base·HEAD:
- 메모 작성 시점(시계 명령 출력의 시각) / 대상 파일 첫 쓰기 전 여부:
- 기존 사용자 변경·다른 작성자의 소유권 / 허용 쓰기·실행·금지 범위:
- 원문 요구/후속 보충의 계약 버전·시각 / 고정 입력 경로·hash / 적용 단계:
- 검증 등급·이유와 파일/줄 수 원시 근거 / R-7 해당·비해당과 이유:

## 읽기와 선택

| 읽은 파일·절 | commit 또는 미커밋 hash | 이 작업에서 필요한 규칙·경계 |
|---|---|---|
| 현재 지침·goal·계약·관련 영역·언어 절 | 실제 기준값 | 적용 이유 |

- 같은 책임의 예시 1~2개(경로·심볼/절) / 따를 이름·서식·오류·주석 관례:
- 재사용 helper·계약 / 재사용하지 않거나 중복이 필요한 이유:
- 영향 파일·사용처·보존 동작:
- 신규 파일 위치·이름 / 기존 경로·명명 관례 근거 / 새 폴더 필요 이유:
- 읽기 상한을 넘긴 추가 경로·구간과 이유(없으면 없음):
- 언어 규칙 부재·임시 기준과 승인 상태(해당 없으면 이유):
- 관련 규칙 절 선택 / 해당 없는 절·제외 이유(관련 없는 원문을 붙이지 않음):
- 열린 질문·차단 / 질문할 담당자 / 완료 때 처리 근거:

## 준수 연결

| 적용 규칙·출처 절 | 준수 계획 | 완료 뒤 실제 파일·심볼/절·근거 | 계획 변경 이유 |
|---|---|---|---|
| 관련 규칙 | 바꿀 경계 | 작성 전은 미작성, 완료 때 관측값으로 갱신 | 없으면 없음 |

- 자기 쓰기 감사(이 세션이 쓴 모든 경로 / 허용 밖 쓰기를 하나씩 위반으로 나열 / 위반 0이면 확인 방법):
```

## 위임 계약

발행 주체 Astra가 채운다. 구현자에게는 요구사항·보존 계약·규칙·관찰 가능한 완료조건을 주고, 검증자에게는 요구사항·보고·실제 diff/실행 원문을 주되 예상 결론·의심 결함·이전 평가로 결론을 유도하지 않는다. 기존 발행·권한 계약은 [orca-work](../../dawnholder-goal-loop/references/orca-work.md)를 따른다.

```markdown
[자기 발신 태그] 작업 계약

- 역할·수신자의 자기 태그 / 지정 모델 / 요청·화면·backend 구분:
- 승인 goal·요구사항 원천 / 작업 하나 / 보존 동작·완료조건:
- 경로·branch·base·HEAD / 기존 변경·파일 소유·쓰기 종료 확인:
- 허용 수정 파일 / 제품·테스트 소유 분리 / 건드리지 않을 영역:
- 허용 실행(읽기 전용 파일 읽기는 기본 허용)·자원 소유·부작용 / 추가 위임·commit/push 금지:
- 허용 쓰기 위치(근거 폴더 아래, receipt·임시 파일 포함. 기본 위치의 세션 임시 폴더(scratchpad)·TEMP·`/tmp`·홈은 허용 밖. 기동 때 근거 쪽으로 지정한 TEMP와 그 아래 Claude Code 임시 폴더(scratchpad)는 허용 안. Git Bash `/tmp`는 그 지정과 무관하게 허용 밖):
- 작업 전 메모 경로 / 완료 보고·원시 근거 경로 / 질문할 담당자:
- live preamble의 check·heartbeat·ask·정확히 한 번 worker_done과 명시 outcome:
- 작업 하나 뒤 정산·종료 / 재사용 금지:
- 계약 버전·원문 결정 출처·시각 / 고정 입력·hash / 다음 버전 적용 단계:
- 현재 작업자 범위 축소 통지 여부 / 새 범위의 다음 계약 이관:
- 검증 등급(강/약/문서 실사)·이유 / 파일·줄 수의 원시 근거:
- 계약 경로의 실제 작업자 cwd / 입력 존재·신규 출력 부모 기계 확인
  명령·exit·원시 근거 / 미확인 경로·처리:
- R-7 해당/비해당·이유 / 해당 시 계약 발행 전 불변식·전제 1파일과
  메인 원문 확인·보완 goal 승인 근거(일반 작업에는 시범 표식 요구 안 함):

## 맥락 묶음

- 최신 지침·goal·이 계약과 관련 기능/영역 문서의 필요한 절:
- 따를 기존 구현/산출물 1~2개의 경로·필요 구간 / 재사용 helper:
- 역할별 추가 읽기 이유와 상한:
- 가독성·주석 위치·책임 분리·배치/이름·탐색·중복 이유의 완료조건:
- 예시는 책임·배치·명명 탐색용인지 / 요구항목·보존 계약·판정 기준:
- 설계 결정이 필요하면 한 줄 대안·영향 / 결정할 담당자:
- 검증 harness 저장 파일·입력·명령/환경·exit·원시 경로와
  의미별 Assert 판단 변수 / 보고 수치의 원시 파일·읽기/계산 근거:

## 적용 규칙 원문

출처 경로: 실제 CODE_CONVENTION 경로
기준: commit SHA 또는 미커밋 파일/원문 hash와 그 hash 대상
적용 절·선택 이유: 관련 절 목록
해당 없는 절·제외 이유: 이 작업에 관련 없는 절별 이유

이 자리에 선택한 각 절의 제목과 본문 전체를 원문 그대로 붙인다.
링크·요약으로 대체하지 않는다. 출처가 다른 구간마다 위 출처/기준을 반복한다.
해당 언어 절이 없으면 부재·임시 기준·출처·미승인 상태를 명시한다.

## 관찰 가능한 완료와 차단

- 실제 준수 위치로 갱신된 메모·허용 diff·명령/출력/exit·미실행 범위:
- 맥락 메모 부재·관련 원문 누락·적용 규칙 위반·메모/결과 불일치는
  수정 또는 메인 결정 전 독립 검증 통과 차단:
- 측정값 위장·제품 계산 복제로 항상 통과하는 테스트도 차단
  (SKILL의 추가 차단 정본 적용):
- 등급별 독립 실사/테스트·실제 진입 실행 범위와 제품 결함의 번호 반환:
- 실제 진입 명령·입력·경로·관찰·대역 사용·미확인 경계 / 미실행·판정 보류:
- R-7 해당 시범에서만 Sol 완료 보고의 전제를 [소스]/[추론]/[미측정]으로 표시:
- 기존 테스트 실패 변경이면 메인 분류 결정 원문을 붙이고
  전 실패 분류·요구사항 출처·같은 명령 전후 실적을 남김:
```

## 검증 판정

신규 Opus는 먼저 자기 맥락 메모를 남기고 보고와 실제 수행을 실사한다. 아래 상태값 중 하나와 근거를 각 항목에 기록한다. 차단 항목이 남았거나 관련 필수 항목이 미검토이면 통과 판정을 내리지 않는다.

실패 분류·측정 추적·추가 차단사유의 정책은 [SKILL의 독립 판정](../SKILL.md#독립-판정과-통과-차단), 메인 표본과 전수 검증 경계는 [R-2](../../../../00_Document/operations/ORCA.md#r2-source-check)를 따른다.

`verifies`는 검증자 Task나 시간 근접 추정이 아니라 계약·receipt에서 확인한 **대상 구현 Task의 실제 ID**다. 각 결함의 심각도·차단 여부·귀속을 아래 표에 명시하고 해당 없음/미확정을 실제 상태로 남긴다. 실제 구현 Task가 없는 문서 검토는 해당 없음과 이유를 적으며, 연결을 확인하지 못했다면 미확정·필요한 확인을 남긴다. parser/helper·토큰 자동 기록은 이 양식 변경에 포함하지 않는다. 등급은 [goal-loop 정본](../../dawnholder-goal-loop/SKILL.md#검증-강도-4주-시범), Fable 시범은 [R-7](../../../../00_Document/operations/ORCA.md#r7-fable-pilot)을 따른다.

```markdown
# 독립 검증 판정

- 검증자·태그 / 지정·확인 모델 / 현재 goal·요구사항 원천:
- 대상 경로·branch·기준 SHA·검증 상태(미커밋이면 표시):
- 구현 쓰기 종료 근거 / 검증자 메모 경로 / 테스트 쓰기 소유:
- 구현 보고·실제 diff·원시 실행 근거·기존 테스트 경로:
- 보고와 실제 수행 대조: 일치/불일치, 구체적인 위치와 관측값:
- 검증 등급·이유·원시 파일/줄 수 / goal·계약의 등급과 실제 요구 범위 대조:
- R-7 해당/비해당·이유 / 해당 시 불변식·전제 파일과 Sol 보고 대조:

## 기계 판독 표

| verifies | 결함 번호 | 심각도 | 차단 여부 | 귀속 | 상태·판정 근거 |
|---|---|---|---|---|---|
| 대상 구현 Task 실제 ID / 해당 없음·이유 / 미확정 | 실제 번호 / 해당 없음 / 미확정 | 관측한 심각도 / 해당 없음 / 미확정 | 예 / 아니오 / 미확정 | 이번 Sol / 기존 코드 / Astra 계약·goal / 메인 / 해당 없음 / 미확정 | 실제 원문·diff·receipt와 귀속 근거 |

번호·심각도·차단·귀속을 시간 근접이나 구현자 결론으로 추정하지 않는다.

## 설계 관찰(비차단)

요구사항 위반·차단 결함은 결함으로 유지하고 이 관찰로 낮추지 않는다.
설계 결정을 요청할 때는 한 줄 대안과 영향을 함께 남긴다.

| 관찰 번호·실제 위치 | 재사용·책임·가독성 관찰과 근거 | 한 줄 대안 | 영향 | 현재 범위 / 후속 경계·결정 주체 |
|---|---|---|---|---|
| 실제 번호·file:line / 관찰 없음 | 실제 관찰 또는 없음 | 대안 / 해당 없음·이유 | 관측·추론·미측정 구분 | 기존 goal 범위 여부·후속 후보 여부와 담당자 |

## 결함별 검사 전환 판단

각 결함마다 가능/불가/판단 보류와 이유를 기록한다. 가능하면 검사·fixture·정본 helper 방식을 짧게 쓰고, 근거가 부족하면 판단 보류와 필요한 확인을 남긴다. 검사 구현·CI 적용·후보 채택은 기존 goal 계약과 승인 범위를 따른다.

| 결함 번호 | 이 결함을 검사로 바꿀 수 있나 | 이유·판단 보류 시 필요한 확인 | 가능한 검사·fixture/helper 방식 |
|---|---|---|---|
| #번호 | 가능 / 불가 / 판단 보류 | 실제 근거 또는 부족한 정보 | 후보 방식 또는 해당 없음과 이유 |
```
