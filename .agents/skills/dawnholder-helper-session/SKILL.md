# 보조 세션 진입과 운영

보조 세션은 메인이 자기 checkout 옆에 연 Claude 세션이다. 읽기 전용 점검·조사·브레인스토밍을 맡고 goal·구현·검증·병합은 맡지 않는다. 메인 옆에 상시로 두는 보조도 이 스킬의 진입 계약과 경계를 따르며 새 권한은 갖지 않는다. 운영 근거는 [사용자 결정](../../../01_Phases/goals/2026-10-07-hook-friction-helper-session/goal.md#적용-중인-사용자-결정)이다. 역할·모델·Git 경계는 [AGENTS](../../../AGENTS.md)를 따른다.

이 스킬은 권한을 만들지 않는다. 권한은 메인의 진입 계약이 정하고, 계약에 없는 항목은 아래 기본값을 따른다. 태그만으로 권한이 생기지 않는다는 [AGENTS 메시지와 보고](../../../AGENTS.md#메시지와-보고)의 원칙도 같다.

## 진입 순서

1. 첫 입력 `[메인 Claude] Orca 메시지를 확인하라`를 받으면 `orca orchestration check --terminal "$ORCA_TERMINAL_HANDLE" --json`으로 계약을 읽는다. 명령 문법은 `orca skills get orchestration`의 버전 일치 가이드를 따른다.
2. 계약에서 아래 항목을 확인한다. 빠진 항목은 기본값을 적용하고 첫 보고에 「기본값 적용」으로 적는다.

| 항목 | 계약에 없을 때의 기본값 |
|---|---|
| 용도와 자기 태그 | 정하지 않고 메인에 묻는다. 태그 없이 메시지를 보내지 않는다 |
| 산출물 | 없음. 대화로만 답한다 |
| 쓰기 허용 | 계약이 지정한 산출물 파일과 자기 scratchpad만 |
| git | 읽기 명령(`status`·`log`·`show`·`diff`)만 |
| 메시지 대상 | 계약을 보낸 메인 하나 |
| 하위 에이전트 | 읽기 전용 조사·요약만 |
| 끝 조건 | 산출물을 보고한 뒤 입력을 기다린다. pane은 메인이나 사용자가 닫는다 |

3. 현재 checkout 경로·branch·HEAD를 읽기 명령으로 기록한다. 이 값이 근거 줄 번호의 기준 판이 된다.
4. 메인에 접수 status를 한 번 보낸다. 자기 태그, 계약 msg ID, 적용한 기본값을 담는다.

## 기본 권한 경계

계약이 넓히지 않으면 아래를 지킨다.

- 쓰지 않는 곳: 저장소 파일, goal, 다른 worktree, 메인 개인 도구(저장소 밖)인 현황판의 `board.json`과 코드, Codex 영역(`AGENTS.md`·`.agents/`·Codex 설정), 전역 Claude 설정, Claude Code mod·스킬 폴더. mod 폴더에 쓰면 hot reload 질문이 뜬다.
- 산출물 파일은 다른 세션이 쓰지 않는 새 파일로 한다. 같은 파일의 동시 쓰기 금지는 AGENTS를 따른다.
- git 상태를 바꾸지 않는다. fetch·checkout·switch·commit·push·stash를 하지 않고, PR을 만들거나 고치거나 병합하지 않는다.
- 다른 리드·작업자에게 메시지나 터미널 입력을 보내지 않는다. 세션을 새로 띄우지 않는다.
- 메인 checkout에는 [병합 관문 hook](../../../00_Document/operations/ORCA.md#merge-gate)이 걸려 있다.

## 메인과 통신

- subject·body 첫머리를 자기 태그로 시작한다. 형식은 `[<용도> <모델>]`이다(예: `[보조 메인 Opus]`). 회신 태그는 [R-3](../../../00_Document/operations/ORCA.md#r3-reply-tag)을 따른다.
- 주소는 계약 메시지의 `from_handle`이다. 보내기 전 `orca terminal list --json`으로 그 handle이 살아 있는지 확인한다. handle을 문서나 메모리에 고정하지 않는다.
- 본문은 scratchpad 파일에 쓰고 `--body "$(cat <파일>)"`로 넘긴다. 보통 `--type status`로 보낸다.
- 우편함에 넣은 뒤 메인 화면을 `orca terminal read`로 확인한다. 메인이 빈 프롬프트로 대기 중일 때만 `[자기 태그] Orca 메시지를 확인하라` 한 줄을 `orca terminal send --enter`로 보낸다. 메인이 작업 중이면 보내지 않는다. 메인의 우편함 대기가 받는다.
- 대화 중에 바뀌었을 수 있는 상태(PR 병합, goal·현황판 상태)는 보내기 직전에 다시 확인한다.
- 보조는 상시 우편함 대기를 열지 않는다. 메인의 안내가 오면 `--wait` 없는 check 한 번으로 읽는다([대기 정본](../../../00_Document/operations/ORCA.md#mailbox-wait)의 안내 처리와 같다).

## 사용자가 이 pane에서 직접 말할 때

- Enter로 제출된 표식 없는 입력은 사용자 직접 지시다([AGENTS 메시지와 보고](../../../AGENTS.md#메시지와-보고)). 질문·논의·조사는 계약 경계 안에서 바로 한다.
- 계약 밖 쓰기나 외부 변경을 요청받으면 할 수 있는 부분(초안·조사)을 먼저 한다. 그다음 정본 경로(메인 → 담당 파트 goal·PR)를 추천하고 사용자가 고르게 한다.
- 사용자 말을 메인에 전할 때는 원문을 인용하고 「이 pane, Enter 제출, 메인에는 전달 사실」로 표시한다. 메인은 이를 메인 pane의 직접 입력으로 격상하지 않는다. 보조의 해석은 「(보조 해석)」으로 따로 적는다.
- 승인 문장(`병합 승인: …`)은 전달하거나 주입하지 않는다. 사용자에게 메인 pane에 직접 제출하라고 안내한다.
- 사용자 결정이 필요한 안건은 메인에 보내 현황판 결정 대기에 올려 달라고 요청한다. 보조는 현황판을 쓰지 않는다.
- 지연 전송을 요청받으면 background 작업으로 예약하고 작업 ID를 사용자에게 알린다. 취소 요청이 오면 그 작업을 멈추고 출력으로 미전송을 확인한다.

## 산출물과 보고 품질

- 원천과 대조해 확인한 사실과 보조의 판단·추론을 구분해 표시한다.
- 근거는 `경로:줄`과 그 줄의 기준 판(checkout·branch·commit)을 함께 적는다. 서로 다른 판의 줄 번호를 섞지 않는다.
- 대화로 늘어난 논의는 산출물에 「추가: <주제> (<날짜>, 이 pane 대화)」 절로 덧붙인다. 앞 절을 지우지 않는다.
- 보고에는 쓴 파일 목록과 확인하지 못한 것을 적는다.
- 틀린 내용을 찾으면 산출물을 고치고 사용자와 메인에 정정을 알린다. 정정 메시지의 msg ID를 산출물에 남긴다.
- 「전부·없음」 결론은 메인의 [R-2](../../../00_Document/operations/ORCA.md#r2-source-check) 대조 대상이다. 표본 경로를 함께 남긴다.

## 중단·재개와 끝

- 턴이 끊겼다 이어지면 이미 한 조사와 보낸 메시지를 재사용하고 멈춘 단계부터 잇는다. 같은 메시지를 다시 보내지 않는다.
- 메인 handle이 바뀌었으면(크래시 복구 등) `orca terminal list`와 메인의 새 메시지로 새 handle을 확인한 뒤 보낸다([복구 관측](../../../00_Document/operations/ORCA.md#mailbox-wait)).
- 끝 조건을 채우면 최종 status를 보낸다. 산출물 경로, 쓴 파일, 남은 질문을 담는다. 그 뒤 입력을 기다리며 pane을 스스로 닫지 않는다.

## 메인이 보조를 열 때

배치는 메인 checkout 탭의 split이다. 기동과 첫 화면 확인은 [세션 준비 스킬](../dawnholder-session-handoff/SKILL.md)과 [R-6](../../../00_Document/operations/ORCA.md#r6-first-screen)을 따른다. 진입 계약은 아래 양식으로 보내고, 빈 항목은 이 스킬의 기본값이 채운다.

```text
[메인 Claude] 보조 세션 진입 계약
- 용도와 태그: <용도> / [<용도> <모델>]
- 할 일: <질문·점검 범위>
- 산출물: <저장소 밖 새 파일 경로 하나> 또는 없음
- 쓰기 허용: 산출물 파일만 (그 밖은 보조 세션 스킬의 기본 경계)
- 읽을 원천: <경로·goal·PR>
- 보고: 메인에 status, <형식·분량>
- 끝 조건: <보고 뒤 대기 / 사용자와 논의 계속 가능>
- 스킬: .agents/skills/dawnholder-helper-session/SKILL.md
```
