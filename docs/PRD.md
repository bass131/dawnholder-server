# PRD — Dawnholder Project

> **상태**: 1차 초안 (Harness 셋업 시점)
> **다음 갱신**: 첫 마일스톤 끝나고 학습한 것 반영

---

## 한 줄 요약

**친구들과 사냥하고, 번 자원으로 우리만의 길드 거점에 시설을 사서 꾸미는
2D 사이드스크롤 캐주얼 RPG.**

핵심 차별점은 **액션 RPG와 길드 타이쿤의 결합** — 둘 중 하나만 있는 게 아니라,
사냥의 보상이 거점 성장으로 직결되고, 거점 성장이 다시 사냥을 돕는 순환 구조.

---

## 목표와 비목표 (Goals & Non-Goals)

### 🎯 Goals

**프로젝트 차원**:
- 게임 회사 백엔드 포지션 지원용 포트폴리오 완성
- 백엔드/네트워킹 실력을 실전 프로젝트로 학습 (raw TCP, 권위 서버, 동시성, 영속화)
- 면접관에게 보여줄 동작 데모 + 부하 테스트 결과 + 기술 블로그 형식 README

**게임 차원**:
- 친구들과 모여 사냥하는 짧은 세션의 즐거움 (캐주얼 액션)
- 길드원 모두가 기여한 거점이라는 소속감과 성장의 만족감 (타이쿤)
- 두 루프(사냥/거점)가 서로 의미 있게 연결되는 디자인

### 🚫 Non-Goals (절대 안 만드는 것)

명시 안 하면 scope가 끝없이 늘어남. **이건 만들지 않는다**:

- **상용 출시** — 학습/포트폴리오 프로젝트. 결제, 보안 감사, GDPR 등 상용 요구사항 무시.
- **모바일/콘솔 지원** — PC 윈도우 클라이언트만.
- **고품질 그래픽** — 무료 에셋 + placeholder 스프라이트 OK. 비주얼은 시각적 임팩트 데모용 정도.
- **로컬라이제이션** — 한국어만.
- **자원 생산 시뮬레이션** — 시설은 "구매 → 기능 제공" 모델만. NPC 고용, 자원 변환, 생산 라인 같은 풀 타이쿤 요소는 안 함.
- **거점 PvP / 영토전** — 거점은 길드별 안전 공간.
- **분산 서버 / 샤딩** — 단일 서버 프로세스로 100~500명 처리. 이게 부족해지면 그건 다음 프로젝트.

### 🤔 Maybe Later (MVP 후 고려)

지금은 안 만들지만 미래에 추가할 수도 있는 것:
- 길드 간 대결 콘텐츠 (PvE 경쟁)
- 거점 시설의 자원 생산 흐름 (풀 타이쿤화)
- 인스턴스 던전
- 시즌제 콘텐츠

## 타겟 플레이어

- **누구**: 본인 + 본인 친구 5~10명이 실제 플레이어. 시연/시험 대상.
- **동시 접속 목표**: 100~500명 (단일 마을에 사람이 있는 느낌. 부하 테스트 봇으로 검증.)
- **플레이 세션**: 30분~1시간 (퇴근/하교 후 친구들과 가볍게)
- **플레이 빈도**: 주 2~3회

## 핵심 기능 (MVP)

> MVP의 정의: **이 6개가 다 되면 데모 영상을 찍을 수 있다.**

### 1. 계정 + 캐릭터 (네트워킹 기본)
- 닉네임 기반 단순 로그인 (비밀번호 단계는 학습 후반에 추가)
- 캐릭터 1개 생성, 외형은 placeholder
- 영속화: 로그아웃 후 다시 들어와도 동일 캐릭터 + 인벤토리 + 위치

### 2. 이동 + 점프 (실시간 동기화 ★)
- 2D 사이드스크롤 이동/점프
- 클라이언트 prediction + 서버 권위 + reconciliation
- 다른 플레이어가 부드럽게 보임 (snapshot interpolation)
- **이게 데모 영상의 절반.** 가장 임팩트 큰 시각 요소.

### 3. 사냥 + 전투 (권위 서버 ★)
- 근접 공격 1종, 몬스터 1~3종
- 데미지/HP/사망/리스폰 — 모두 서버 권위
- 드랍 (골드 + 간단한 재료 아이템)
- lag compensation (서버에서 200ms 위치 history로 hit check)

### 4. 인벤토리 + 길드 창고 (트랜잭션 ★)
- 개인 인벤토리 (NN 슬롯)
- 길드 창고 — 길드원이 동시에 접근 시 동시성 처리
- 아이템 이동/스택/버리기 — 모두 서버 권위 + 검증

### 5. 길드 + 거점 (영속 영역 ★)
- 길드 생성/가입/탈퇴
- 길드별 전용 거점 맵 (인스턴스)
- 거점에 시설 구매/배치 (예: 모루 1, 모루 2, 회복샘, 창고 확장)
- 시설 효과: 길드원이 시설 사용 시 기능 제공 (예: 모루 = 장비 강화 NPC, 회복샘 = HP 회복)
- 길드 자금 — 길드원 기여, 시설 구매에 사용

### 6. 마을 + 사냥터 (월드)
- 공용 마을 1개 (모든 플레이어 만남)
- 사냥터 1~2개 (오픈 월드, 모든 플레이어 함께)
- 길드 거점 (인스턴스, 길드원만)
- 맵 간 이동 = portal/handoff

### MVP에 의도적으로 뺀 것
- 채팅 (의외로 복잡, 보안 고려할 게 많음 → MVP 후)
- 친구 시스템, 우편, 거래
- 직업/스킬 트리
- 퀘스트/NPC 대화
- 업적/도감/통계

## ⚠️ 위험과 대응

### 위험 1: Scope 폭주
**원인**: 두 장르 결합이라 이미 무거움. "이것도 추가하면 좋겠는데"가 끝없음.
**대응**:
- 위 Non-Goals를 헌법으로 취급. 새 기능 욕구 시 "이거 정말 MVP에 필요한가?" 자문.
- 추가 아이디어는 "Maybe Later" 섹션에 적기만, MVP 안에 넣지 않기.

### 위험 2: 거점 초기 텅 빔
**원인**: 첫 시간 동안 거점이 비어있으면 "타이쿤 재미"가 안 와닿음.
**대응**:
- 첫 시설 구매까지의 시간을 5~10분으로 설계.
- 길드 가입 시 시드 자금 지급으로 즉시 소비 가능하게.

### 위험 3: 혼자 테스트 시 재미 평가 불가
**원인**: 친구들과 같이의 마법은 사람이 있어야 발생.
**대응**:
- 헤드리스 봇으로 다인 시뮬레이션 (qa-sim 에이전트 활용).
- 친구 2~3명을 정기 플레이테스터로 미리 섭외.
- "혼자 30분 플레이해도 의미 있는" 솔로 사냥 루프 보장.

### 위험 4: 포트폴리오로서 임팩트 부족
**원인**: 동작은 하는데 면접관에게 보여줄 결과물이 약함.
**대응**:
- 부하 테스트 결과 그래프 필수.
- README는 기술 블로그 형식 ("이 문제를 이렇게 풀었다"의 서사).
- 학습 일지를 노션이나 블로그에 누적.

## 성공 기준

> "이 프로젝트가 성공했다"고 말할 수 있는 객관적 기준.

### 게임 차원
- [ ] 친구 3명 이상과 동시 접속해서 함께 30분 플레이 가능
- [ ] 마을→사냥터→거점→다시 마을의 한 사이클이 끊김 없이 동작
- [ ] 길드 5개, 거점 시설 5종 이상 구현
- [ ] 1시간 연속 플레이 시 클라/서버 모두 안정 (메모리 누수, 크래시 없음)

### 기술 차원
- [ ] 헤드리스 봇으로 동접 100명 부하 테스트 통과
  - 서버 tick p99 < 10ms
  - 메모리 누수 없음 (1시간 부하 후 baseline 대비 +5% 이내)
  - 패킷 손실 / 비정상 disconnect < 1%
- [ ] 권위 서버 위반 사례 0건 (헌법 hook으로 자동 검출)
- [ ] 단위 테스트 커버리지: 핵심 핸들러 / 공식 100%, 전체 60%+

### 포트폴리오 차원
- [ ] README가 기술 블로그 수준 (아키텍처 다이어그램, 핵심 문제 해결 서사 2~3개)
- [ ] 데모 영상 2분 이내 (사냥 + 거점 시설 구매 시퀀스)
- [ ] 부하 테스트 결과 그래프 포함
- [ ] 개발 학습 일지 (노션 또는 블로그)

## 마일스톤 (잠정)

> 작업 진행하며 조정. 각 마일스톤 끝에 데모 가능한 상태가 목표.

| ID | 이름 | 끝나면 데모할 수 있는 것 |
|----|------|--------------------------|
| **M1** | Foundation | 서버 부팅, TCP 리스너, 한 명 접속/끊김 |
| **M2** | First Connection | 클라이언트 1명이 서버에 접속, 캐릭터가 서버 기준으로 움직임 (예측 + 검증) |
| **M3** | Multiplayer | 두 명이 같은 맵에서 서로 보임, 부드러운 보간 |
| **M4** | Combat | 몬스터 1종 + 근접 공격 + HP/사망/리스폰 |
| **M5** | Persistence | DB 연결, 캐릭터/인벤토리 영속화, 재접속 시 복원 |
| **M6** | Guild Foundation | 길드 생성/가입/탈퇴, 길드 창고 (동시성 처리) |
| **M7** | Guild Hideout | 길드 거점 인스턴스, 시설 구매/배치 1~2종 |
| **M8** | Polish & Load Test | 헤드리스 봇 부하 테스트, 안정화, 데모 영상 촬영 |

각 마일스톤은 `phases/M{N}-{slug}/` 안에 더 작은 Phase로 쪼개짐 (`/plan` 커맨드 활용).
